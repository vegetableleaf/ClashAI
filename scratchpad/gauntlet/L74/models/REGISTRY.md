# Model checkpoint registry

Owner rule 2026-10-17: every model checkpoint is named **"[DECK] Mark [Roman numeral]: [One word that describes the change]"**. Decks: **ICEBOW** (the icebow X-Bow deck) and **Bait** (the Log Bait deck). Generated from `registry.json` by `register_ckpt.py --render`; do not edit by hand.

**Who gets a Mark** (lead's rule 10-17 + recorded calls): a distinct model = a checkpoint deployed live, used as the init / graft source of another run, or evaluated as a candidate (it got its own verdict vs a baseline). One Mark per training configuration; its seed replicates, intermediate snapshots, controls that never got a promotion verdict, smokes, failed launches, test scaffolding (rltest) and opponent / exploiter policies stay unmarked but are recorded with their relation. A same-run checkpoint gets its own Mark only when it was deployed, used as an init, or was an explicit continuation with its own verdict (LONGER). A raw checkpoint and its grafted twin are one Mark (two files). **Numbering**: per deck, chronological by the checkpoint's creation (earliest mtime of any byte-identical copy; HANDOFF date for the two no-file Marks). **Word**: the change vs the parent Mark (its init); siblings from one parent are named by the change their arm tested; scratch-trained models (no init) are named by the change vs the model they were compared with (shown as 'compared to').

- Current live icebow model (L70/live/CKPT_OVERRIDE): **ICEBOW Mark CXXIV: LONGER** (`icebow/data/bench/rl_royale/rlarm_gae/rlarm_gae_u0250_grafted.pt`).
- Current Bait model (L70/live/bait/CKPT_OVERRIDE): **Bait Mark I: SPECIALIST**.
- Live periods come from the start events of scratchpad/gauntlet/L68/live_reader*/live_play_*.jsonl (matches with >= 5 plays, dry runs excluded; deck = bait when the bait CKPT_OVERRIDE / LIVE_OPTIONS was used). Before 09-25 they come from scratchpad/live_run*.log and HANDOFF_ARCHIVE.md.
- '(pod backup only)' files live under C:/Users/benpe/pod_backup_weekend/ (same volume, so they are hard-linked too).

Original files are never moved or renamed. Each Mark has NTFS hard links (zero extra space, sha256-verified) under `icebow/data/models/<DECK>/` named `<DECK>_Mark_<ROMAN>_<WORD>.pt` (`_grafted.pt` = the grafted twin that live play loads). `register_ckpt.py --name PATH` prints any file's Mark name.

## How to name a new checkpoint

1. It needs a Mark only if it is a distinct model: evaluated as a candidate, deployed live, or used as the init of another run. Snapshots (u0005, u0010 ...) and seed replicates stay unmarked (listed below).
2. Pick its PARENT Mark = the checkpoint it was initialised from (`rl.init` / `grafted_heads_from` inside the .pt). Scratch IL models have no parent; name the change vs the model they were measured against.
3. Pick ONE uppercase word for the change vs the parent (e.g. CUES, EXPLOITERS, HEROIW, LONGER, POSTURE). If the run bundled several changes, name the dominant one and list all in --note. A repeated word is fine; the numeral disambiguates.
4. Register it (the number is the deck's next Roman numeral):
   `icebow/.venv/Scripts/python.exe scratchpad/gauntlet/L74/models/register_ckpt.py PATH [GRAFTED_PATH] --deck ICEBOW --change CUES --parent "ICEBOW Mark CXXIV" --run RUNID --note "..." --eval "..."`
   It hashes the file(s), appends the Mark to registry.json, creates + verifies the hard link(s) and regenerates this file. Commit registry.json + REGISTRY.md (never icebow/data).
5. When a Mark goes live, add its live period to its `live` field in registry.json and run `--render`.
