# PARITY v2: mechanics replay

`--mechanics-replay` / `MECHANICS_REPLAY=1` is an explicit parity-only opt-in.
Without it the original strict deal path remains. No training/eval/live script,
runtime selector, engine checkout or installed runtime is modified. No network,
commits or actual SIM execution are part of this ticket.

The frozen cohort is `output/cohort100/sources`. A v1 source lacks own hands, so
the planner reads ONLY `public.own_hand` and `public.own_next_card` from the exact
original decision log and verifies its SHA256 against the frozen source. No
opponent hand, elixir (including estimates), next card or hidden deck is read.
Hydrated sources save that allowlisted projection, so subsequent pod comparisons
can use them without the original logs. Missing/mutated originals are explicit
input skips; matches are never replaced by later easier matches.

Every usable decision specifies the owner's four slots in their recorded order.
An explicitly logged next card leads the constructed queue; the remaining known
own cards complete it deterministically. Missing next card is recorded as
unobserved, not recovered from a presumed cycle. In this cohort **none of the
32,442 decisions logs the next card**. All own plays use the latest prior logged
hand, with no future-hand repair. An invalid hand skips its decision and any
dependent own commands, each with its row/tick/reason. Engine own elixir remains
simulated; its mismatch and command refusals remain visible.

Opponent reset entries are a variable-size roster of *observed played cards*,
not an inferred eight-card deck. Each public placement proxy gets its own slot
and synthetic full elixir at its recorded tick, then invokes the normal deploy
path at its recorded position. Repeated/fast/out-of-cycle plays therefore need
no legal deal or unknown deck slots. Placement, form and terminal rejections
remain recorded. Enemy elixir is never a metric. Configured forms still use
observed lower bounds and the engine's evolution counters; unobserved abilities,
spell plays, opening state and exact deploy timing remain limitations.

## Source-backed adapter

Both local pinned source trees were inspected:

- `research/ext/Royale/RoyaleSim/crates/royalesim/src/py.rs`:
  `Battle.reset`, `step`, `save`, `load`; `state.rs`: `PlayerState`, `save`,
  `load_with`, `spawn_unit`, `spawn_unit_resolved`, `spawn_unit_tapped`.
- `research/ext/Royale-20261006/RoyaleSim/crates/royalesim/src/{py,state}.rs`:
  old runtime has the same snapshot self-check and player fields.
- `research/ext/Royale/RoyaleGym/royalegym/state_mutator.py`:
  `ScriptedBoardStateMutator` creates a reset setup, not an in-progress injection.

Rust has forced spawning, but neither pinned Python binding exports it. The
adapter uses the available snapshot API. Internal card indices are learned from
fresh four-card resets and their public catalogue IDs, never guessed from the
catalogue's ordering. The worker edits ONLY own hand/queue/refill state or the
opponent's hand/queue/refill plus synthetic mana, then calls `step(..., 0)`.
Combat entities, projectiles, tower HP, time, RNG and pending effects are retained.
These edits and the queue completion are experimental scenario controls, not
claims that the logged match had that deal or opponent elixir.

Snapshots are self-checking JSON. For each intentional edit, `load_with` computes
the rebuilt hash and rejects the old hash **before replacing the battle**. The
adapter accepts only the exact `snapshot self-check failed: saved hash ..., rebuilt ...`
diagnostic, writes that computed hash, and retries once. Every card/arena/format/
calibration/catalogue check still runs. Any other exception rolls back the
original snapshot and fails the job. Successful load verifies the edited players
and unchanged tick. This is deliberately default-off and depends on the checked
API contract; changed serialization/diagnostics fail closed. No patched binary
is required. Real-runtime compatibility remains for the pod run to establish.

## Pairing and reporting

An old-runtime `IceWizard has no loadable hero form` reset exception is
`UNSUPPORTED_EXPECTED`, with its original detail, not a failure. It is never
downgraded to base IceWizard. Only that actual old exception permits the
`new_fork_unsupported_old` comparison group. Other old failures do not silently
enable fallback. The dry planner predicts this case from observed form 2 and
labels the prediction separately from actual runtime results.

`all_requested` and `new_fork_unsupported_old` each use the intersection of
successful matches AND available decision ticks with measurement rows. Empty
results cannot become paired measurements. Each group's JSON includes its own
mismatch ranking; the text report also retains the overall per-runtime ranking.
Use the groups for comparisons because overall runtime coverage can differ.
Reports include matches, decision rows, body rows, command rejections, expected
unsupported jobs, per-row skips and reason totals. Unpaired completed matches
are disclosed with dropped decision/body counts. `selection.json` also records
input-filter exclusions. Levels remain the frozen **assumed uniform 15**, not
measurements from logs.

## No SIM checks and planning receipt

```powershell
icebow/.venv/Scripts/python.exe scratchpad/gauntlet/L74/parity/verify_v2.py --tests
python scratchpad/gauntlet/L74/parity/verify_v2.py --planning --contract
```

`planning_v2.json` contains every match's source hash, counts and skip reasons,
plus the prepared cohort path. The same 100 originals yield 100 usable matches,
32,442 decision rows, 3,594 own plays and 2,888 opponent injection plans. All 100
carry IceWizard hero, so expected coverage is 100 new/fork-only and zero
three-runtime matches. Zero planning skips. This is expected usable coverage,
not runtime acceptance or a measured fidelity result. `verification_v2.json`
records commands, exits and output fingerprints; mocks exercise the actual
adapter/worker control flow without importing a real engine.

## Pod command

Stage the changes plus the hydrated source directory named in `planning_v2.json`
and that receipt itself. Existing old/new/fork runtimes and fork manifest from
the original ticket are prerequisites; this command performs no install/build.
From the repo root on pod D, using a fresh OUT:

```bash
COHORT=$(/workspace/venv/bin/python -c 'import json; print(json.load(open("scratchpad/gauntlet/L74/parity/planning_v2.json"))["hydrated_cohort"])') \
MECHANICS_REPLAY=1 WORKERS=24 OUT=/workspace/results/PARITY_v2 \
  bash scratchpad/gauntlet/L74/parity/run_parity.sh
```

Alternatively use the pod's original frozen `COHORT=/workspace/results/PARITY/sources`
if the exact source logs also exist at the default live-reader directory; the
hash-checked hydration then runs there. Do not set ASSUME_LEVEL with COHORT.
`--live` on the Python CLI selects a relocated raw log directory if needed.
The launcher retains cpu.lock, thread limits, fresh-output protection, and
SUMMARY/DONE failure receipts. Snapshot reload overhead has not been timed on
pod; the worker batches print measured throughput and ETA. No SIM run was made
locally.
