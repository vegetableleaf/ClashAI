# S6: do the SIM's visual-cue fields mean the same as the live reader's? (2026-10-16)

`pipeline/sim_unit_state.py::extract` (SIM) vs the live reader's cue blocks (`behavior_state_raw`, phase-2 buffs, phase-3
attack rows, `proj`, `fx`), on the same bodies at the same ticks, through `fights.py` fight replays. Scripts, per-body
records and every number below: `scratchpad/gauntlet/L74/parity/s6/` (`analysis_all.txt`, `analysis_p3_logs.txt`,
`analysis_p2_logs.txt`, `analysis_before_175459.txt` / `analysis_after_175459.txt`).

## Verdict

Safe to train on now (encoding is the same on both sides; what disagrees is SIM parity, not meaning):
`state` (all seven classes), `hide`, `attack.hit_speed_ms`, `attack.progress_ms`, `attack.load_ms`, `attack.phase`
(idle vs active; the `hit` bucket is noisy), `attack.frac`, `status.frozen / slowed / invisible / shielded / raged`
(flags only), `slow_frac` of the Ice Wizard slows, `charging` (only with the charger-card live rule below), the weapon-shot
list `projectiles` (source, target, position) and spell-in-the-air / static `areas` names.

Safe only if the live side applies a mapping rule that is NOT yet in the spec (section 4): `attack.target` (live holds far
default targets), `slow_frac` of area-refreshed slows (Poison), `charging` (restrict to charger cards).

Not safe, drop or mask: `status.taunted` (the SIM has no taunt: live 467 rows, SIM 0), `status.stunned` (never True in the
live data; the engine has one stun flag, it is `frozen`), the `buffs` list `frac` / `ms` for area-refreshed buffs (Rage,
Poison: live duration field accumulates, sawtooth phase offsets), `projectiles[].effect` (live has no such field, untested).

## 1. Method

- Replay: `fights.py` unchanged (imported; `Engine.bodies`, `run_fight`, `measure` wrapped in-process, `s6/collect.py`).
  Each frame it calls `extract(battle, memo, hit_window_ms=100)` (memo per fight) and `s6/live_cues.py::live_cue` for the live
  body; pairs = fights' own `initial_pairs` (setup by exact point, grown by `pair_frame`). Towers pair by id.
- Seeds: the two new captures (`icebow/data/p3_captures/...`) are not in `fights.py`'s `P3_DIR`, so `s6/mkseeds.py` writes
  `PARITY_ATTACKS` / `PARITY_BUFFS` for all logs (formats of `fights.py attacks` / `buffs`); t0 attack target, progress, load and
  the Freeze / Tesla-stun / IW-slow buffs are therefore seeded from the reader on every log.
- Live-side mapping = READER_STREAM_SPEC section 5 plus the rules of section 4 here (reference implementation: `s6/live_cues.py`).
  Hit speed on the live side is the reader's own `defs` (HitSpeed), not the table.
- Data (8 logs, 415 fights, 547,727 body-frames, 505,528 aligned): phase-3 logs `133158 / 134401 / 135037` (L70 captures),
  `162405`, `175459` (merged reader, blocks inline in the frame log); the three phase-2 owner matches `115958 / 121354 /
  122204` (buffs, no attack block) because the five phase-3 logs contain no charge, river jump, dash, tunnel or hero cast.
  Attack rows exist only at ticks where the capture row sits on the frame tick (cue coverage 296,169 / 505,528 aligned).
- Buckets. **A** = bodies on the board at t0, first 20 ticks (1 s): the SIM state is the live state seeded by `fights.py`, so
  disagreement is mostly definitional (i). **B** = every other frame: definitions plus SIM divergence (ii). Scored only where
  the two bodies are within 0.25 tile (aligned).
- Runtime: royalesim 0.1.35 (Windows wheel, `PARITY_SIM_PATH`), `PYTHONHASHSEED=0`, K = 0 (one replay per fight, 5 min per match).

## 3. Definitional mismatches found, and what was done

Fixed in `pipeline/sim_unit_state.py` (+ `pipeline/tests/test_sim_unit_state.py`, 8 tests pass; pyflakes clean).
Before = commit 2689bfe extractor, after = current, both on `175459` with the same seeds (89 fights, 98,954 B-frames).

| # | mismatch | example | fix | before -> after |
|---|---|---|---|---|
| 1 | Hero Ice Wizard slow never read as slowed: the buff rows `IceWizardHeroSlow`, `..._SlowBuff`, `..._FreezeBuff` are not in the top-level `buffs` table, only nested in projectile / ability rows | live `IceWizardHeroSlow` (-30) on 422 B-frames, SIM carries the buff, `slowed` False | `_all_buffs`: index every nested buff row by name (top-level table wins) | `slowed` live-only 422 -> 0; A 0.980 -> 1.000 |
| 2 | `stunned` double-counted: an `A|B` alias is one engine id, the word match ran on the whole joined string (`...GiantHero_Slap_Stun...`), plus `stun_ticks` | live Freeze = `frozen` only; SIM said stunned + frozen on 290 frames | name-word tags only for single-name aliases; the engine stun flag now sets `frozen` (live: every -100 buff is `frozen`) | sim-only `stunned` 290 -> 0 |
| 3 | Evo Knight Fortify and Super Knight shield are an engine `idle_buff` (BuffWhenNotAttacking), never a buff entity, live lists them while the unit is not attacking | live `Knight_Fortify_EV1` on 597 frames, SIM none | when the card has `idle_buff` and `state != engaged`, append the buff and its status | `shielded` both-true 0 -> 493 of 597 |
| 4 | Tesla `hide` read `up` while deploying; live shows state 4 (deploying), hide undefined | 366 B-frames (None, up) | `hide = None` while `deploying` | 366 -> 16 |
| 5 | `slow_frac` read 1.0 for a slow first seen mid-way (fight started from a live board) | A bucket slow_frac within 0.15: 22/60 | totals from the card table (`buff_time_ms` next to the buff row) before the memo max | A 0.367 -> 0.967 |

Mismatches the extractor cannot fix, required in the LIVE mapping (`pipeline/live_unit_state.py`, step c; reference code in
`s6/live_cues.py`, numbers in section 2):

- **Target (largest effect).** Live `target_gen` is the unit's tracked target even when it is far (a princess tower aims at
  the opposite tower 19 tiles away; Bats and Skeletons carry a tower while walking). The SIM target is set only once the target
  is acquired. Live target set while SIM none: 41,141 of 72,203 live-target frames (175459), 94% of them with the target beyond
  1.25 x sight; inside 1.25 x sight both sides have a target on 96%. Rule: live `tg = None` when centre distance to the target body >
  max(SightRange, Range) + 1500 mt (defs carry both). Sweep (175459, all frames): towers 0.47 -> 0.92 (+0) -> 0.965 (+1500); troops 0.71
  -> 0.88 (+0) -> 0.92 (+1500) -> 0.94 (+3000). The tolerance is the target's radius, a sweep not a derived constant.
- **Charging.** The 2-frame speed rule fires on any fast mover (Goblin Demolisher kamikaze, Skeletons in a Tornado: 672 false positives on the
  phase-3 logs; Fire Spirits' leap: 1,354 of 1,444 on the phase-2 logs). Restrict it to cards with a `charge` row (Prince, Dark Prince, Battle Ram, Ram
  Rider, Royal Recruits evo).
- **Buff fractions.** Live `duration_ms_raw` grows while an area keeps refreshing a buff (Rage, Poison), so `remaining /
  duration` falls from 0.6 to 0.36 while `remaining` itself saw-tooths 800-1000 on both sides. Use `remaining / table
  duration` live (the SIM does since fix 5): slow_frac 0.705 -> 0.901 on B.
- **Taunt.** The SIM models taunt as an action (`ActionTaunt`), not a buff; there is no per-unit flag to read. The forced
  target shows in `attack.target`. Mask `taunted` in training or train it live-only (it would be a feature the SIM never shows).
- **Stun.** Live `stunned` is name-based (`...Stun...`) and never fired in these logs; SIM `stunned` is now the same rule.
  Use `frozen`.

## 4. Simulation divergence (ii), not encoding

- Attack cycle after the first second: progress exact 0.889, phase either-attacking 0.830. Mix of Rage (not seeded at t0 by
  `fights.py`: AngryBarbarian progress A 0.324 vs Knight 0.917), later retargeting, and hit timing. By attacker (log 175459, B, either
  attacking): X-Bow phase 0.951, IW hero 0.918, Knight 0.904, princess tower 0.816, Bat 0.755, Mega Minion hero 0.825.
- Weapon shots: counts agree (tower 13,210 vs 13,192) but only 0.75 of (source, target) pairs match per frame (0.81 with +-1
  frame); positions of matched pairs agree to 13 mt. On the phase-2 logs, without the attack seed, the same match is 0.61 /
  0.58 and position error median 998 mt. In the first second the SIM starts with no shot in flight (live 2,127 vs SIM 1,582).
- Mega Knight dash: the extractor maps the SIM dash correctly (probe `s6/probe_mk.py`: `dash_state` Dashing -> `jumping` at
  5 and 6 tiles), but the SIM MK does not dash at 3.5-4 tiles where live does (live 41 jump frames, 9 of them aligned, SIM 0). Engine start
  condition, not encoding.
- Rage / Poison / Taunt / Zap seeded or cast times: `status.raged` A misses (Rage buffs on the t0 board are not seeded; B
  live-only 723 vs sim-only 184), `slowed` Poison 409 live-only on the p2 logs.
- Tower / Tesla / X-Bow `engaged` vs `idle` (5,310 + 2,525 tower frames, 1,941 building frames): target acquisition timing.
- Live state 2 with no target (1,279 troop frames in 175459) has no SIM counterpart.

## 5. Other findings

- Card table (client 160402017) vs device build 160402012: `SkeletonArmy_EV1_Soldier` HitSpeed 1000 live vs 1100 table,
  `GoblinDemolisher` 1200 vs 1100 (18 rows). Affects `frac` of those two only.
- Tesla `rising` (27 SIM frames) has no live counterpart (up 20 / hidden 7); the live reader cannot resolve the 0.5 s rise.
- GoblinDrill (the building) reads state 6 live at t0 but the setup spawn is idle in the SIM: 8 A-frames.
- The `frac` of a merged `A|B` alias is a lower bound (longest table duration of its names); use `slow_frac` and flags.

## 6. Concerns and limits

- Coverage gaps: no Battle Ram / Dark Prince charge, no Miner tunnelling, no champion ability, no Mega Knight jump matched,
  one charger card (Prince). Taunt exists in one match. `stunned`, `invisible` (126 frames) and `effect` are thin.
- Half the capture frames sit one tick off the log frame and were dropped (59% coverage): the sample is unbiased in time
  but halves the n. The merged-reader log (175459) has 100%.
- Agreement is on seeded fights, K = 0; no noise ceiling is applied. B numbers are the SIM-vs-live ceiling of a replay that
  runs up to 12 s, not the encoding.
- Nothing committed. Files changed: `pipeline/sim_unit_state.py`, `pipeline/tests/test_sim_unit_state.py`, this file,
  `scratchpad/gauntlet/L74/parity/s6/`. `fights.py` untouched.
