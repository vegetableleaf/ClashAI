## 2. LIVE OBS BUILDER

**Where.** `icebow/src/clashrl/play.py` -- `act_in_match(frame)` at `play.py:504-566` builds every input; `_threat_extra()` at `:397-471` builds the detector-derived blocks; `_tower_frac()` at `:473-490` the tower block. Frame source: `WindowCapture.grab()` (`capture.py:31+`, mss, physical pixels of the window matched by `window.title_contains: "Clash Royale"`, `window.region: null` = auto-detect; `config.yaml:8-10`).

**Checkpoint that play.py deploys.** `train.rl_checkpoint: data/policy_rl.pt` is preferred when it exists (`play.py:109-112`, `config.yaml:930-931`). Its metadata (loaded read-only): `in_ch 12, threat_dim 52, n_cards 10, n_cells 432, grid [18,24], arena_size [64,96], gate present, NO 'algo' key` (file dated 2026-09-05 19:51). `data/policy.pt` (BC) is `in_ch 3, threat_dim 52, no gate`. `data/policy_sim_ppo.pt` (2026-08-29) is the PPO sibling and is NOT what play.py picks up unless passed explicitly (`cli.py:681`).

**Tensor layout fed to `PolicyNet.forward_parts(x, hv, nv, ev, tv)`** (`play.py:552-559`):
- `x`: `[1, in_ch, 96, 64]` float in [0,1] = uint8/255, from `obs` = `Vision.observe(frame)` (`[96,64,3]` BGR) concatenated with the canvas stack. With the deployed net `in_ch 12` = 3 RGB + 6 semantic (`detect_obs.CHANNELS` = enemy_ground, enemy_air, enemy_building, my_ground, my_building, spell; `detect_obs.py:27-28`) + 3 predictive (`PRED_CHANNELS` enemy_predicted, my_predicted, enemy_urgency; `:34`) x `canvas_stack 1` slice (`config.yaml:299`). `use_predictive_canvas: true` (`:264`), `predictive_canvas_dt_s: 1.0` (`:265`), `use_hp_canvas: false` (`:281`) so the 2 HP channels are absent. Stack depth is taken from the checkpoint, not the config (`play.py:321`).
- `hv`: `[1, 10]` hand multi-hot from template matching of the 4 tray slots (`Vision.recognize_hand`, `vision.py:231`, slots `hand.slots` `config.yaml:17`, `hand.match_threshold 0.5` `:30`; templates under `templates/cards/`). If NO card is recognised the tick is skipped entirely (`play.py:509-510`).
- `nv`: `[1, 10]` next-card vector from `CycleTracker.observe(hand_ids, Vision.recognize_next(frame))` (`play.py:511`; next-card portrait at `hand.next_slot [0.090, 0.965]`, own template set `templates/next`, `config.yaml:46-50`).
- `ev`: `[1, 1]` = `read_elixir(frame)/10` -- INTEGER elixir (`int(read_elixir_frac)`, `vision.py:427-434`) from the pink fill's right edge along `elixir.bar_y 0.971`, `bar_x0 0.2797`, `bar_x1 0.9672` (`config.yaml:56-63`), HSV-thresholded, +0.1 pip bias nudge (`vision.py:436-474`). The sim feeds `eng.elixir[0]/10` which is fractional (`sim/env.py:621`) -- live quantises to integers (inferred mismatch, small).
- `tv`: `[1, 52]` = 16 base threat (`ThreatTracker.update(frame).vector()`, `threats.py:186-207`: red-pixel-mass features -- mass, my-side mass, largest blob, count, green, purple, depth, 3 lane masses, speed, projectile flag/x/toward-tower, behind-bridge mass, siege flag) + 10 identity (`card_threat.identity_threat_vector`) + 8 opponent memory (`OpponentMemory.update`) + 12 interactions (`interactions.interaction_vector`) + 6 tower HP (`_tower_frac`). Which blocks are appended is inferred from `threat_dim` of the checkpoint (`play.py:266-290`).

**How each scalar is read live (pixel/template readers -- no OCR except the tower digit CNN):**
- Elixir: pixel band HSV fill length (above). Only OUR elixir is on screen.
- Hand / next: `cv2.matchTemplate` TM_CCOEFF_NORMED against per-card PNG templates (`vision.py:149-230`).
- Match time: NOT an observation input. `ElixirClock` (`clock.py:49-135`) is WALL-CLOCK elapsed since the match-start read (`elixir.double_time_s 120 / triple_time_s 240 / overtime_time_s 180`, `config.yaml:74-80`), cross-checked against x2/x3 badge templates with the clock authoritative; it feeds the phase machine / live_search, not the tensor. There is no timer read of the on-screen "Time left" digits for the policy.
- Tower HP: princess towers via a digit CNN over the printed HP numbers (`tower_hp.py:203-329`, weights `src/clashrl/hp_digits.npz`, boxes `env.enemy_tower_hp_boxes` / `env.my_tower_hp_boxes` `config.yaml:1099-1100`, consensus 2 frames, min conf 0.55, `hp_full 4032`, `my_hp_full 4424`). Tower ALIVE flags via `TowerTracker` (`reward.py:546-600`): team-colour pixel fraction at the tower anchors below `env.tower_alive_frac`, latched after `confirm` frames. King HP: never printed -> alive flag only (1.0 until it falls) (`play.py:488-489`).
- Unit HP: `use_hp_canvas false`; `read_hp_frac` (`detect_obs.py:266+`) exists but is unused live.

**Fields NOT available live and what they get:**
- Opponent elixir: not visible. `OpponentElixirEstimator` (`opponent_elixir.py`) mirrored-spend estimate goes into opponent-memory slot 5 because `env.opp_mem_slot5: opp_estimate` (`config.yaml:1148`, `play.py:311-315`, `:460`). The sim wrote OUR elixir there (`sim/env.py:661`) -- HANDOFF 5cr.8 records this; the config is still on the mismatched `opp_estimate` value.
- Unit HP fractions: absent (HP canvas off).
- Team of an unresolved detection: `"unknown"` detections are NOT painted into the canvas (`detect_obs.py:196-206`) and are excluded from the identity/memory/interaction blocks (`play.py:445, :465`); the sim never emits unknown.
- Unit identity for cards outside `observation.detector_cards` (46 trusted base keys): painted into the semantic canvas (channel by KB role) but EXCLUDED from identity/memory/interaction/predictive blocks (`play.py:445, :465, :531`).
- Opponent hand/cycle, card levels, exact unit positions in tiles, king HP, match clock: absent from the tensor (zeros / alive proxy / nothing).
- Sim-only ground-truth twins: `sim/view.threat_vector` fills only indices 0-5 of the 16 base threat features (hp-mass, count/6, biggest hp, left/right-lane flags, depth; `sim/view.py:200-222`) while live `threats.py:186-207` fills all 16 with pixel-mass semantics whose index meaning DIFFERS (e.g. live idx1 = my-side red mass, sim idx1 = count/6; live idx3 = count/12, sim idx3 = "centroid left" flag). (observed by reading both; whether HANDOFF already carries this as a known parity gap is checked in section 4.)

**RGB image path: WARP NOT INSTALLED IN play.py.** `Vision.observe` returns the board-true remap only when `set_board_warp()` was called (`vision.py:97-131`); the ONLY caller is `env.py:466` (train-rl's env). `play.py` never calls it (grep: no `set_board_warp` / `_board_warp` in play.py), so live play's RGB channels are a plain `cv2.resize` of the WHOLE captured window (HUD + tray + board) to 64x96, while the semantic/predictive canvases in the same tensor ARE warped board-true (`play.py:523-524`). The docstring at `vision.py:100-104` calls the un-warped image "a permanent train/serve mismatch on the RGB channels and a driver of the live cell-head collapse (2026-08-14)". The sim's RGB is `sim/view.render_obs` (`sim/view.py:81-109`): grass fill, one river row, tower squares, 1-pixel unit dots -- a synthetic render, so RGB parity is approximate at best even when warped (inferred).

**Act period.** `play.act_period: 0.6` (`config.yaml:1285`, read at `play.py:492`; code default 1.5 is NOT what runs). Perception `observation.perception_hz: 10` (`:345`). Sim `sim.agent_dt: 0.6` (`:1522`) matches.

**Gate rule used live.** `play.py:628-633`: if the checkpoint has `algo == "ppo"` -> WAIT iff `sigmoid(gate[play] - gate[wait]) <= sim.ppo_gate_threshold` (= **0.25**, `config.yaml:2164`, read at `play.py:140`); OTHERWISE (no `algo` key, i.e. the deployed `data/policy_rl.pt`) -> legacy DDQN rule WAIT iff `gate[wait] >= gate[play]` (= tau 0.5). Consequences: (a) `sim.ppo_gate_rule: sample` (`:2173`) is honoured by viewers/graders only, not by play.py (the config comment at `:2170-2172` says so); (b) `train.rl_gate_tau: 0.25` (`:911`) is read by `train_rl.py:206-212` but NOT by play.py (grep: no `rl_gate_tau` in play.py) -- so a train-rl checkpoint is trained/benchmarked under tau 0.25 and deployed under tau 0.5, the exact drift the `rl_gate_tau` comment (`config.yaml:911-914`) says drops ~99% of the policy's plays. Live exploration `play.epsilon: 0.0` (`:1329`). `sim.live_search_enabled: true` (`:2155`) can override the policy's (card, cell) after the gate (`play.py:634+`).

**Ground truth for a live match: NONE.** Findings:
- No live recording carries the bot's own frames + detections + actions together. The overlay clips are pixels only; `reward_stats` carries actions + outcome but no perception dump; `play.py` never writes detections, obs tensors or the capture (grep `np.savez|jsonl|.write(` in `play.py`, `train_rl.py`, `env.py`, `perception.py` -> only the text log at `play.py:794-811`; the only `np.savez` is the offline labeler `label.py:226`).
- No live match logs a battle tag, the bot account's player tag, or a RoyaleAPI/official-API battle time. The only `player_tag` uses are card-level lookup for deck detection (`deck_detect.py:95-103`, CLI `--player-tag` `cli.py:879`) and the top-ladder deck/battlelog crawler (`deck_import.py:118-196`, `/players/{tag}/battlelog`); `tools/replay_priors.py:77-85` reads `battle_timestamp`/`player_tag` from the PRO crawl only. `config.yaml` holds `sim.api_token_file` (`:2267`) and `sim.api_base` (`:2272`) but NO own-account tag key.
- What COULD be matched after the fact (inferred, untested): each `reward_stats` record has an epoch `t` at match end and `play_log[].t` seconds since match start; the official API's `/players/{ownTag}/battlelog` returns the last ~25 battles with `battleTime` and both decks (card list only -- the official battlelog carries no per-play timings or positions), so at best one could recover opponent DECK + result per live match, not the opponent's play sequence. Per-play timings/tiles exist only in RoyaleAPI's replay data (as crawled into `plays_ext.csv` for pro tags), and that requires the bot's own tag + the replay tag, neither of which is logged. The bot's opponents are ladder players whose replays may not be crawled.
- Consequence for a frame-by-frame re-drive: the live->engine direction exists only as `sim/live_bridge.py` (detections -> `SimEngine` state for live search; its docstring lists what is ASSUMED: per-unit HP = spec max, deploy state idle, opponent hand uniform over detected deck, opponent elixir = estimate, ~80 fields unmodelled). There is no engine->live comparison harness and no recording with the opponent's true card plays to seed one. The closest ground-truth-bearing material is the pro replay crawl (card + time + tile per play, both sides) -- but those are pro-vs-pro matches with no screen recording from this pipeline, so they can test the ENGINE against pro outcomes, not the DETECTOR/obs path against a live frame.
