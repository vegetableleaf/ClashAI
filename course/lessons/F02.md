## Why this matters for ClashBot

A learning model does not directly consume a sentence such as “our tower is weak and X-Bow is affordable.” It receives numbers arranged in arrays. Linear algebra supplies a precise language for combining those numbers and checking whether their shapes agree.

The syllabus lists no source file here. We use `pipeline/model_v3.py`, a real model implementation with card, coordinate, and board representations. Its dimensions are larger than our examples, but the basic operations are the same. We will use NumPy from C01, keeping neural-network libraries for F08.

## 1. A vector is an ordered list of numbers

A **vector** is a sequence of numerical components with a fixed order. A **component** is one entry. A feature vector might contain elixir advantage followed by normalised tower-HP advantage. “Normalised” here means rescaled to a chosen numerical range.

```python
import numpy as np
state = np.array([2.0, -0.5])
print(state.shape)
print(state[0], state[1])
```

**Output:** `(2,)`, then `2.0 -0.5`.

A **dimension** can mean the number of components in a vector. This vector has two components. The shape tuple has one entry because the array has one axis. Keep those two uses of dimension distinct when reading descriptions.

The ordering is a contract. If the first weight expects elixir but receives HP, NumPy may still calculate an answer. Shape checks cannot detect every meaning error. Write a feature-order note beside every small model.

## 2. Addition and scaling

Vector addition combines corresponding components. **Scalar multiplication** multiplies each component by one number. A **scalar** is a single numerical value rather than an array of several values.

```python
import numpy as np
before = np.array([5.0, 100.0])
change = np.array([1.0, -20.0])
print((before + change).tolist())
print((change * 2).tolist())
```

**Output:** `[6.0, 80.0]` and `[2.0, -40.0]`.

These components have different units, so do not interpret their sum across components as a meaningful game quantity. Adding an elixir change to elixir is valid; adding elixir to HP usually is not.

A model can combine different features after choosing scales and weights, but that is a defined prediction rule, not a physical identity. The distinction matters when interpreting a large coefficient: it may compensate for a small input scale rather than indicate greater strategic importance.

## 3. The dot product makes a weighted score

A **dot product** multiplies matching components and adds the products. For vectors x and w, it is x[0]w[0] + x[1]w[1] + so on. The result is a scalar.

```python
import numpy as np
x = np.array([2.0, -0.5])
w = np.array([0.3, 0.8])
print(round(float(x @ w), 3))
```

**Output:** `0.2`.

The @ operator performs matrix multiplication; for two one-dimensional arrays it calculates a dot product. NumPy's np.dot also works for this simple case. First calculate 2×0.3=0.6 and -0.5×0.8=-0.4, then add them.

A **bias** is a constant added to the score. The expression x @ w + b can shift predictions even when every feature is zero. F04 will use this form for linear and logistic models.

```python
import numpy as np
x = np.array([2.0, -0.5])
w = np.array([0.3, 0.8])
b = -0.1
print(round(float(x @ w + b), 3))
```

**Output:** `0.1`.

This score is not yet a probability. It may be negative or exceed one. Do not label it P(win) until a defined transformation or model produces valid probabilities.

## 4. A matrix stores several vectors

A **matrix** is a rectangular array with rows and columns. A **batch** groups several examples for calculation together. If each row is one board state with two features, three examples form a matrix of shape (3,2).

```python
import numpy as np
X = np.array([[2.0, -0.5],
              [0.0, 1.0],
              [-2.0, 0.0]])
w = np.array([0.3, 0.8])
print(X.shape, w.shape)
print(np.round(X @ w, 3).tolist())
```

**Output:** `(3, 2) (2,)`, then `[0.2, 0.8, -0.6]`.

Each row is dotted with w. The output has one score per row, shape (3,). You can verify the first score using the previous example. This is a useful debugging habit: compare one batch row with a manual calculation.

**Elementwise multiplication**, written X * w, multiplies entries without summing across features. It produces a different shape and meaning. Broadcasting from C01 can make such a mistaken expression run successfully, so check outputs as well as exceptions.

## 5. Several outputs at once

Suppose a toy model assigns one score to “wait,” one to “Tesla,” and one to “X-Bow.” Put one output's weights in each column of a matrix W. With two features and three outputs, W has shape (2,3).

```python
import numpy as np
X = np.array([[2.0, 1.0], [0.0, -1.0]])
W = np.array([[1.0, 0.0, 0.5], [0.0, 2.0, -1.0]])
scores = X @ W
print(scores.shape)
print(scores.tolist())
```

**Output:** `(2, 3)`, then `[[2.0, 2.0, 0.0], [0.0, -2.0, 1.0]]`.

The inner dimensions match: X ends with two features and W begins with two features. The outer dimensions become the output: two examples and three choices. This shape rule prevents many mistakes before code runs.

A **transpose** swaps matrix rows and columns. NumPy uses .T for a two-dimensional transpose. If weights were stored as one output per row instead, you would multiply X @ W.T. There is no universal storage orientation; inspect the declared shapes.

## 6. Length and direction

A vector's **Euclidean norm**, often called its length, is the square root of the sum of squared components. It measures size in the chosen coordinate system.

```python
import numpy as np
v = np.array([3.0, 4.0])
print(float(np.linalg.norm(v)))
```

**Output:** `5.0`.

A **unit vector** has norm one. Divide a nonzero vector by its norm to keep its direction while removing its magnitude. A zero vector has no defined direction, so division by its norm is invalid.

```python
import numpy as np
v = np.array([3.0, 4.0])
unit = v / np.linalg.norm(v)
print(unit.tolist())
```

**Output:** `[0.6, 0.8]`.

For mixed-unit game features, length depends on scaling. Replacing HP with thousands of HP changes the geometry. That is one reason normalisation must be defined before interpreting distances.

## 7. Similarity and embeddings

An **embedding** represents a category, such as a card identity, with a vector. Learned embeddings are adjusted during training. They need not have human-labelled axes such as “defence” or “speed.”

For teaching, imagine invented vectors for three cards. These are not actual ClashBot embeddings or reliable card statistics.

```python
import numpy as np
cards = np.array([[1.0, 0.0], [0.8, 0.2], [0.0, 1.0]])
query = np.array([1.0, 0.0])
print((cards @ query).tolist())
```

**Output:** `[1.0, 0.8, 0.0]`.

A dot product depends on both direction and magnitude. **Cosine similarity** divides the dot product by the product of the two norms, comparing direction. For nonzero vectors its value is between minus one and one.

```python
import numpy as np
a = np.array([1.0, 0.0])
b = np.array([2.0, 0.0])
cosine = (a @ b)/(np.linalg.norm(a)*np.linalg.norm(b))
print(float(cosine))
```

**Output:** `1.0`.

The vectors point the same way despite different lengths. Cosine similarity does not mean the cards are interchangeable in a match. Affordability, placement, cycle, and target interactions are separate constraints.

Our exercise adopts a defined zero-vector convention: return 0.0 if either norm is zero. This avoids division by zero but should be documented because the mathematical cosine itself is undefined there.

## 8. Trace a shape before a value

For every operation, write the input shapes and expected output shape. Then use a tiny numerical example. Finally, check a non-square case so accidental transposes are visible.

An identity matrix, written np.eye(n), leaves an n-component vector unchanged under multiplication. It is useful as a control case. A matrix of zeros should produce zero scores before adding bias. These tests ask meaningful questions about the operation rather than just repeating its syntax.

Keep numerical comparisons tolerant of tiny rounding differences. NumPy's np.allclose compares arrays within a small tolerance. Use exact comparisons for shapes and integer counts, and approximate comparisons for calculated floating-point values.

## In the real project

From `pipeline/model_v3.py`:

```python
GRID_X, GRID_Y = 36, 64             # half-tile cells: cx = floor(x * 36), cy = floor(y * 64)
PATCH_X, PATCH_Y = 9, 16            # 2-tile patches
N_CELLS = GRID_X * GRID_Y
N_PATCHES = PATCH_X * PATCH_Y
```

**Output:** none; these define dimensions.

The first line defines the placement grid. The second defines a coarser board partition. The third multiplies grid dimensions to obtain 2,304 cells. The fourth obtains 144 patches. The stored axes represent spatial organisation, not the number of examples.

Another exact line from the same source:

```python
        kp = (self.cell_key(enc["p"]) * q.unsqueeze(1)).sum(-1)                        # [B, P]
```

**Output:** none by itself; the result is assigned.

This is PyTorch syntax, which F08 covers properly. For now, enc["p"] supplies patch representations, self.cell_key transforms them, and q supplies a comparison vector. Unsqueeze inserts an axis so shapes align. Multiplication forms component products; sum(-1) adds along the last axis. The comment says the result has one score per batch example and patch. It is the dot-product pattern you just practised.

## Common mistakes

- Swapping feature order while keeping the same shape.
- Using elementwise multiplication where a summed score is needed.
- Calling an unrestricted score a probability.
- Dividing by a zero norm.
- Treating embedding similarity as strategic equivalence.
