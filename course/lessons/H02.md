## Why this matters for ClashBot

In H01 an earlier X-Bow decision received credit for a later win. That does not tell us whether the decision was unusually good. If ClashBot was already overwhelmingly likely to win, a victory provides different information from an unexpected recovery.

The `loo_advantage` and `gae` functions in `pipeline/rl_royale.py` implement two ways to compare results with expectations. These are alternatives with different assumptions. Reading their names is easier once you can work a three-decision example yourself.

A value estimate can be wrong because the model is poorly trained, because crforge presents unfamiliar boards, or because the live reader supplies different observations. This lesson separates arithmetic correctness from prediction quality. We can test the former exactly; the latter needs held-out matches.

## 1. Predict a return, then observe one

A **value function**, written V(s), predicts the expected future return from state s under a specified policy. Expected means an average across possible continuations, not a guarantee for this match. With rewards +1 for a win and -1 for a loss, a state with 75% win probability and no draws has value 0.5.

```python
p_win = 0.75
value = p_win * 1 + (1 - p_win) * -1
print(value)
```

It prints `0.5`. This value is not itself a win probability. Solving for the probability gives (value + 1) / 2 only under the stated two-outcome convention. If draws or discounting enter, explain what quantity you are predicting before converting units.

A **Monte Carlo target** uses an observed return from a complete episode. A single winning continuation gives target +1 even if the best prediction before playing was 0.5. The difference is not necessarily a prediction bug: one observation is noisy. Over many comparable examples, the value model should predict the average.

```python
targets = [1, 1, 1, -1]
print(sum(targets) / len(targets))
```

It prints `0.5`. Four samples are too few to establish precise calibration, but they illustrate the distinction between an individual outcome and an expectation.

## 2. Advantage asks what exceeded expectation

An **advantage** measures how much better an action's return is than a baseline expectation. In a simple sampled estimate, advantage equals observed return minus predicted value. A **baseline** is the quantity subtracted to remove predictable variation.

```python
returns = [1.0, -1.0]
values = [0.8, -0.6]
advantages = [g - v for g, v in zip(returns, values)]
print([round(a, 2) for a in advantages])
```

It prints `[0.2, -0.4]`. The win is only modestly better than expected. The loss is worse than the prediction, although that prediction was already negative. The sign concerns the comparison, not just whether the match was won.

Subtracting a baseline can reduce noise in policy learning. H03 will show why the baseline must not depend on the sampled action in the wrong way. A value model uses information available before choosing the action; inserting the later result into that input would leak the answer.

Do not equate advantage with a causal proof. A lucky opponent mistake can make a poor deployment receive a positive sampled advantage. Repeated experience, careful opponents and uncertainty estimates remain necessary.

## 3. Learn partly from a prediction of the next state

A **temporal-difference target**, or TD target, uses the immediate reward plus a discounted next-state value. This is **bootstrapping**: using one estimate inside the target for another estimate. It can update before the full match ends, but it inherits prediction error.

The **TD error**, delta, subtracts the current prediction from that target. For a completed terminal transition, there is no future return after the match. Use next value zero, even if a reset state has already been placed into the next observation slot.

```python
reward = 0.0
gamma = 0.9
value = 0.2
next_value = 0.5
delta = reward + gamma * next_value - value
print(round(delta, 2))
```

It prints `0.25`. A terminal winning transition with current value 0.2 instead has delta 0.8. Accidentally adding the next match's opening value changes that target and creates a hidden dependency between unrelated games.

A time limit that interrupts a still-running game is not always a true terminal state. Our exercises contain only completed episodes. A real collector needs to distinguish termination from truncation and define whether the final observation can be bootstrapped.

## 4. Combine short and long credit with GAE

**Generalized advantage estimation**, abbreviated GAE, adds discounted TD errors backwards through an episode. Its extra parameter **lambda** controls how strongly later errors contribute. The recurrence is A[t] = delta[t] + gamma * lambda * A[t+1].

```python
deltas = [0.1, 0.8]
gamma = 0.9
lam = 0.5
last = 0.0
out = []
for delta in reversed(deltas):
    last = delta + gamma * lam * last
    out.append(last)
print([round(a, 2) for a in reversed(out)])
```

It prints `[0.46, 0.8]`. Lambda zero uses only each TD error. Lambda one, with complete episodes and matching discount conventions, gives observed return-to-go minus the current value. Intermediate settings trade some long-horizon noise for dependence on imperfect value estimates.

**Bias** is systematic error in an estimate. **Variance** is its spread across repeated samples. Neither word means that one method is always better. A weak value model can make short bootstrapped targets misleading; long complete-match targets can be noisy.

When processing several matches together, reset both the next value and next advantage at every match boundary. In the exercise, a Boolean `done` list marks terminal transitions. Walk backwards, set the continuation to zero at a boundary, then compute that row. Never carry the final advantage from match two into match one.

## 5. Use other continuations as a baseline

**Leave-one-out**, or LOO, means the baseline for sample i averages all samples in its group except sample i. In `match_loo`, the group is repeated rollouts of the same matchup. This controls for some matchup difficulty without training a critic.

For returns [1, -1, 1], the first rollout's baseline is zero, so its advantage is one. The losing rollout's baseline is one, so its advantage is minus two. The third advantage is one again.

```python
returns = [1, -1, 1]
total = sum(returns)
advantages = []
for result in returns:
    baseline = (total - result) / (len(returns) - 1)
    advantages.append(result - baseline)
print(advantages)
```

It prints `[1.0, -2.0, 1.0]`. The advantages sum to zero for this group. Including a sample in its own baseline shrinks its contrast; calling that LOO would be incorrect.

A one-element group has no other continuation. The project returns zero advantage for it rather than dividing by zero. This is a conservative convention, not evidence that the decision was average. Also, do not mix unrelated matchups merely to make the group larger. Different starting decks or opponent strengths can dominate the comparison.

When all repeated outcomes are equal, every LOO advantage is zero. A hard matchup with all losses then provides no contrast through this particular estimator. That limitation should inform experiment design rather than be hidden by inventing small positive rewards.

## In the real project

No file is listed for H02, so the relevant trainer functions are the source. This exact excerpt is from `pipeline/rl_royale.py`:

```python
def loo_advantage(R, clip: float = 2.0) -> np.ndarray:
    """E1 3.2: A_i = R_i - mean_{j != i} R_j over one entry's rollouts; |A| <= clip; a one-outcome group -> 0."""
    R = np.asarray(R, dtype=np.float64)
    if len(R) < 2:
        return np.zeros(len(R))
    return np.clip(R - (R.sum() - R) / (len(R) - 1), -clip, clip)
```

Line one names the function and its clipping default. Line two states the estimator and singleton convention. Line three converts the returns to a floating-point array. Lines four and five handle groups without a usable comparison. Line six subtracts the other-rollout mean and clips the result. This definition prints nothing; calling it on [1, -1, 1] produces the advantages above.

The same file's GAE contract says:

```text
    gamma_t V_{t+1} - V_t with V after a match's last row = 0 (terminal); A_t = delta_t + gamma_t lambda A_{t+1} within
    the match. -> (A, returns = A + V); lambda = 1 makes the returns the discounted returns-to-go. One step = one
```

The first line makes the terminal boundary explicit. The second gives the value-training target as advantage plus old value and identifies the lambda-one special case. The excerpt is part of a docstring, so it has no stdout.

A tolerance checks mathematical agreement; it should not conceal a wrong sign or missing reset.

## Common mistakes

- Treating value on a -1/+1 reward scale as a probability.
- Bootstrapping after a terminal match into the next match.
- Subtracting the full group mean and calling it leave-one-out.
- Letting the critic use information from after the action.
- Interpreting zero LOO advantage as proof that a policy is optimal.
