## Why this matters for ClashBot

ClashBot plays the Icebow X-Bow deck through a phone emulator. A match produces observations, decisions, and a recorded ending. The file `scratchpad/gauntlet/L74/loss_review/matches.jsonl` collects summaries of these runs. Reading it lets you ask what was actually recorded instead of relying on an impression from watching the phone.

The same basic skill supports later work with RoyaleSim and crforge, the project's game simulators. A **simulator** is a program that computes how a game changes. Their records and live records are different sources of evidence. Successfully reading either source does not make their results interchangeable.

Later, **imitation learning** will mean learning from examples of actions, and **reinforcement learning** will mean learning from outcomes of actions. Both depend on correctly interpreting records. This lesson does not train anything. It teaches you to preserve the meaning of the input before calculating a result.

## 1. Start with text, not assumptions

A **text file** stores characters. Python initially reads those characters as strings, not as dictionaries. A **record** is one logical item of data, such as one match summary. In **JSON Lines**, abbreviated JSONL, each nonblank line contains a separate JSON value. Here the intended value is a match dictionary.

Recall that a dictionary associates field names with values. The text spelling of that dictionary is not yet a Python dictionary:

```python
line = '{"derived":"WIN","n_plays":12}'
print(line)
print(type(line))
```

It prints `{"derived":"WIN","n_plays":12}` and then `<class 'str'>`. Quotes around the outer string tell Python to treat the contents as text. The double quotes inside belong to JSON. A log line can look structured to your eyes while still being one string to Python.

Do not start by assuming there is a field called `win`. This project's file uses a field called `derived` for recorded outcome labels. Some rows do not have that field. We will keep those rows visible rather than invent an answer for them.

## 2. Decode one string

**Decode** means convert a stored representation into values your program can work with. Python supplies a JSON decoder. For now, `import json` makes that supplied tool available; B08 explains imports in detail. This small introduction is enough for today's file work.

```python
import json

line = '{"derived":"WIN","n_plays":12}'
row = json.loads(line)
print(row["derived"])
print(row["n_plays"] + 1)
```

It prints `WIN` and `13`, on separate lines. The `s` in `loads` means the input is a string. The number twelve becomes an integer, so addition works normally. Parsing does not verify that twelve plays really happened. It only interprets the text's structure.

A JSON `false` becomes Python `False`, and JSON `null` becomes Python `None`. **None** is Python's value for no value being supplied. It is different from zero, an empty string, and `False`.

```python
import json

row = json.loads('{"dry_run":false,"decide_ms_med":null}')
print(row["dry_run"])
print(row["decide_ms_med"] is None)
```

It prints `False` and `True`. The operator `is` checks identity; `is None` is the usual way to ask whether something is the special missing-value object.

## 3. Open a file and close it reliably

**Opening** a file asks the operating system for access to it. `open` returns a **file object**, a value with operations for reading or writing. A `with` block keeps that access open during the indented statements and closes it when the block finishes.

```python
path = "scratchpad/gauntlet/L74/loss_review/matches.jsonl"
with open(path, encoding="utf-8") as source:
    first_line = source.readline()
print(first_line.startswith("{"))
```

For the inspected file, it prints `True`. `readline()` reads one line, including its ending newline if present. `startswith` tests the beginning of a string. The variable `first_line` still exists after the file is closed because its text has already been read.

An **encoding** is the rule used to turn stored bytes into characters. UTF-8 is the encoding used here. Explicitly naming it avoids depending on a Windows default. The path is relative to the **working directory**, the folder from which the process resolves relative paths. The interactive exercise runner uses the repository root, even though its temporary Python file lives elsewhere.

The default opening mode is reading. You do not need a write mode to analyse a log. Reading leaves the recorded evidence unchanged.

## 4. Process one line at a time

A file object can be used directly in a `for` loop. Each iteration gives the next line. The string method `strip()` removes whitespace from the ends. A string containing only spaces and a newline becomes an empty string, which is false in an `if` condition.

```python
lines = ['{"derived":"WIN"}\n', '   \n', '{"derived":"LOSS"}\n']
nonblank = 0
for line in lines:
    if line.strip():
        nonblank += 1
print(nonblank)
```

It prints `2`. Skipping a blank line is different from skipping a malformed record. A nonblank line with broken JSON will raise an error. B07 teaches how to report that error. For now, letting it stop the program is better than quietly counting incomplete text as a loss.

Reading a whole file using `source.read()` is sometimes convenient, but one call to `json.loads` cannot decode several independent JSON objects separated by newlines. Decode each line separately. JSONL is not the same format as a single JSON list containing many dictionaries.

## 5. Build a reusable loader

Combine the file loop with the functions you learned in B05. This function receives a path and returns a list of decoded rows:

```python
import json

def load_rows(path):
    rows = []
    with open(path, encoding="utf-8") as source:
        for line in source:
            if line.strip():
                rows.append(json.loads(line))
    return rows
```

This definition prints nothing. Calling it returns data; returning and printing are different actions. Keeping the loader separate from printing lets another function count rows or select particular fields without rereading the file.

The loader assumes each nonblank line is valid JSON. It also assumes the decoded values are dictionaries. Those are **input assumptions**: conditions the rest of the code relies on. P02 will make the dictionary requirement explicit. Do not confuse a convenient beginner example with a complete validator for arbitrary files.

## 6. Count labels without losing unknown records

The dictionary method `get(name)` returns the named value when present and `None` when absent. Unlike square-bracket lookup, a missing name does not immediately stop execution.

```python
row = {"n_plays":12}
print(row.get("derived"))
print(row.get("derived", "UNKNOWN"))
```

It prints `None` and `UNKNOWN`. The second argument is a default used only when the field is absent. A present value of `None` remains `None`, so a robust category counter also checks which labels it recognises.

```python
rows = [{"derived":"WIN"}, {"derived":"LOSS"}, {}, {"derived":"DRAW"}]
counts = {"WIN":0, "LOSS":0, "DRAW":0, "UNKNOWN":0}
for row in rows:
    label = row.get("derived")
    if label not in ("WIN", "LOSS", "DRAW"):
        label = "UNKNOWN"
    counts[label] += 1
print(counts)
```

It prints `{'WIN': 1, 'LOSS': 1, 'DRAW': 1, 'UNKNOWN': 1}`. Every row contributes exactly once. Unknown does not mean defeat, victory, or draw. It means this counting rule has no recognised recorded label.

A **denominator** is the number underneath a fraction. For a decided-match win rate, use wins plus losses as the denominator. Draws and unknowns still need their own counts. One win, one loss, and eight unknowns gives a decided-match rate of one half, with very incomplete outcome coverage. Reporting only fifty percent hides that limitation.

The file also includes `dry_run`. A **dry run** records a rehearsal rather than ordinary live execution. P02 includes only rows explicitly marked `dry_run: false` in its outcome counts and reports other rows separately. Today's simple tally counts labels regardless of that flag so you can learn one operation at a time.

## 7. Encode and write deliberately

**Encode** reverses decoding: `json.dumps` turns a Python value into JSON text. It does not save that text anywhere by itself.

```python
import json

text = json.dumps({"derived":"WIN"})
print(text)
```

It prints `{"derived": "WIN"}`. Spaces may differ from the original input while the decoded value remains the same. JSONL needs a newline between records. Forgetting it can join two objects into one invalid line.

For exercises we use an **in-memory stream**, a file-like destination that keeps text in memory. This lets you practise `write` without overwriting any repository file. The supplied `io.StringIO` tool provides that destination; its module mechanics are covered in B08.

```python
import io
import json

destination = io.StringIO()
destination.write(json.dumps({"derived":"WIN"}) + "\n")
print(destination.getvalue().splitlines())
```

It prints `['{"derived": "WIN"}']`. `getvalue()` returns stored text, and `splitlines()` divides it into strings without line endings. A real destination opened with mode `"w"` would replace existing contents; mode `"a"` would append. You will not open the match source in either mode.

## In the real project

Open `scratchpad/gauntlet/L74/loss_review/matches.jsonl` as text. This is a short exact fragment from its first record, not a complete JSON object:

```text
"has_end": true, "stop_why": "max_seconds", "wall_s": 30.1
```

On this single line, `has_end` records an ending marker, `stop_why` gives the stopping reason, and `wall_s` records elapsed seconds. An ending marker with a time limit is not by itself evidence of a win. This first row has no `derived` label. That is why our counter needs UNKNOWN.

Another exact fragment from that same record is:

```text
"pending_plays": 0, "valid_state": false
```

On this line, `pending_plays` is a count and `valid_state` is a boolean. The two values answer different questions. Neither is an outcome label. Real records contain several kinds of evidence; choosing the field that answers your question is part of programming, not just a formatting detail.

These fragments are reading examples and print nothing. The interactive loader reads complete lines, not these fragments. The file may grow, so exercise checks compare against its current contents rather than a count copied into this lesson.

## Common mistakes

- Passing the whole JSONL file to one `json.loads` call.
- Treating a missing outcome as a loss.
- Opening the source with `"w"`, which would replace it.
- Forgetting the newline between written JSON objects.
- Confusing a valid JSON structure with a verified game result.
