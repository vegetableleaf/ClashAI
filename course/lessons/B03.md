# B03 - Collections: a deck as a list, card stats as a dictionary

**Time:** about 4 hours - **You will be able to:** represent decks, hands, and card lookups with appropriate collections.

## Why this matters for ClashBot

An Icebow deck contains multiple cards, and a visible hand contains four. Giving every card its own unrelated variable makes ordering and updates awkward. Collections let you represent groups directly, while preserving distinctions such as ordered hand positions and named card properties.

`icebow/data/card_ids.json` maps numeric-looking identifiers to card names. It is a useful real example of structured lookup data. We will inspect a short excerpt and read this specific file in an exercise. Its mapping direction matters: an identifier looks up a name, not an elixir cost.

Learning code needs collections for observations, available actions, and recorded examples. Whether those records came from a phone emulator, RoyaleSim, or crforge, you still need to know what each collection contains before passing it to a model.

## 1. Lists preserve order

A **collection** groups several values. A **list** is an ordered, changeable collection written with square brackets. Commas separate its **elements**, the individual values inside it.

```python
hand = ["X-Bow", "Tesla", "Knight", "Skeletons"]
print(hand)
```

It prints `['X-Bow', 'Tesla', 'Knight', 'Skeletons']`. Python's display includes brackets and quoted strings to show the structure. These are not extra cards; they are notation describing a list.

The built-in `len` reports the number of elements:

```python
hand = ["X-Bow", "Tesla", "Knight", "Skeletons"]
print(len(hand))
```

It prints `4`. A four-element list is a useful hand representation, but its length alone does not prove that each card is legal or that the hand matches the emulator. Structure checks are necessary but not sufficient evidence about game state.

For a teaching deck, we will use X-Bow, Tesla, Ice Wizard, Knight, Skeletons, Tornado, Rocket, and The Log. Exact project configurations may use different naming conventions or variants. Our strings are labels for exercises; the real identifier file below provides a separate mapping convention.

## 2. Indexing selects one element

An **index** is an element's position. Python lists start at zero. For four elements the indexes are zero, one, two, and three. Square brackets after a list name select a position.

```python
hand = ["X-Bow", "Tesla", "Knight", "Skeletons"]
print(hand[0])
print(hand[3])
```

It prints `X-Bow` then `Skeletons`. Index zero selects the first card; index three selects the fourth. This is why a hand position displayed as "slot 1" in an interface may correspond to index zero in code. Document which convention you mean.

Negative indexes count backward from the end. Index `-1` selects the last element:

```python
hand = ["X-Bow", "Tesla", "Knight", "Skeletons"]
print(hand[-1])
```

It prints `Skeletons`. An index beyond the available range causes an error rather than returning an invented card. B07 teaches errors systematically; today avoid out-of-range indexes by tracing the list's length.

## 3. Slicing selects a sequence

A **slice** selects a range of elements. `items[start:stop]` includes the start position and excludes the stop position. Omitting the start means start at the beginning. Omitting the stop means continue to the end.

```python
deck = ["X-Bow", "Tesla", "Ice Wizard", "Knight", "Skeletons", "Tornado", "Rocket", "The Log"]
print(deck[:4])
print(deck[4:])
```

It prints `['X-Bow', 'Tesla', 'Ice Wizard', 'Knight']` and then `['Skeletons', 'Tornado', 'Rocket', 'The Log']`. The first slice models a starting hand; the second models the remaining ordered cards. This is a simplified cycle representation, not a complete engine implementation.

A list slice produces a new list. Changing the new list's top-level elements does not replace elements in the original list. Simply assigning another name to the same list is different: both names refer to the same collection. We explore that distinction shortly.

## 4. Change a list deliberately

A **method** is an operation accessed through a value with a dot, such as `hand.append(...)`. Methods are introduced minimally here for collections; B09 explains objects and methods more fully. `append` adds one element to the end. `pop(index)` removes and returns an element.

```python
queue = ["Skeletons", "Tornado"]
queue.append("X-Bow")
next_card = queue.pop(0)
print(next_card)
print(queue)
```

It prints `Skeletons` then `['Tornado', 'X-Bow']`. Removal changes the list, so the second display no longer includes Skeletons. The returned value was stored separately as `next_card`.

You can replace an element by assigning to an index:

```python
hand = ["X-Bow", "Tesla", "Knight", "Skeletons"]
hand[0] = "Rocket"
print(hand[0])
```

It prints `Rocket`. This changes only the first position. A real hand-cycle operation also needs to update the queued cards. B05 will package that complete operation into a function.

## 5. Copies and shared names

A **mutable** value can be changed in place. Lists are mutable. Two names can refer to the same list, which is sometimes called **aliasing**. Assigning the list to another name does not automatically copy its elements.

```python
hand = ["X-Bow", "Tesla"]
other = hand
other[0] = "Rocket"
print(hand[0])
```

It prints `Rocket`, because both names refer to the same list. This can be surprising when you intend to compare a before-state with an after-state.

```python
hand = ["X-Bow", "Tesla"]
other = hand[:]
other[0] = "Rocket"
print(hand[0])
```

It prints `X-Bow`. The slice copied this flat list. A **shallow copy** copies the outer collection but not any nested mutable contents. Our card-name lists contain strings, so an outer copy is sufficient for these exercises. Nested state copying comes later.

## 6. Tuples describe fixed sequences

A **tuple** is an ordered collection that does not allow replacing its elements. Such a value is **immutable**. Parentheses commonly express tuples, with commas between elements.

```python
cell = (3, 12)
print(cell[0])
print(cell[1])
```

It prints `3` then `12`. This could represent a toy arena coordinate. The order must be defined: first horizontal position, then vertical position. A tuple does not know those meanings automatically.

Tuples support indexing and slicing like lists. Choose one when a fixed grouping communicates your intent, such as a pair of coordinates. Choosing a tuple does not validate whether the coordinates lie inside the actual arena. Representation and rule checking remain separate concerns.

## 7. Dictionaries look up named values

A **dictionary**, type `dict`, maps lookup names called **keys** to values. A key need not be a word; it can also be another supported immutable value. In our examples, keys are strings. Braces enclose pairs, colons separate keys from values, and commas separate pairs.

```python
costs = {"X-Bow": 6, "Tesla": 4, "Skeletons": 1}
print(costs["Tesla"])
```

It prints `4`. A list lookup asks "what is at this position?" A dictionary lookup asks "what value belongs to this key?" This distinction is more important than memorizing brackets because both operations use square brackets in Python.

The method `get(key, default)` returns the value if present, otherwise the supplied default:

```python
costs = {"X-Bow": 6}
print(costs.get("Unknown", -1))
```

It prints `-1`. Here that value explicitly means "missing from this teaching mapping." Using zero would misleadingly suggest a free card. Defaults should preserve uncertainty rather than disguise it.

## 8. Sets represent distinct members

A **set** is a collection of distinct elements without meaningful positional order. Construct one with `set(sequence)`. Repeated values collapse to one member. The expression `value in collection` asks about membership and returns a boolean.

```python
seen = set(["Tesla", "X-Bow", "Tesla"])
print(len(seen))
print("Tesla" in seen)
```

It prints `2` then `True`. Do not use a set to represent a hand's positions or a cycle order. Sets answer "which different cards?" rather than "which card comes next?" Their printed order should not be treated as stable evidence.

## In the real project

From `icebow/data/card_ids.json`:

```json
{
 "26000000": "knight",
 "26000001": "archers",
 "26000002": "goblins",
```

This is the opening excerpt of a longer file, not a complete JSON document to run. It prints nothing. Line 1 opens the object. Line 2 maps an identifier string to `knight`. Line 3 maps another identifier to `archers`. Line 4 maps another to `goblins`. The real file continues and closes its object.

These identifiers look numeric but are JSON object names, so they are strings. The values are lowercase card labels, not costs. Do not reinterpret the large identifiers as damage, levels, or elixir. The mapping's direction is identifier to name.

## A small preview of reading that file

For one exercise we need a tiny preview of imports and file reading. **Import** makes a module's tools available; a **module** is a named unit of Python code. `json.load` reads a JSON document from an open file. `with` manages the file's lifetime and closes it afterward. We cover these properly in B06 and B08.

```python
import json
with open("icebow/data/card_ids.json", encoding="utf-8") as source:
    card_names = json.load(source)
print(card_names["26000000"])
```

It prints `knight` for the inspected mapping. The quoted path is relative to the repo root. `encoding="utf-8"` tells Python how to interpret stored text. `as source` gives the opened file the temporary name `source`; `json.load(source)` reads from it. The indented line belongs inside the `with` block. The exercise supplies this reading scaffold; you complete ordinary collection operations on its result.

## Common mistakes

- Counting list indexes from one.
- Including the stop position in a slice.
- Treating a set as ordered.
- Assuming assignment copies a list.
- Treating card identifiers as costs.
