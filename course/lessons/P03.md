## 1. Specify the report before reading results

The **analysis pipeline** is a sequence of transformations from records to conclusions. Our contract is fixed: read nonblank JSON lines, retain only timestamp and derived outcome for analysis, parse the recorded timestamp format, report invalid dates, and split valid rows at the chronological midpoint. The first period contains floor(n/2) rows; the second contains the remainder. This is a deterministic educational split, not an optimized changepoint or a test of a particular deployment. If timestamps tie, stable sorting preserves input order. Tied timestamps may cross the midpoint, which is another reason to describe these as chronological halves rather than distinct calendar regimes.

```python
n=5
cut=n//2
print(cut,n-cut)
print(['early']*cut+['late']*(n-cut))
```

**Output:** `2 3` and `['early', 'early', 'late', 'late', 'late']`.

The floor-division operator // was introduced with Python arithmetic. Fixing the rule before inspecting outcomes avoids moving the boundary to create a flattering result. For a real deployment analysis, use a separately justified deployment time and record it before scoring.

## 2. Clean records without erasing evidence

The first milestone converts rows into a table with ts, result, and parsed time. Keep WIN, LOSS, DRAW, and unknown. Missing or invalid timestamps become missing date-time values through errors='coerce'. This policy separates two kinds of missingness: an unknown outcome can still have a valid time and belong to a period, while an invalid time prevents chronological placement even if its outcome is known. Report both exclusions. A small synthetic fixture, meaning a deliberately constructed test input, lets you prove those distinctions before reading the current file.

```python
import pandas as pd
rows=[{'ts':'20260925_183254','derived':'WIN'}, {'ts':'bad'}]
df=pd.DataFrame(rows)
time=pd.to_datetime(df['ts'],format='%Y%m%d_%H%M%S',errors='coerce')
print(time.notna().tolist())
print(df['derived'].fillna('unknown').tolist())
```

**Output:** `[True, False]` and `['WIN', 'unknown']`.

This display uses fillna for the fixture. Your complete cleaner also checks recognized outcome values, so an unfamiliar string becomes unknown. Do not print entire source rows just to inspect a count. The analysis only needs the two selected fields.

## 3. Summarize with uncertainty

For each period, count all four outcome categories. Set n=wins+losses and rate=wins/n when n is positive. Call the C05 Wilson helper and retain both endpoints. An empty decisive subset has rate=None and ci=None. The report must not display it as a zero-percent period or draw an invented error bar. pandas indicators make the counts concise, while an ordinary dictionary keeps the final summary transparent. **Serialization** into a dictionary is useful here because the final prose and plot can consume the same checked values.

```python
w,l,d,u=3,2,1,4
n=w+l
print({'wins':w,'losses':l,'draws':d,'unknown':u,'n':n})
print(round(w/n,2))
```

**Output:** `{'wins': 3, 'losses': 2, 'draws': 1, 'unknown': 4, 'n': 5}` and `0.6`.

The category counts sum to ten, while the denominator is five. A report that provides only .6 hides half the story. Wilson intervals cover sampling uncertainty under their model; they do not repair selection bias if matches with unknown endings systematically differ from known ones.

## 4. Plot estimates and intervals

An **error bar** is a graphical interval attached to an estimate. matplotlib's errorbar accepts yerr as distances below and above each point. Wilson intervals are not generally symmetric around the sample fraction, so supply two separate distances: rate-low and high-rate. This lesson introduces errorbar explicitly; you already know figure creation, labels, savefig, and close from C03. Multiply the estimate and both distances by 100 when labeling percentage units. Skip undefined estimates and explain why a point is absent.

```python
import matplotlib.pyplot as plt
fig,ax=plt.subplots()
rate,lo,hi=.6,.23,.88
ax.errorbar([0],[100*rate],yerr=[[100*(rate-lo)],[100*(hi-rate)]],fmt='o')
ax.set_ylabel('Decisive win rate (%)')
ax.set_ylim(0,100)
print(ax.get_ylabel())
plt.close(fig)
```

**Output:** `Decisive win rate (%)`; an asymmetric error bar is created in memory.

fmt='o' draws a circular marker. In the project, use early and late labels and save only inside a caller-provided temporary directory. The plot communicates the summaries; it is not a formal paired treatment comparison. Do not infer a test result just by whether the separate intervals overlap.

## 5. Write a bounded conclusion

The final milestone assembles the report and produces a conclusion string. **Measured** means a claim directly supported by the computed observations. **Plausible** means an explanation worth testing but not established by this report. **Contradicted** applies to a claim that conflicts with the observed result under its stated scope. A positive observed difference measures improvement in this sample, not proof of higher underlying future win probability. A negative observed difference contradicts the narrower statement that the later sample had a higher rate, but does not prove every proposed policy change is harmful.

```python
early,late=.5,.6
delta=100*(late-early)
print(f'Measured: later minus earlier = {delta:.1f} percentage points.')
print('Plausible: policy changes contributed; causation is not established.')
```

**Output:** `Measured: later minus earlier = 10.0 percentage points.` followed by the stated plausible explanation.

If either period has no decisive games, say insufficient decisive outcomes instead of subtracting None. Include the unknown and invalid-date counts beside the conclusion. Your final written discussion should propose one controlled follow-up, such as a frozen paired simulator comparison, rather than recommending deployment from this descriptive report.

## Common mistakes

- Splitting on outcomes or choosing a favorable date after seeing rates.
- Dropping invalid dates without reporting their number.
- Calling overlapping intervals proof that periods are identical.
- Mixing a percent difference with percentage points.
- Claiming improvement caused by training from an uncontrolled period comparison.
