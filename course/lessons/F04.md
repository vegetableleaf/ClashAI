## 1. Linear regression predicts a number

**Regression** estimates a numerical target. **Linear regression** uses a weighted sum of features plus a bias. In the two-feature case, prediction = w0×x0 + w1×x1 + b. “Linear” refers to the parameterised combination, not a claim that the game itself behaves linearly.

Let x0 be elixir advantage divided by ten and x1 be tower-HP advantage divided by three thousand. These are invented scales for the lesson, not the repository's exact observation contract.

```python
import numpy as np
X=np.array([[0.2,0.5],[-0.1,0.0]])
w=np.array([2.0,1.0])
b=0.1
print(np.round(X@w+b,3).tolist())
```

**Output:** `[1.0, -0.1]`.

An unrestricted prediction can be negative or exceed one. That is acceptable for some numerical targets, but not for a probability. State the target's meaning and units before choosing a model.

## 2. Fit by reducing squared error

Use mean squared error from F01. For residuals r = prediction - target, the weight gradient is 2×X.T@r/n, and the bias gradient is 2×mean(r). The transpose aligns features with residual contributions.

```python
import numpy as np
X=np.array([[1.0],[2.0]])
y=np.array([2.0,4.0])
w=np.zeros(1)
b=0.0
r=X@w+b-y
dw=2*X.T@r/len(y)
db=2*r.mean()
print(dw.tolist(),float(db))
```

**Output:** `[-10.0] -6.0`.

This extends the chain-rule gradient from F03. Every feature gets a derivative, while the bias receives a contribution of one per example. Compute both gradients from the same residuals before updating either parameter.

```python
import numpy as np
X=np.array([[-1.0],[0.0],[1.0]])
y=np.array([-1.0,1.0,3.0])
w=np.zeros(1)
b=0.0
for _ in range(200):
    r=X@w+b-y
    dw=2*X.T@r/len(y)
    db=2*r.mean()
    w-=0.1*dw
    b-=0.1*db
print(np.round(w,3).tolist(),round(float(b),3))
```

**Output:** `[2.0] 1.0`.

The known toy relationship is y=2x+1. Check the learned rule on a new input rather than reporting only training loss. In real data, noise and imperfect features usually prevent exact recovery.

## 3. Classification predicts a category

**Classification** predicts membership in categories. **Binary classification** has two categories, such as decisive win and decisive loss. Encode win as one and loss as zero when fitting an outcome model.

Unknown outcomes are not zeros. Remove them from the labelled outcome data and report their count. Our decisive setup also separates draws. Otherwise the model can learn that missing observations mean “loss,” which is an error in the dataset rather than a game relationship.

**Logistic regression** combines a linear score with a function that converts it to a probability. Despite the name, it is commonly used for classification.

The unrestricted score is called a **logit**. A probability and a logit are different representations. A logit of zero corresponds to probability one half, not zero.

## 4. Sigmoid converts a score to probability

The **sigmoid** function is 1/(1+exp(-z)). Exp is the exponential function. The sigmoid maps real scores into the interval from zero to one.

```python
import numpy as np
z=np.array([-2.0,0.0,2.0])
p=1/(1+np.exp(-z))
print(np.round(p,3).tolist())
```

**Output:** `[0.119, 0.5, 0.881]`.

Larger logits mean larger predicted probabilities. A logit can change substantially near an extreme while the probability changes little. The relationship is curved, which is why subtracting probabilities is different from subtracting logits.

Very negative z can overflow exp(-z). A **numerically stable** implementation avoids unnecessarily huge intermediate values. For nonnegative z use the formula above; for negative z use exp(z)/(1+exp(z)).

```python
import numpy as np
z=np.array([-1000.0,0.0,1000.0])
p=np.empty_like(z)
positive=z>=0
p[positive]=1/(1+np.exp(-z[positive]))
e=np.exp(z[~positive])
p[~positive]=e/(1+e)
print(p.tolist())
```

**Output:** `[0.0, 0.5, 1.0]`.

The boolean mask selects which elements use each branch. The tilde operator reverses a NumPy boolean mask. At extreme finite scores, floating-point rounding can produce exactly zero or one even though the mathematical sigmoid is strictly between them.

## 5. Log-loss scores probabilities

**Binary log-loss**, also called binary cross-entropy, is the average of -[y log(p)+(1-y) log(1-p)]. The natural logarithm is np.log. A confident wrong answer receives a large penalty.

```python
import numpy as np
y=np.array([1.0,0.0])
p=np.array([0.8,0.2])
loss=-np.mean(y*np.log(p)+(1-y)*np.log(1-p))
print(round(float(loss),3))
```

**Output:** `0.223`.

When y=1, only -log(p) remains. When y=0, only -log(1-p) remains. This explains the formula without requiring memorisation of both terms.

For a simple probability-based implementation, **clip** probabilities into [epsilon,1-epsilon] before taking logs. Epsilon is a small positive value such as 1e-12. Clipping avoids log(0), though robust training libraries often calculate the loss directly from logits.

A probability of 0.51 and one of 0.99 can produce the same class decision but different log-loss. F05 explores why probability quality requires more than accuracy.

## 6. Logistic gradients are compact

For a batch, logits = X@w+b and p=sigmoid(logits). The gradient of mean binary log-loss with respect to weights is X.T@(p-y)/n. The bias gradient is mean(p-y).

Notice there is no factor two. That factor belonged to squared error. Combining the sigmoid derivative with the log-loss derivative simplifies to p-y; this is a chain-rule result, not permission to reuse every gradient for every loss.

```python
import numpy as np
X=np.array([[-1.0],[1.0]])
y=np.array([0.0,1.0])
p=np.array([0.5,0.5])
dw=X.T@(p-y)/len(y)
print(dw.tolist(),float((p-y).mean()))
```

**Output:** `[-0.5] 0.0`.

Subtracting the negative weight gradient increases the weight. That makes positive inputs more likely to receive label one and negative inputs less likely. The direction matches the toy labels.

For our tiny exercise, use a modest fixed learning rate and a few hundred iterations. Do not run an unbounded loop until perfect accuracy. Some data are not separable, and even separable data can drive logistic weights larger without a finite unregularised optimum.

## 7. Features and decision thresholds

A **decision threshold** turns a probability into a class. With threshold 0.5, probabilities at least one half become predicted wins. The threshold is a reporting choice, not part of the sigmoid formula.

```python
import numpy as np
probabilities=np.array([0.3,0.5,0.8])
print((probabilities>=0.5).astype(int).tolist())
```

**Output:** `[0, 1, 1]`.

The boundary convention matters for exactly 0.5. Our exercises include equality in the positive class. A different application might choose a different threshold based on error costs, but it should be declared before measuring a final test set.

Feature scaling also affects training. Large HP values can create much larger gradient contributions than elixir values. Choose scales from training data or explicit domain units, then apply the same transformation to validation and test data. F06 explains why fitting preprocessing on future data leaks information.

## 8. Evaluate without telling the model the answers

Fit parameters on training examples, then use the returned w and b to predict separate examples. Do not refit on the evaluation labels. Compare with a simple baseline trained under the same rules.

A low loss on invented data proves the implementation can learn that invented relationship. It does not prove that elixir and HP are sufficient to predict live wins. Card cycle, deployment positions, latency, opponent strategy, and observation quality may matter.

Outcome labels derived from complete matches can also reflect events after the prediction time. That is acceptable as a target if the inputs use only information available at prediction time. It becomes leakage if later information enters the input features.

For each experiment, report feature definitions, split unit, target cleaning, training settings, and evaluation metric. These details make a small baseline interpretable and reproducible.

## Common mistakes

- Calling raw linear scores probabilities.
- Using squared-error gradients with log-loss.
- Including unknown match outcomes as label zero.
- Letting huge exponentials overflow unnecessarily.
- Choosing a threshold after looking at final test performance.
