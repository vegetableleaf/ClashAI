## Why this matters for ClashBot

ClashBot repeatedly asks small questions: can a card be afforded, how much elixir remains, and which card enters a hand after a play? Rewriting the same logic everywhere makes mistakes harder to find. Functions give those operations names and clear inputs and outputs.

`scratchpad/gauntlet/L74/crapi/crapi.py` contains functions supporting recorded battle information. We will inspect only a tiny time-formatting function and the opening of a record-writing function. We will not import or execute the operational program to learn basic syntax.

Small functions also make simulator and learning code easier to test. Before trusting a full Icebow match in RoyaleSim, crforge, or the live phone-emulator workflow, you should be able to test individual transformations on simple known inputs.

## 1. Define a reusable operation

A **function** is a named block of code that can be called with inputs and can produce a result. The word `def` begins a function definition. Parentheses contain its input names, a colon ends the header, and indentation marks the body.

```python
def double_elixir(amount):
    return amount * 2

print(double_elixir(3))
```

It prints `6`. The definition creates the function but does not run its body immediately. The later call supplies three, executes the body, and returns six to the surrounding `print` call.

A **parameter** is a name in the definition, such as `amount`. An **argument** is a value supplied at a call, such as `3`. You saw command arguments in Bash; Python function arguments serve a similar purpose of providing information to an operation.

## 2. Return provides a value

The `return` statement sends a result back to the caller and ends that function call. **Caller** means the code requesting the function's execution. A returned value can be assigned, combined in arithmetic, or passed to another function.

```python
def remaining_elixir(elixir, cost):
    return elixir - cost

left = remaining_elixir(10, 6)
print(left + 1)
```

It prints `5`. The function returns four, then the caller adds one. This demonstrates why returning is different from printing: returned values remain usable in the surrounding computation.

```python
def announce(card):
    print(card)

result = announce("X-Bow")
print(result)
```

It prints `X-Bow` and then `None`. **None** is Python's value representing no result or absence. A function reaching its end without an explicit returned value returns `None`. Printing a card does not also return that string.

For exercise functions, follow the requested contract. A **contract** specifies expected inputs, output, and relevant behavior. If the contract says return a number, printing that number is not sufficient. Tests inspect the value returned by a call.

## 3. Use several parameters clearly

Parameters let one implementation handle many situations. Put changing information in parameters instead of hiding a single fixed example inside the function.

```python
def damage_left(hp, damage):
    return max(0, hp - damage)

print(damage_left(300, 100))
print(damage_left(300, 500))
```

It prints `200` and `0`. The same rule works for ordinary damage and overkill. These numbers are toy examples, not current card damage statistics. Boundary tests reveal whether the zero floor is implemented correctly.

Arguments supplied by position are matched to parameters in order. Swapping HP and damage can produce a wrong answer without a syntax error. **Keyword arguments** name the parameters explicitly, as in `damage_left(hp=300, damage=100)`. You already saw this style in `open(..., encoding="utf-8")` in B03.

## 4. Defaults express a usual choice

A **default argument value** is used when the caller omits that argument. Write it in the definition after an equals sign. Required parameters normally come before parameters with defaults.

```python
def regenerate(elixir, seconds, multiplier=1):
    return min(10, elixir + seconds * multiplier / 2.8)

print(regenerate(3, 2.8))
print(regenerate(3, 2.8, 2))
```

It prints `4.0` and `5.0`. The first call uses the default 1x multiplier. The second explicitly requests 2x. The cap still applies in both cases. This retains B02's simplified continuous regeneration model.

Prefer simple immutable defaults such as numbers or `None`. A mutable list used as a default can retain changes between calls because the default object is created once when the definition executes. For beginner functions, take the list as a required parameter instead of using an empty list default.

## 5. Document the contract

A **docstring** is a documentation string placed first in a function body. Triple quotes allow it to span lines. A good docstring explains meaning and assumptions, not merely repeats the function name.

```python
def can_pay(elixir, cost):
    """Return whether available elixir covers the full cost."""
    return elixir >= cost

print(can_pay(6, 6))
```

It prints `True`. The documentation tells a reader that equality is affordable and that the result is a boolean. For a longer simulation function, also document units, update order, and whether input collections are changed.

Documentation is not enforcement. If the body used `>` instead of `>=`, the docstring would still sound correct while the implementation was wrong. Tests should include the exact-cost boundary to check that the code matches its stated contract.

## 6. Names have scope

**Scope** is the region where a name can be used to refer to a particular binding. Parameters and names assigned inside a function are ordinarily **local** to that call. Names assigned outside functions at the file level are commonly called **global** names.

```python
elixir = 10

def spend(amount):
    elixir = amount - 6
    return elixir

print(spend(8))
print(elixir)
```

It prints `2` then `10`. The local name inside `spend` is separate from the outer name. Reassigning it does not update the outer binding. Passing inputs and returning outputs makes these relationships easier to follow.

Mutable objects need special care. If a function receives a list and changes an element, the caller can observe that change even though the parameter name is local. B03's aliasing rule still applies: two names can refer to the same list.

## 7. Affordability from card names

Now combine dictionaries with functions. Our teaching mapping supplies illustrative fixed costs for the named cards. An unknown card should be rejected explicitly rather than treated as free.

```python
def can_afford(card, elixir):
    costs = {"X-Bow": 6, "Tesla": 4, "Skeletons": 1}
    if card not in costs:
        return False
    return elixir >= costs[card]

print(can_afford("Tesla", 4))
print(can_afford("Unknown", 10))
```

It prints `True` then `False`. `not in` is the negative membership test: it asks whether the name is absent. The early return handles that case before the dictionary lookup. This prevents an invalid name from being mistaken for an affordable option.

An **early return** ends a function before later statements. After returning `False`, Python does not continue into the lookup. Early returns can make exceptional or simple cases easier to read, provided the contract remains clear.

## 8. Model a four-card hand cycle

Use two ordered lists: `hand` contains four visible cards and `queue` contains four waiting cards. Playing slot `i` removes the front queued card into that slot and appends the played card to the queue's end. This is a simplified ordinary eight-card cycle, excluding special game mechanics.

We will return new lists instead of changing the caller's lists. B03 taught slicing as a shallow copy, and card names are immutable strings, so a shallow copy is enough here.

```python
def cycle_hand(hand, queue, slot):
    new_hand = hand[:]
    new_queue = queue[:]
    played = new_hand[slot]
    new_hand[slot] = new_queue.pop(0)
    new_queue.append(played)
    return new_hand, new_queue
```

This definition prints nothing. It returns a **pair**, here a two-element tuple containing the two new lists. Writing values separated by a comma in `return` constructs that tuple.

**Unpacking** assigns each element of a sequence to a corresponding name. It lets the caller receive both results:

```python
hand = ["X-Bow", "Tesla", "Ice Wizard", "Knight"]
queue = ["Skeletons", "Tornado", "Rocket", "The Log"]
next_hand, next_queue = cycle_hand(hand, queue, 0)
print(next_hand[0])
print(next_queue[-1])
print(hand[0])
```

After the preceding definition, it prints `Skeletons`, `X-Bow`, and `X-Bow`. The new hand gained Skeletons, the new queue ends with the played X-Bow, and the original hand remains unchanged. The contract assumes a valid slot and two four-card lists; broader input validation is a later topic.

## Test the contract, not just one example

For affordability, test below cost, exactly cost, above cost, and an unknown name. For regeneration, test the default multiplier, an explicit multiplier, zero seconds, and the cap. For cycling, test a different slot and verify the input lists remain unchanged.

A function can appear correct for one example by returning a fixed answer. Several carefully chosen inputs reveal whether it actually implements the rule. This is the foundation of meaningful tests, which B12 develops in detail.

## Common mistakes

- Printing when the contract asks for a returned value.
- Calling a function before its definition has executed.
- Confusing local reassignment with mutation of a passed list.
- Using a mutable default list without understanding its lifetime.
- Updating the hand but forgetting the queue.
