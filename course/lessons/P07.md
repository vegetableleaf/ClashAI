## Why this matters for ClashBot

Project 4 introduced a deterministic mini simulator. This project adds learning around that idea: reset a match, choose actions, collect outcomes, update a policy and evaluate fresh episodes. The interface is deliberately small enough to inspect completely.

The real trainer in `pipeline/rl_royale.py` includes many more decision heads and production safeguards. Our project retains the essential PPO probability ratio, clipping and value target. It is a complete training experiment in a reduced game, not a replacement trainer for RoyaleSim or crforge.

Interactive exercises run independently. Each milestone therefore supplies the earlier working components it needs. You can complete this project even if your P04 code exists only in the lesson editor. After the milestones, the write-up explains how the same environment interface would wrap your longer lane simulator.

## The game and the acceptance criteria

Our **environment contract** defines reset, observation, legal actions and step outputs. We use a two-tick lane duel. The scripted opponent destroys our tower at the end of tick two unless we defeat it first. The learner starts with either zero or one elixir, selected deterministically from a seed.

Action zero waits and gains one elixir, capped at two. Action one fires a toy siege shot, costs one elixir and defeats the one-HP opponent. An unaffordable shot is illegal. This is explicitly scaled teaching arithmetic: it is not the real six-elixir X-Bow cost, and it does not model deployment delay.

A terminal win pays +1, a terminal loss pays -1, and an unfinished step pays zero. The episode has at most two transitions. The opponent is scripted because its attack time never adapts. A successful learner must wait when empty and shoot before the deadline when able.

The finished experiment must preserve input states, mask illegal actions, collect fresh on-policy batches, retain fixed old log probabilities across PPO epochs, train a value estimate and evaluate unused environment seeds. It must also report a confidence interval and the limits of the toy. All training stays in memory on one CPU thread.

## Milestone 1 — wrap the game as an environment

The first exercise implements `reset(seed)` and `step(state, action)`. Reset returns a fresh dictionary. Step returns three items: the next state, reward and a Boolean terminal flag. These are enough for a collector to run until the match ends.

```python
state = {"elixir": 0, "tick": 0, "enemy_hp": 1}
state = {"elixir": 1, "tick": state["tick"] + 1, "enemy_hp": 1}
print(state["elixir"], state["tick"])
```

It prints `1 1`. This shows the first wait by hand. A shot from this state ends the match with a win at tick two. Waiting again instead lets the scripted opponent win.

Reject an action after termination. Otherwise a collector could keep adding rewards to a finished episode. Reject unavailable shots rather than silently rewarding them. Check input-state immutability with a before/after dictionary comparison.

The observation is a two-number tensor: elixir divided by two and remaining ticks divided by two. **Scaling** keeps these inputs in a small comparable range. The state retains exact integer rules; the observation is merely the representation passed to the neural network.

## Milestone 2 — turn rewards into targets

Use gamma one for this short finite game. That makes the return from every decision in a completed winning episode +1 and every decision in a losing episode -1. The choice is stated rather than inherited accidentally from another experiment.

```python
rewards = [0, 1]
running = 0.0
targets = []
for reward in reversed(rewards):
    running = reward + running
    targets.append(running)
print(list(reversed(targets)))
```

It prints `[1.0, 1.0]`. Restore chronological order before pairing targets with observations. Reversing only the rewards or only the targets would assign credit to the wrong rows.

A **critic** is the value-prediction model used as a baseline. Our critic is a linear layer with two inputs and one output. It is small because the game is small. The policy is another linear layer with two outputs, one logit per action.

Keep terminal boundaries separate during collection. The collector computes returns one episode at a time and then appends them to the training batch. This avoids a backwards accumulator leaking from one duel into the previous one.

## Milestone 3 — implement the clipped loss

Use the H04 objective. Calculate ratio = exp(new_logp - old_logp), multiply by detached advantage, compare with the clipped-ratio product, choose the minimum and negate its mean.

```python
import torch
ratio = torch.tensor([1.5, 0.5])
advantage = torch.tensor([1.0, -1.0])
objective = torch.minimum(ratio * advantage,
                          ratio.clamp(0.8, 1.2) * advantage)
print(round((-objective.mean()).item(), 2))
```

It prints `-0.2`. The positive sample contributes -1.2 to loss and the negative sample contributes +0.8. Averaging gives -0.2.

The **value loss** is mean squared error between critic predictions and observed return targets. The combined loss is policy loss plus 0.5 times value loss. We omit entropy bonuses and KL stopping in this small pedagogical trainer; the implementation should not be represented as the full production configuration.

We also omit advantage normalization to keep the sign and scale directly traceable. These choices are controlled simplifications. Record them in the write-up so another learner can reproduce the experiment.

## Milestone 4 — collect and train PPO

The supplied scaffold defines observations and masked action distributions. A **mask** suppresses unavailable actions before sampling. At zero elixir, the shot logit becomes a large negative value so its probability is effectively zero.

```python
import torch
logits = torch.tensor([0.0, -1e9])
dist = torch.distributions.Categorical(logits=logits)
print(dist.probs.tolist())
```

It prints `[1.0, 0.0]`. Use the same mask when recomputing training probabilities. A mask mismatch breaks the ratio even if the network weights have not changed.

Train for 24 updates, each collecting 24 complete episodes. Each update then performs three full-batch PPO epochs with Adam learning rate 0.04. Initialize policy weights and biases to zero, giving a uniform distribution wherever both actions are legal. Set the PyTorch seed inside training.

Collection runs without gradient recording. Store observations, sampled actions and their old log probabilities. After collection, compute the critic baseline once and detach the resulting advantages. During all three epochs, leave old log probabilities and targets fixed.

Clear gradients, backpropagate the combined loss and step the optimizer. Fresh episodes are collected only after these epochs complete. This is ordinary synchronous PPO. There are no actors running concurrently and no stale-data correction in this project.

## Milestone 5 — evaluate on held-out seeds

A **held-out evaluation** uses episodes not used for training. Training uses environment seeds from zero through 575. Evaluation uses a separate range beginning at 10,000. Keep the action-sampling seed separate as well.

Evaluate by sampling from the learned policy, matching the declared training action-selection rule. A greedy evaluation would answer a different question. It is allowed as an additional diagnostic only if labelled separately.

The initial uniform policy provides a meaningful baseline. With starting elixir one, it can shoot immediately or after one wait, giving win probability three quarters. With starting elixir zero, it must wait first and then wins with probability one half. The exact mixture depends on the seeded starts; the expected balanced-mixture baseline is five eighths.

```python
baseline = (0.75 + 0.5) / 2
print(baseline)
```

It prints `0.625`. The learned sampled policy should substantially exceed this baseline and beat the scripted opponent in most held-out episodes. The tests check performance on hundreds of tiny games, not a hard-coded trained parameter vector.

Compute a Wilson interval for the observed win count. Even an all-win evaluation has a lower bound below one. Finite evidence never establishes that all future episodes must be won.

## Milestone 6 — produce a reviewable result

Return a report dictionary containing wins, losses, unknown, rate, interval and a limitation statement. In this deterministic toy, every completed evaluation receives an outcome, so unknown is zero. Keep the field to preserve the reporting discipline used for real logs.

A **baseline comparison** should name the initial uniform policy, the held-out seeds and the sampled decoding rule. Compare fresh evaluations using the same environment seed set. Training on those evaluation outcomes and then reporting the same set as untouched would invalidate the held-out claim.

The final exercise assembles the report from supplied counts rather than rerunning training. That keeps the milestone focused on interpretation and avoids unnecessary repeated computation.

Write approximately 250 to 400 words in the course notes area or your own draft. Explain the game, observation, legal-action mask, reward, discount, network sizes, optimizer, update count and evaluation protocol. State the actual measured count and Wilson interval from your run.

Explain why the result demonstrates a working PPO learning loop. Then name at least three missing elements before it could inform live ClashBot performance: full card cycling, unit movement, placement, realistic opponents, observation gaps or emulator latency are appropriate examples.

## Common mistakes

- Using the real X-Bow cost in the deliberately scaled one-elixir toy.
- Recomputing old log probabilities after a PPO step.
- Forgetting to apply the legality mask during training.
- Testing on the same environment seeds used for collection.
- Claiming toy victories demonstrate live emulator readiness.
