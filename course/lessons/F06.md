## Why this matters for ClashBot

A model can improve its training loss while becoming worse at predicting new opponents. If every observed result influences the next choice, an apparently held-out score can gradually become part of training by human decision. ClashBot needs explicit separation between fitting, selection, and final evidence.

## 1. Overfitting is a generalisation failure

**Overfitting** occurs when a model or development procedure adapts to peculiarities of available examples that do not carry over to new ones. It is not simply “having a large model.” Even a small rule can overfit if selected from many candidates using the same small evaluation set.

```python
history=[
    {"step":1,"train":0.9,"validation":1.0},
    {"step":2,"train":0.6,"validation":0.8},
    {"step":3,"train":0.3,"validation":0.85},
]
print([r["train"] for r in history])
print([r["validation"] for r in history])
```

**Output:** `[0.9, 0.6, 0.3]` and `[1.0, 0.8, 0.85]`.

Training loss decreases throughout, while validation loss worsens after step two. This is consistent with overfitting, though noisy measurements can also fluctuate. Do not infer a detailed cause from three numbers alone.

The practical lesson is to preserve evaluation data and use a declared selection rule. “The last checkpoint is best” and “the lowest training loss is best” are both unsupported shortcuts.

## 2. Three roles for data

The **training set** fits model parameters. The **validation set** guides choices such as model size, learning rate, and which checkpoint to retain. The **test set** is reserved for final assessment after those choices are frozen.

A **hyperparameter** is a choice controlling the model or training procedure rather than a value fitted by the usual parameter updates. Learning rate and number of layers are examples. Selecting hyperparameters uses information too.

```python
roles={"training":"fit parameters",
       "validation":"choose a checkpoint",
       "test":"assess the frozen choice"}
print(roles["validation"])
```

**Output:** `choose a checkpoint`.

Validation is held out from direct parameter fitting, but it is still used for development decisions. Test data stops being final evidence if you repeatedly inspect it and revise the model to improve its score.

A **sealed block** is data intentionally withheld from inspection until a specified assessment. “Sealed” describes the evaluation procedure. Reading the block early and promising not to train on it does not undo the information gained.

## 3. Split matches, not neighbouring frames

ClashBot observations from one match share players, decks, and surrounding states. Adjacent frames may be nearly identical. Randomly splitting rows can put those related observations on both sides of an evaluation boundary.

A **group split** assigns all records from one group to the same partition. Here a match ID is a natural group. Other tasks may need grouping by player, collection period, or replay source.

```python
rows=[{"match":"a","tick":1},{"match":"a","tick":2},
      {"match":"b","tick":1}]
train_ids={"a"}
train=[r for r in rows if r["match"] in train_ids]
print(len(train),{r["match"] for r in train})
```

**Output:** `2 {'a'}`.

Both rows from match a stay together. Grouping does not guarantee independence across every dimension, but it removes a clear leakage route.

The exercise takes explicit sets of IDs for training, validation, and test. Reject overlapping ID sets. Reject any row whose match has no assignment. Silent dropping would make sample counts hard to audit.

## 4. Time changes the question

A **chronological split** trains on earlier data and evaluates on later data. This can better reflect predicting future live opponents than randomly mixing all dates. It also makes changes in game versions or populations visible.

**Distribution shift** means the relationship or input distribution changes between data sources or periods. A model trained on replay data can face different decks, timing, or observation errors in live emulator play.

A chronological split does not solve every problem. If you repeatedly tune against the same later period, it becomes validation. Keep a separate final period if the intended claim requires untouched future-like evidence.

Document the split boundary and group assignment before fitting. The exercises use explicit toy IDs so you can inspect exactly where every row goes. Real experiments need the same clarity at a larger scale.

## 5. Preprocessing also learns

**Preprocessing** transforms raw features before modelling. **Standardisation** subtracts a mean and divides by a standard deviation. Those quantities are estimated values, so fit them on training data only.

```python
import numpy as np
train=np.array([[1.0,10.0],[3.0,10.0]])
mean=train.mean(axis=0)
scale=train.std(axis=0)
scale=np.where(scale==0,1.0,scale)
held_out=np.array([[5.0,10.0]])
print(((held_out-mean)/scale).tolist())
```

**Output:** `[[3.0, 0.0]]`.

The constant second feature has standard deviation zero. Replacing that scale with one preserves finite values without pretending the feature varied. NumPy's default standard deviation here uses the population denominator; apply the same definition consistently.

If you recompute the mean using held-out features, you have allowed evaluation data to influence the transformation. Even without using labels, that changes the procedure being evaluated.

Store the training mean and scale with the selected model. Applying new statistics at deployment would change the model's input meaning. A checkpoint should preserve more than a bare list of weights when preprocessing is part of prediction.

## 6. Choose the direction of improvement

A **checkpoint** saves a model state at a particular training point. A **selection metric** determines which saved state is preferred. Lower NLL is better; higher accuracy is better. The comparison operator must match that direction.

```python
history=[{"step":10,"val_nll":0.8},
         {"step":20,"val_nll":0.6},
         {"step":30,"val_nll":0.7}]
best=min(history,key=lambda r:r["val_nll"])
print(best["step"])
```

**Output:** `20`.

Use validation values, not training values or test values. Decide how ties are resolved. Our exercise keeps the earliest record when values tie; Python min returns the first minimum encountered.

The history should include enough metadata to associate a score with the correct model. A result from a different engine build, data split, or representation may not be a valid comparison even if the metric has the same name.

## 7. Early stopping

**Early stopping** ends training after a declared period without validation improvement. **Patience** is the number of consecutive evaluations tolerated without an improvement. It counts evaluations, not necessarily individual gradient updates.

Our rule defines improvement as a strictly smaller loss. With patience two, stop at the second consecutive non-improving evaluation. A tie is non-improvement. Always retain the best checkpoint, which may occur before the stopping point.

```python
losses=[0.9,0.7,0.71,0.72,0.6]
best=float("inf")
bad=0
stop=None
for index,value in enumerate(losses):
    if value<best:
        best,bad=value,0
    else:
        bad+=1
    if bad>=2:
        stop=index
        break
print(stop,best)
```

**Output:** `3 0.7`.

The later 0.6 is not inspected because training would already have stopped. Evaluating the whole list first and then inventing a stopping point would violate this sequential rule.

Early stopping does not guarantee the best possible future result. It is a predeclared tradeoff between continued computation and evidence of improvement. Report the evaluation frequency, patience, and improvement definition.

## 8. Regularisation changes the objective

**Regularisation** discourages certain model solutions to improve generalisation. **L2 regularisation** adds a penalty proportional to the sum of squared weights. It encourages smaller weights, although smaller weights alone do not prove better predictions.

```python
import numpy as np
weights=np.array([3.0,4.0])
data_loss=0.5
strength=0.01
objective=data_loss+strength*np.sum(weights**2)
print(float(objective))
```

**Output:** `0.75`.

The regularisation strength is a hyperparameter selected using validation, not final test evidence. In this convention the penalty gradient is 2×strength×weights. Other software may define the coefficient differently, so read the exact formula.

Feature scaling matters: a large feature can be represented using a small weight. Regularisation and preprocessing therefore interact. Compare models under a consistent transformation.

## 9. Freeze choices before final assessment

Before reading final results, freeze the selected checkpoint, preprocessing, metric definitions, outcome cleaning, and comparison procedure. Then evaluate once for the stated question and report limitations.

Unknown outcomes remain unknown. For a decisive outcome task, train and evaluate only explicit WIN and LOSS labels, while reporting DRAW and UNKNOWN counts separately. A changing proportion of missing results can affect how representative the labelled data is.

If a final result disappoints, it can motivate a new development cycle. But the old test result has now influenced choices; do not keep calling it untouched final evidence for the revised system. Use a new appropriately held-out assessment.

## Common mistakes

- Splitting related frames across partitions.
- Fitting normalisation on all available data.
- Selecting by training loss or final test score.
- Keeping the last checkpoint instead of the selected one.
- Counting patience in updates when the rule specifies evaluations.
