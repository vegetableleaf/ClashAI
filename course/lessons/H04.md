# H04 · PPO: the algorithm the project trains with

**Time:** about 6 hours · **You will be able to:** calculate clipped PPO losses, distinguish KL stopping from a penalty, and identify stale rollout probabilities.

## Why this matters for ClashBot

A policy-gradient update can change ClashBot's decisions so much that the data collected a moment ago no longer describes the updated policy. Reusing a batch makes training cheaper, but careless reuse can amplify that mismatch.

`pipeline/rl_royale.py` implements **proximal policy optimization**, or PPO. Proximal means nearby: the objective discourages some excessively large probability changes relative to the policy that collected the data. It does not guarantee that every action probability stays within a hard interval.

This file also supports a decoupled variant for data collected by older actors. That matters when crforge simulations and neural-network updates overlap. We will first establish the ordinary ratio, then identify which additional policy is needed for stale data. Everything in the exercises is numerical or a tiny tensor operation.

## 1. Compare the same action under two policies

The **behaviour policy** is the policy that generated the stored action. Save its log probability when collecting the rollout. The **current policy** is the policy being updated. Recompute the log probability of exactly the same stored action under that policy.

The **probability ratio** is current probability divided by behaviour probability. Using logs, compute exp(log_current - log_old). This is numerically convenient and works with sums of conditional log probabilities.

```python
import math
old_probability = 0.25
new_probability = 0.30
ratio = math.exp(math.log(new_probability) - math.log(old_probability))
print(round(ratio, 2))
```

It prints `1.2`. A ratio greater than one means the action became more likely. It does not mean that the action is good. Its advantage supplies that part of the learning signal.

Before the first update on freshly collected data, recomputed ratios should be very close to one. If they are not, suspect mismatched action masks, temperatures, network modes or stored inputs. Do not explain a large initial discrepancy as normal learning: no learning has happened yet.

## 2. Clip the objective, not the action

PPO uses the smaller of ratio * advantage and clipped_ratio * advantage. Clipping restricts a number to an interval; with epsilon 0.2 the interval is [0.8, 1.2]. Negate the selected quantity to obtain a loss for gradient descent.

```python
ratio = 1.5
advantage = 2.0
clipped = min(1.2, max(0.8, ratio))
objective = min(ratio * advantage, clipped * advantage)
print(round(objective, 2), round(-objective, 2))
```

It prints `2.4 -2.4`. The unclipped objective would be 3.0, but the improvement is capped. For this positive advantage, making the action still more likely does not improve this sample's clipped objective.

Now consider negative advantage. If an undesirable action becomes much less likely, the improvement is also capped. If it instead becomes more likely, PPO still penalizes that damaging movement. This is why choosing the minimum after multiplying by advantage matters.

```python
ratio = 1.5
advantage = -2.0
clipped = min(1.2, max(0.8, ratio))
print(min(ratio * advantage, clipped * advantage))
```

It prints `-3.0`. Blindly using clipped_ratio * advantage would hide some harmful change. Test both signs and both sides of the clipping interval.

The objective is only one component of optimization. Shared parameters can change other action probabilities even when one sample's objective is flat. PPO clipping is not a strict guarantee that all ratios remain in the interval.

## 3. Measure movement with KL and entropy

**Kullback-Leibler divergence**, or KL, measures the difference between probability distributions. For discrete distributions p and q, KL(p || q) is sum p * log(p/q). It is zero for identical distributions and generally differs when its arguments are reversed.

```python
import math
p = [0.5, 0.5]
q = [0.6, 0.4]
kl = sum(a * math.log(a / b) for a, b in zip(p, q))
print(round(kl, 4))
```

It prints `0.0204`. This is a full-distribution calculation for the toy example. Production estimates may aggregate several heads and weight samples. Always identify which distributions and aggregation rule a reported KL uses.

An **early stop** ends the remaining update steps when measured movement exceeds a limit. A **KL penalty** adds a weighted divergence to the loss. These are different mechanisms. A zero penalty coefficient does not disable a separately configured KL early stop.

**Entropy** measures a distribution's uncertainty: minus sum p log p. Uniform action probabilities have higher entropy than near-certain choices. An entropy bonus can encourage exploration, but a high-entropy policy may still perform poorly. It is a diagnostic or objective term, not a replacement for evaluation.

```python
import math
entropy = -sum(p * math.log(p) for p in [0.5, 0.5])
print(round(entropy, 4))
```

It prints `0.6931`. These calculations use natural logarithms, so the units are nats. No conversion is necessary for the exercises.

## 4. Reuse a batch without rewriting its history

An **epoch** is one pass through a collected training batch. A **minibatch** is a smaller subset used for one optimizer step. Several epochs can improve data efficiency, but the old log probabilities must remain those recorded during collection throughout those epochs.

If you overwrite old log probabilities after each step, every ratio resets near one and the clipping reference moves. The resulting algorithm no longer has the intended behaviour-policy anchor. Store old values as detached tensors and recompute only the current side.

```python
import torch
old_logp = torch.tensor([-0.7, -0.3]).detach()
new_logp = old_logp.clone().requires_grad_()
ratios = torch.exp(new_logp - old_logp)
print(ratios.tolist())
```

It prints `[1.0, 1.0]`. This is the initial identity check. During training, `new_logp` changes because the model changes; `old_logp` remains fixed.

The project's configured `kl_stop_prev` of 0.02 is a particular early-stop setting, not a universal theorem about PPO. The trainer checks the summed head divergences before taking the next step. The configuration and anchor policy determine what that limit means.

## 5. Stale data needs a separate comparison

**Stale data** was collected by a policy older than the learner's chosen update reference. A **proximal policy** in decoupled PPO is that recent reference, distinct from both the behaviour policy and the current trainable policy.

The decoupled construction in the source uses two ratios. An **importance weight** compares the proximal policy with the behaviour policy and is capped. The PPO ratio compares the current policy with the proximal policy. Keeping their roles separate avoids treating an old actor as if it had just sampled from the learner.

```python
behaviour = 0.2
proximal = 0.3
current = 0.33
importance = min(2.0, proximal / behaviour)
ratio = current / proximal
print(round(importance, 2), round(ratio, 2))
```

It prints `1.5 1.1`. The current-to-behaviour ratio would be 1.65, but it is not either of these two quantities. Multiplying the weights without clipping recovers that overall ratio; the decoupled clipped objective treats the two sources of change separately.

Importance weighting does not make arbitrarily stale data harmless. If the behaviour policy almost never chose a useful action, there may be too few examples to correct reliably. Track policy versions and data age. H09 returns to these measurements when discussing actor and learner throughput.

## Practice plan

Work through positive and negative advantage cases before implementing the vectorized tensor version. A test at ratio one alone is not sufficient because most incorrect clipping formulas agree there.

The exercises then ask for KL and the decoupled scalar loss. Their probabilities are strictly positive, so no smoothing convention is needed. A real masked distribution needs explicit support handling; silently dividing by zero is not an acceptable extension.

Finally classify whether an update should stop from its head divergences. This is a pure function, not a command to interrupt a running trainer. Keep numerical policy checks distinct from operating the real system. The course is about understanding the mechanism, and the tiny examples give complete evidence for their calculations.

## Common mistakes

- Refreshing old log probabilities between PPO epochs.
- Clipping before considering the sign of advantage incorrectly.
- Treating the 0.02 stop as a KL penalty coefficient.
- Assuming clipping guarantees every action ratio stays bounded.
- Confusing current-to-behaviour and current-to-proximal ratios.
