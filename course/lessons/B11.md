## 1. Treat paths as structured values

`pathlib` supplies the **Path** class, which represents a filesystem path. A Path object can describe a location even when no file exists there. Constructing one does not create a file.

```python
from pathlib import Path

path = Path("course") / "syllabus.json"
print(path.name)
print(path.suffix)
print(path.exists())
```

It prints `syllabus.json`, `.json`, and `True` in this repository. The `/` operator joins path components when used with Path objects. `name` gives the final component, and `suffix` gives the filename extension. `exists()` asks the filesystem whether that location currently exists.

Prefer this to manually concatenating platform-specific separators. A Windows drive path and a repository-relative path still have different meanings, however. Path does not guess your intended working directory. The interactive runner uses the repository root, so `Path("course")` resolves relative to that root.

```python
from pathlib import Path

path = Path("course/syllabus.json")
print(path.parent.name)
print(path.is_file())
```

It prints `course` and `True`. `parent` refers to the containing directory. `is_file()` is more specific than `exists()`: a directory may exist without being a regular file. These distinctions make error messages more precise when a report receives the wrong input path.

## 2. Turn command-line text into options

A **command-line argument** is a piece of text supplied when launching a program. A **flag** is an argument naming an option, often beginning with `--`. `argparse` converts those strings into a structured object and can produce usage help.

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("--limit", type=int, default=5)
args = parser.parse_args(["--limit", "2"])
print(args.limit)
print(type(args.limit))
```

It prints `2` and `<class 'int'>`. Without `type=int`, the supplied value would remain text. Passing an explicit list to `parse_args` is useful in tests because it avoids depending on the actual process arguments. Calling `parse_args()` without that list reads the process command line.

A boolean switch can use `action="store_true"`. Its presence sets the attribute to True; absence leaves it False.

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("--no-fast-plays", action="store_true")
print(parser.parse_args([]).no_fast_plays)
print(parser.parse_args(["--no-fast-plays"]).no_fast_plays)
```

It prints `False` and `True`. Hyphens become underscores in the attribute name. This example only parses a flag familiar from bot commands. It does not connect the flag to live behaviour or alter any running process.

For P02, `--input` will identify the match log. Making it required forces the caller to name the source. The parser can reject missing arguments before the loader begins, which gives a clearer failure than trying to open an unspecified path.

## 3. Separate calendar time from elapsed time

The `datetime` module represents dates and times. A **timestamp** identifies a point on a timeline. A **timezone offset** states how a displayed local time differs from UTC, the common reference time used here.

```python
from datetime import datetime, timezone

stamp = datetime.fromisoformat("2026-10-29T23:30:00-04:00")
utc = stamp.astimezone(timezone.utc)
print(utc.date().isoformat())
```

It prints `2026-10-30`. The offset means the source clock is four hours behind UTC. Conversion crosses midnight, so grouping before conversion would produce a different date bucket.

An **aware datetime** includes timezone information. A **naive datetime** does not. Do not assume a naive timestamp is UTC merely because your program can parse it. The match log's `ts` values look like `20260925_015246`, which does not encode an offset. P02 will group by the source date and explicitly leave its timezone unspecified.

The `time` module also supports elapsed-time work. `time.monotonic()` provides a clock intended for measuring durations without depending on changes to the calendar clock. The absolute returned number has no useful calendar meaning; the difference between two readings does.

```python
import time

before = time.monotonic()
after = time.monotonic()
print(after >= before)
```

It prints `True`. This does not measure meaningful model speed; there is almost no work between the readings. A timing experiment needs a defined operation, repeated measurements, and a stated environment. The example simply demonstrates which clock property a duration calculation needs.

## 4. Count repeated values with Counter

`collections.Counter` is a dictionary-like class for counting items. It removes repetitive setup when the task is simply “how many times did each value appear?”

```python
from collections import Counter

counts = Counter(["WIN", "LOSS", "WIN"])
print(counts["WIN"])
print(counts["DRAW"])
print(dict(counts))
```

It prints `2`, `0`, and `{'WIN': 2, 'LOSS': 1}`. A missing item reads as zero. Converting to a plain dictionary preserves stored counts, but does not automatically insert every possible category. If a report must show DRAW and UNKNOWN even when zero, add them deliberately.

Counter can count observed opponent-card names, but you still control the unit being counted. Counting a raw list of sightings differs from counting each distinct card once per match. Use a set per match when the intended quantity is matches containing that observed card.

The class does not know which rows are dry runs or which labels are valid. Convenience tools reduce code, not responsibility for the report definition. Keep filtering and category meaning visible before applying the counter.

## 5. Fingerprint exact bytes

A **hash** is a fixed-size value calculated from input bytes. A **fingerprint** uses such a value to help identify exact content. `hashlib.sha256` calculates a SHA-256 digest. A **digest** is the resulting hash value, often displayed as hexadecimal text.

```python
import hashlib

a = hashlib.sha256(b"WIN\nLOSS").hexdigest()
b = hashlib.sha256(b"WIN\nLOSS\n").hexdigest()
print(len(a))
print(a == b)
```

It prints `64` and `False`. The final newline changes the bytes and therefore the fingerprint. The `b` prefix creates a bytes literal. To hash ordinary text, first call `.encode("utf-8")` so the byte representation is explicit.

In a training experiment, a file fingerprint can help distinguish the exact input or checkpoint used. A **checkpoint** is a saved model state that can be loaded later. Equal names are not enough to establish equal file contents. A matching digest is strong evidence of matching bytes, but it does not establish that those bytes describe a good model or a fair experiment.

Today's exercise hashes a tiny list of labels, not a model file. It fixes both the separator and the absence of a final newline. A reproducible fingerprint requires agreement on those exact details, not merely on what the text looks like when printed.

## 6. Run a small local process

A **process** is a running program managed by the operating system. `subprocess.run` starts another program and waits for it to finish. That program is often called a **child process** of the caller.

```python
import subprocess
import sys

result = subprocess.run(
    [sys.executable, "-B", "-c", "print(6 - 3)"],
    capture_output=True, text=True, timeout=5,
)
print(result.returncode)
print(result.stdout.strip())
```

It prints `0` and `3`. `sys.executable` selects the current Python interpreter. `-c` supplies the tiny Python program, and `-B` avoids writing bytecode cache files. `capture_output=True` stores output instead of displaying it immediately. `text=True` decodes it into strings.

**Standard output**, or stdout, is a program's ordinary output stream. **Standard error**, or stderr, is its diagnostic stream. A **return code** indicates process completion status; zero conventionally means success. A nonzero code can occur even when some normal output was produced, so checking only stdout is insufficient.

The timeout prevents the parent from waiting indefinitely. If exceeded, Python raises `subprocess.TimeoutExpired`. Passing a list of arguments avoids having a shell interpret one combined command string. This exercise launches only local arithmetic; it does not run an emulator command or start a training job.

## 7. Use logging for diagnostics

**Logging** records diagnostic messages with a level such as INFO, WARNING, or ERROR. Unlike ad hoc print statements, logging lets a program control which levels are shown and how messages are formatted.

```python
import logging

logging.basicConfig(level=logging.INFO, format="%(levelname)s: %(message)s")
logging.info("Loaded %s match rows", 3)
```

In a fresh Python process, it emits `INFO: Loaded 3 match rows` to stderr, not stdout. The format contains placeholders that logging fills with the level and message. INFO describes normal progress; WARNING indicates something worth attention; ERROR reports a failure condition.

Keeping report data on stdout and diagnostics on stderr helps another tool consume the report. A progress message should not silently become a row in a machine-readable output file. The course runner displays both streams, so an emitted log line may still appear in the exercise output panel.

## In the real project

The watcher `scratchpad/gauntlet/L74/liveops/stuck_watch2.py` ends with these exact lines:

```python
if __name__ == "__main__":
    ap = argparse.ArgumentParser(description=__doc__.split("\n")[0])
    ap.add_argument("--once", action="store_true", help="exit after the first alert (the old stuck_watch.sh behaviour)")
    ap.add_argument("--no-screenshot", action="store_true")
    ap.add_argument("--poll", type=float, default=30.0)
    sys.exit(run(ap.parse_args()))
```

This is source to inspect, not a command to run. Line 1 guards direct execution. Line 2 creates the parser using the first line of the module docstring. Line 3 defines a one-shot switch. Line 4 defines another boolean switch. Line 5 accepts a numeric polling interval. Line 6 parses process arguments, calls `run`, and uses its result as the process exit status.

The declaration prints nothing by itself. Executing the guarded path would enter operational watcher behaviour, which is outside these exercises. Recognising the argument flow is enough: text arguments become an options object, and that object is passed into the main operation. P02 uses the same pattern for a read-only report.

## Common mistakes

- Assuming constructing a Path creates a file.
- Forgetting `type=int` and doing arithmetic on argument text.
- Assigning UTC to a timestamp whose timezone was never recorded.
- Hashing different newline conventions while claiming identical input.
- Checking child output but ignoring its return code.
- Mixing diagnostic messages with machine-readable report output.
