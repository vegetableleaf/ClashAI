# G04 - Measuring human-likeness

**Time:** about 4 hours ? **You will be able to:** measure style differences, interpret discriminator AUC, and construct a human-versus-human control.

## Why this matters for ClashBot

A simulator opponent can be strong without behaving like the humans facing Icebow. It can also match some average human habits while defending X-Bows badly. The human-likeness scorecard in `scratchpad/gauntlet/L74/opp_model/humanlike/HUMANLIKE.md` measures several aspects separately.

**Human-likeness** here means agreement with a defined human reference population on specified measurements. It is not a claim about consciousness or a subjective impression. We need to say which humans, which observations, which features, and which comparison procedure.

The source contains several dated threshold versions and later controls. We will use it as an example of measurement design, not present its first historical threshold as a timeless rule. The exercises calculate small statistics locally and never launch a live bot or simulator job.

## 1. Summarise behaviour per match

A **style feature** is a numerical summary of behaviour, such as plays per minute, reaction delay, or fraction of placements in a region. Using one row per match helps keep the analysis unit aligned with independent game episodes.

```python
play_seconds = [10, 20, 40, 50]
duration_seconds = 60
plays_per_minute = len(play_seconds)/(duration_seconds/60)
gaps = [b-a for a,b in zip(play_seconds,play_seconds[1:])]
print(plays_per_minute)
print(gaps)
```

This prints `4.0` and `[10, 20, 10]`. The mean rate and the pattern of gaps capture different things. Two opponents can have the same total number of plays while one acts in bursts and another acts evenly.

Feature definitions must match across live and simulator records. If live reaction time begins at first screen sighting but simulator reaction time begins at the underlying event, an apparent style difference may include measurement delay.

A feature list is part of the measurement. Changing from nine to thirteen features changes what the aggregate score means. The source explicitly warns that older reports used different feature sets.

## 2. Put different units on a common scale

Raw differences cannot be averaged sensibly when one feature is seconds and another is a fraction. A **standardised difference** divides a mean difference by a measure of spread.

We use **Cohen's d** with sign defined as bot mean minus human mean, divided by a pooled sample standard deviation. A **sample variance** estimates spread using denominator n-1; NumPy requests it with `ddof=1`.

For group sizes nh and nb, pooled variance is the weighted average of sample variances with weights nh-1 and nb-1. Take its square root to obtain pooled standard deviation.

```python
import numpy as np
human = np.array([1.0, 2.0, 3.0])
bot = np.array([2.0, 3.0, 4.0])
pooled_variance = ((len(human)-1)*human.var(ddof=1)
                  +(len(bot)-1)*bot.var(ddof=1))/(len(human)+len(bot)-2)
d = (bot.mean()-human.mean())/np.sqrt(pooled_variance)
print(round(float(d), 3))
```

This prints `1.0`. The bot mean is one pooled standard deviation higher. Whether "higher" is desirable depends on the feature. Higher plays per minute is not inherently better or worse for imitation.

Cohen's d is not a probability. A value of 0.2 does not mean ?20% less human.? It expresses a mean separation relative to the groups' spread.

## 3. Handle zero spread explicitly

If a feature is constant in both populations, pooled spread is zero. If the constants are equal, our teaching convention returns d=0 because the means agree. If the constants differ, a finite standardised difference is undefined, so the exercise raises ValueError.

```python
human = [0, 0, 0]
bot = [0, 0, 0]
print(sum(human)/len(human) == sum(bot)/len(bot))
```

This prints `True`. It verifies equality of these constants but does not make division by zero legitimate. A production scorecard may drop an undefined feature according to a documented rule instead. Keep the convention explicit.

Do not silently add a large arbitrary denominator to make a difficult feature disappear. Conversely, dividing by a tiny spread can create a huge effect size for a small absolute change. Report the raw means and uncertainty beside standardised scores when interpreting unusual results.

## 4. Combine effects with RMS

The **root mean square**, abbreviated **RMS**, squares values, averages the squares, and takes the square root. Squaring prevents positive and negative differences from cancelling.

```python
import numpy as np
effects = np.array([0.3, -0.4])
print(round(float(np.sqrt(np.mean(effects**2))), 4))
print(round(float(effects.mean()), 4))
```

This prints `0.3536` and `-0.05`. The signed average looks small because the two deviations oppose each other. RMS records their magnitude.

RMS is still a summary. A small overall value can hide one important failing feature among many quiet ones. Report the largest absolute effects and inspect relevant tactical features separately, such as response to an X-Bow.

Adding many almost-duplicate features can also distort interpretation. Correlated measurements are not independent confirmations. Define the feature set before scoring models, and compare scores only under compatible definitions.

## 5. Train a discriminator as another instrument

A **discriminator** is a classifier trained to distinguish examples from two sources, here bot versus human behaviour. If it can reliably separate them on held-out matches, some difference exists in its input features.

The **area under the ROC curve**, or **AUC**, was introduced in F05. With larger scores meaning more likely bot, AUC is the probability that a randomly selected bot example receives a higher score than a randomly selected human example, with half credit for ties.

```python
human_scores = [0.2, 0.5]
bot_scores = [0.5, 0.8]
credit = 0
for bot in bot_scores:
    for human in human_scores:
        credit += (bot > human) + 0.5*(bot == human)
auc = credit/(len(bot_scores)*len(human_scores))
print(auc)
```

This prints `0.875`. Three pairs are correctly ranked and one ties. The exercise implements this pairwise definition, so no external classification package is needed.

An AUC near 0.5 means this discriminator did not separate these samples reliably. It does not prove identical distributions. A weak model, poor features, or too little data can also produce 0.5. AUC below 0.5 may mean the scoring direction is reversed.

A high AUC can reflect instrument differences rather than strategic behaviour. The source notes that simulator and live observations are not always recorded identically. A discriminator that detects logging conventions is measuring a real difference, but not necessarily the intended one.

## 6. Establish a human noise floor

A **human noise floor** is the variation seen when comparing human samples with other human samples under the same measurement procedure. Even samples from the same population rarely have exactly identical means.

Randomly split human matches into two groups, compute the style score, and repeat with different shuffles. This gives a **null distribution**, a reference distribution for scores when the two labels do not identify different sources.

```python
import numpy as np
values = np.array([1.0, 2.0, 3.0, 4.0])
rng = np.random.default_rng(5)
order = rng.permutation(len(values))
left = values[order[:2]]
right = values[order[2:]]
print(len(left), len(right))
print(sorted(left.tolist()+right.tolist()))
```

This prints `2 2` and `[1.0, 2.0, 3.0, 4.0]`. **Permutation** means a shuffled ordering without replacement. Each match is used once in each split, unlike bootstrap sampling with replacement from C05.

For a feature matrix, shuffle whole rows so correlated features from one match stay together. Shuffling each column independently destroys relationships and creates a different null experiment.

The approximate expression sqrt(2/n) appears in an early source table as a human reference scale. It is not a universal acceptance threshold. Feature distributions, sample sizes, weighting, and dependence matter. The exercise builds an empirical control rather than assuming one formula fits every feature set.

## 7. Validate the instrument with planted differences

A **positive control** introduces a known difference that the procedure should detect. For example, multiply a reaction-time feature by a large factor in one copy of the data. A **negative control** compares samples expected to agree, such as comparable human halves.

The source reports both human-half controls and planted bugs. A measurement that never fails may be insensitive. A measurement that frequently rejects comparable humans may be too strict for the available sample size or reference population.

Choose thresholds using the declared human controls before scoring candidate models. Adjusting a threshold after seeing which value makes a favourite model pass compromises the comparison.

Do not mistake a null distribution from random halves for a complete treatment of temporal drift. Today's humans can differ systematically from last week's humans. The later scorecard sections revisit recency weighting and newest-block controls precisely because the target population matters.

## 8. Keep uncertainty and sufficiency visible

A point estimate alone is not enough. Confidence intervals from C05 describe uncertainty under stated assumptions. A **sufficiency requirement** sets a minimum amount of evidence before a pass/fail claim is allowed.

A small sample can give AUC 0.5 by chance. A large sample can detect a tiny but practically unimportant mean difference. That is why a scorecard may combine effect-size limits, uncertainty bounds, and minimum match counts.

Unknown game outcomes are still unknown when a style report also includes win rates. Follow G01: exclude missing derived results from the win-rate denominator, count them separately, and keep draws explicit. Style measurements may have their own availability masks; an unknown outcome does not automatically erase every observed play.

## 9. Interpret the result as a collection of checks

The exercises compute one feature's standardised difference, RMS across features, pairwise AUC with ties, and a repeated human-half null. They do not train a production discriminator or certify an opponent.

For a useful report, name the human population, time window, feature set, match count, effect directions, RMS, discriminator evaluation split, and human control. If a source version changes, identify that version rather than mixing limits from one with scores from another.

Finally, connect back to G03. An opponent can have a small style distance and still be tactically ineffective. Another can be strategically strong but easily distinguishable from human play. ClashBot needs evidence about both properties because its learner will exploit the actual opponents it encounters, not the label attached to them.

## Common mistakes

- Interpreting Cohen's d as a probability or percentage.
- Averaging signed effects so opposite deviations cancel.
- Combining scores computed from different feature lists.
- Treating AUC 0.5 as proof of identical behaviour.
- Choosing thresholds after inspecting candidate scores.
- Shuffling individual features instead of whole match rows.
