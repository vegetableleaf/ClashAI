## 1. One neuron is a calculation

A **neuron** computes a weighted sum and usually transforms the result. Its **weights** say how strongly each input contributes. Its **bias** is an adjustable constant added after the sum. These are **parameters**, numbers changed during training. Input values are data, not parameters.

Take two teaching features: elixir divided by ten and own tower health divided by its starting health. Dividing puts both on a comparable scale. A value of 0.6 means six elixir only because we chose that definition. Changing the definition later would change what the weights mean.

```python
import numpy as np
x = np.array([0.6, 0.8])
w = np.array([2.0, -1.0])
b = 0.1
z = float(x @ w + b)
print(round(z, 2))
```

This prints `0.5`. The `@` operator is the dot product from F02: multiply corresponding entries and add them. The positive elixir contribution is 1.2; the health contribution is -0.8; the bias contributes 0.1. The sign of a learned weight is not a strategy rule. Correlated inputs can make an individual weight misleading.

## 2. Add an activation

An **activation function** transforms the weighted sum. The **rectified linear unit**, usually called **ReLU**, returns the input if it is positive and zero otherwise. It creates a bend in the graph. Without a nonlinear activation, stacking linear layers still produces one linear transformation.

```python
def relu(z):
    return max(0.0, z)

print(relu(-0.5), relu(0.5))
```

This prints `0.0 0.5`. The negative input is blocked. The positive input passes through unchanged. A neuron whose weighted sum is negative has zero ReLU slope at that input. This does not mean its weights are permanently useless; a different observation might activate it.

At exactly zero, ReLU has no unique mathematical derivative. We will use the conventional computational choice zero. That choice must appear in our tests. When comparing derivatives numerically, avoid points exactly at the bend.

## 3. A layer computes several neurons

A **layer** is a group of calculations applied together. A **hidden layer** is an intermediate representation between inputs and outputs. A **multilayer perceptron**, or **MLP**, is a network of linear layers separated by activations.

Our row-vector convention is input shape `(features,)` multiplied by weights shaped `(features, hidden)`. A **shape** is the tuple describing an array's dimensions. Write the dimensions down before writing the multiplication.

```python
import numpy as np
x = np.array([1.0, 2.0])
W = np.array([[1.0, -1.0], [0.5, 1.0]])
b = np.array([0.0, 0.0])
z = x @ W + b
h = np.maximum(z, 0.0)
print(z.tolist())
print(h.tolist())
```

This prints `[2.0, 1.0]` twice. Column zero of W defines the first neuron; column one defines the second. Both happen to be active. The function `np.maximum` compares each entry with zero.

A second weight vector can combine these hidden values into one score. The **forward pass** is the calculation from inputs through the layers to the output. Keep intermediate values: the backward calculation will need them.

```python
import numpy as np
h = np.array([2.0, 1.0])
v = np.array([0.5, -1.0])
prediction = float(h @ v)
print(prediction)
```

This prints `0.0`. Two positive hidden values can still produce a zero score because their output contributions cancel. Hidden units do not have to be individually interpretable as cards or tactics.

## 4. Define a loss before differentiating

A **loss function** measures the disagreement between prediction and target. For this lesson, use half the squared error: `loss = 0.5 * (prediction - target) ** 2`. The half simplifies the derivative. This is a teaching loss for a numerical score, not the project's complete training objective.

```python
prediction = 0.0
target = 1.0
error = prediction - target
loss = 0.5 * error ** 2
print(error, loss)
```

This prints `-1.0 0.5`. The derivative of the loss with respect to the prediction is the error, -1. Increasing the prediction a little should reduce the loss here. The sign agrees with the story: the prediction is below its target.

A target must come from an explicitly defined task. A human's next card is a classification label; a tower-health quantity is a numerical target. Calling every target a win probability would hide major differences between tasks.

## 5. Backpropagation follows the chain backwards

**Backpropagation** is an efficient application of the chain rule through a network. It computes how much each parameter influences the loss. It does not run the game backwards or undo an emulator action.

For our two-hidden-unit example, let the output weights be `[0.5, -1.0]`, hidden values `[2.0, 1.0]`, and target 1. The output error is -1. The output-weight gradient is error times hidden values: `[-2.0, -1.0]`. The hidden-value gradient is error times output weights: `[-0.5, 1.0]`.

Both hidden pre-activations were positive, so both ReLU slopes are one. The gradient before ReLU is unchanged. For each input weight, multiply that neuron's gradient by the input feeding it.

```python
import numpy as np
x = np.array([1.0, 2.0])
dz = np.array([-0.5, 1.0])
dW = np.outer(x, dz)
print(dW.tolist())
```

This prints `[[-0.5, 1.0], [-1.0, 2.0]]`. The **outer product** multiplies every entry of one vector by every entry of another, producing a matrix. Entry `dW[1, 0]` is -1 because input 2 multiplies gradient -0.5.

The bias gradient is simply `dz`: adding a bias changes the pre-activation one for one. If a hidden pre-activation were negative, its ReLU slope would be zero and its incoming weights would receive zero gradient for this example.

## 6. Update only after computing all gradients

A **learning rate** is the step size multiplying a gradient. Gradient descent subtracts that product. A positive gradient means increasing the parameter would locally increase the loss; subtracting it moves downhill.

```python
weight = 0.5
gradient = -2.0
learning_rate = 0.1
weight = weight - learning_rate * gradient
print(weight)
```

This prints `0.7`. Subtracting a negative gradient increases the weight. A common error is to add the gradient because the prediction was too small. The derivative already carries the direction.

Compute every gradient using the old parameters. If you update the output weights before calculating the hidden gradient, you mix two different networks in one backward pass. Store the gradients first, then apply the updates together.

A single smaller training loss is a useful implementation check, not evidence of generalisation. F06 still applies: assess predictions on held-out matches. One observation cannot establish that an Icebow policy improves against a new opponent deck.

## 7. Check the derivative independently

A **finite difference** estimates a derivative by slightly increasing and decreasing a parameter. Divide the resulting loss difference by twice the small displacement. This is slower than backpropagation, but helpful for a tiny test.

```python
def loss(w):
    return 0.5 * (2 * w - 1) ** 2

eps = 0.00001
numerical = (loss(0.0 + eps) - loss(0.0 - eps)) / (2 * eps)
print(round(numerical, 3))
```

This prints `-2.0`. The analytical derivative is `(2*w - 1)*2`, also -2 at zero. A sign error would be easy to spot. Use a tolerance rather than exact equality because floating-point arithmetic rounds.

Do not choose an extremely tiny epsilon. Subtracting nearly equal rounded numbers loses precision. Values around one hundred-thousandth work well for these small double-precision examples. Test several ordinary inputs, including an inactive neuron, rather than only the example that first worked.

## 8. Plan your exercise work

The first exercise isolates a neuron's forward calculation. Write its weighted sum on paper, then compare your code on a negative and a positive case. The second exercise returns all scalar gradients for a one-hidden-neuron network. Its scalar form removes matrix bookkeeping so you can concentrate on the chain rule.

The third exercise moves to a NumPy batch. A **batch** is a collection of examples processed together; F12 studies its performance implications. Rows are examples, columns are features. Matrix multiplication should preserve the example count while changing feature count. Never fix a shape error by flattening everything until Python stops complaining.

The final exercise estimates a derivative numerically. It calls a supplied loss function, so the test checks the method rather than one remembered answer. Together these tasks provide separate evidence for forward computation, derivative direction, shape handling, and numerical checking.

Before advancing, explain the backward pass aloud without library names. Start with how wrong the prediction is. Work backwards through the output multiplication, the activation, and the input multiplication. This explanation is the bridge to F08: an automatic differentiation library saves bookkeeping, but it cannot decide whether you chose the right inputs, labels, or loss.

## Common mistakes

- Updating output weights before computing hidden gradients.
- Confusing the input feature values with trainable parameters.
- Applying a ReLU derivative of one to a negative pre-activation.
- Using exact equality for a finite-difference result.
- Treating a smaller training loss as a measured improvement in live play.
