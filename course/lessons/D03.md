## 1. Three names, several layers

An **engine** implements state updates and game rules. An **interface** is the set of operations and data formats another component uses to interact with it. An **adapter** translates between interfaces. The current source describes RoyaleSim as a Rust engine and imports RustEngine from royalegym.rust_engine. Thus RoyaleGym appears here as an access layer or package name connected to that engine. crforge is the Java engine discussed in the listed investigation. **Java** and **Rust** are programming languages; reading their full syntax comes later in E03 and E04. Here we only need to distinguish implementation language from the Python-facing contract.

```python
engines=[{'name':'RoyaleSim','access':'royalegym'},
         {'name':'crforge','access':'facade'}]
print([e['name'] for e in engines])
print(engines[0]['access'])
```

**Output:** `['RoyaleSim', 'crforge']` and `royalegym`.

A **facade** is a simplified entry point to a larger system. The dictionary is a teaching map, not a runtime discovery mechanism. No imports from the real engine are needed for these exercises: importing an adapter can activate a runtime, so we inspect source text and manipulate small stand-ins.

## 2. Tables describe parameters

A **data table** stores values used by rules. Card health, movement speed, and attack damage can be parameters. **Behavior code** determines when movement happens, how a target is selected, and whether a dying unit attacks before being removed. Changing one does not automatically correct the other. The term csv_logic refers to game logic tables stored as CSV-like data; a table version identifies a particular set of values. A record with damage=100 cannot tell you whether damage occurs at launch, impact, or the next tick. That timing belongs in rules.

```python
card={'name':'toy Knight','hp':100,'damage':20,'cost':3}
def apply_hit(hp,stats):
    return max(0,hp-stats['damage'])
print(apply_hit(45,card))
print(card['cost'])
```

**Output:** `25` and `3`.

The dictionary supplies parameters; apply_hit supplies a rule. Both are deliberately simplified. If a replay differs by exactly one attack, changing damage values might hide the mismatch while leaving the timing bug untouched. Diagnose which layer explains the discrepancy before altering anything.

## 3. Versions define the comparison

To **pin** a dependency is to identify the exact version used. A **manifest** is a structured record of the ingredients in a run. Include engine code, table version, adapter version, and evaluation settings. CRFORGE_S0 records a particular engine revision with 16.402-series tables. The later lead log explicitly switches from 16.402.22 to 16.635.3 and reruns baselines. Those strings name snapshots, not numerical performance scores. A fair policy comparison should hold the environment fixed or explicitly evaluate both policies under each environment. Do not mix old and new rows silently.

```python
a={'engine':'revision-A','tables':'16.402.22','adapter':'v1'}
b={'engine':'revision-A','tables':'16.635.3','adapter':'v1'}
print(a==b)
print([k for k in a if a[k]!=b[k]])
```

**Output:** `False` and `['tables']`.

The changed table version does not prove a large outcome difference; it proves the runs differ in a potentially relevant input. Measure the effect with a same-code baseline rerun. The real lead log does exactly that for its specified arms, but its result should not be generalized to every deck or future table change.

## 4. Translate units at boundaries

A **boundary** between components is where one representation becomes another. The RoyaleSim adapter states a scale of 18 between its units and the pool's units. A tile measured as 1000 pool units therefore becomes 18000 engine units. Scaling coordinates is not the same as reflecting sides or mapping screen pixels. Keep each operation named separately. A **round trip** converts into another representation and back; it is a useful test when the conversion should be lossless. Fractional or rounded conversions need a stated tolerance instead.

```python
SCALE=18
pool_x=4500
engine_x=pool_x*SCALE
print(engine_x)
print(engine_x/SCALE)
```

**Output:** `81000` and `4500.0`.

The numeric type changes on division, but the value is preserved. If the adapter accidentally used 1000 instead of 18, it would place units wildly outside the intended arena. A small hand-computed coordinate example is often more informative than a large end-to-end training failure.

## 5. Fidelity requires layered evidence

**Fidelity** is agreement with the behavior being modeled. A **smoke test** checks that a basic operation works, such as creating a match and reading towers. A **determinism test** checks repeatability. A **parity test** compares outputs between implementations or against observations. These are different claims. The crforge work investigates exact replay and seed recovery because useful evaluation requires more than a plausible-looking match. It motivates the move toward crforge for fidelity studies, but a dated investigation does not establish that every current training or live path has migrated. Keep source evidence bounded.

```python
evidence={'smoke':True,'deterministic':True,'all_frames_exact':False}
print(evidence['smoke'] and evidence['deterministic'])
print(all(evidence.values()))
```

**Output:** `True` and `False`.

The first result supports basic operation and reproducibility. The second rejects the stronger combined claim. A simulator can repeat an incorrect rule perfectly. Machine-learning experiments on such an engine may learn its quirks, so behavior validation matters before interpreting training gains as progress in phone play.

## Common mistakes

- Treating a newer table version as proof that behavior rules are correct.
- Assuming the same seed means comparable runs across engines.
- Passing pool coordinates to RoyaleSim without scaling.
- Claiming a smoke test proves full replay fidelity.
- Describing an adapter import as proof of a separate engine implementation.
