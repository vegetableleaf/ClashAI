## 1. Accuracy counts correct decisions

**Accuracy** is the fraction of predictions matching their target labels. **Top-1 accuracy** uses the highest-scoring class as the prediction. For next-card prediction, a class may be a card identity or slot, depending on the dataset.

```python
import numpy as np
scores=np.array([[0.2,0.7,0.1],[0.6,0.3,0.1]])
labels=np.array([1,2])
predicted=scores.argmax(axis=1)
print(predicted.tolist())
print(float((predicted==labels).mean()))
```

**Output:** `[1, 0]`, then `0.5`.

Axis one means choose within each row. The target labels are zero-based class indices. Argmax chooses the first maximum if scores tie. State this convention rather than leaving ties ambiguous.

Accuracy ignores how much probability was assigned to the correct label. Predicting the wrong card at probability 0.51 and at probability 0.999 counts as one error in either case. That is useful for agreement, but incomplete for probability quality.

## 2. Softmax for several classes

F04 used sigmoid for one binary logit. **Softmax** converts several class scores into probabilities that sum to one. Exponentiate each score and divide by the sum of the exponentials.

Subtract the row maximum before exponentiating. This leaves the probabilities unchanged mathematically while avoiding unnecessarily large intermediate exponentials.

```python
import numpy as np
z=np.array([[1000.0,1000.0,1000.0],[0.0,1.0,2.0]])
shifted=z-z.max(axis=1,keepdims=True)
e=np.exp(shifted)
p=e/e.sum(axis=1,keepdims=True)
print(np.round(p,3).tolist())
print(p.sum(axis=1).tolist())
```

**Output:** approximately `[[0.333, 0.333, 0.333], [0.09, 0.245, 0.665]]`, then `[1.0, 1.0]`.

Keepdims=True retains a one-column axis so broadcasting subtracts and divides within each row. Without careful shape handling, a batch operation can accidentally mix different examples.

Adding the same constant to every score in a row must not change softmax probabilities. This is a good test because it checks an important mathematical property rather than one copied output.

## 3. Negative log-likelihood rewards correct probability

**Negative log-likelihood**, NLL, is minus the logarithm of the probability assigned to the observed label, averaged across examples. Lower is better. Natural logarithms measure this loss in **nats**, a logarithmic unit.

```python
import numpy as np
p=np.array([[0.8,0.2],[0.4,0.6]])
y=np.array([0,1])
chosen=p[np.arange(len(y)),y]
print(chosen.tolist())
print(round(float(-np.log(chosen).mean()),3))
```

**Output:** `[0.8, 0.6]`, then `0.367`.

The paired indices select one true-class probability from each row. This is different from choosing the largest probability in each row. Loss must score the actual target, even when the model prefers a different class.

For this course implementation, clip true-class probabilities away from zero. State the clipping value because it caps the penalty for impossible predictions. Library training implementations commonly work directly from logits for better numerical behaviour.

Two models can have identical top-1 predictions and different NLL. One can be more honest about ambiguous choices. That distinction matters when probabilities drive sampling or downstream decisions.

## 4. Calibration asks whether confidence is trustworthy

A classifier is **calibrated** when events assigned a given probability occur at about that frequency. Among predictions made with roughly 80 percent confidence, about 80 percent should be correct under top-label calibration.

**Confidence** here is the largest class probability for an example. **Top-label calibration** compares this confidence with whether the top prediction was correct. It differs from calibration of a particular event probability, such as the probability of playing during a timing slot.

```python
confidences=[0.8,0.8,0.8,0.8,0.8]
correct=[1,1,1,1,0]
print(sum(confidences)/len(confidences))
print(sum(correct)/len(correct))
```

**Output:** `0.8` and `0.8`.

This single group matches perfectly, but five examples are too few to establish broad calibration. Calibration depends on sample size, population, and the grouping procedure.

The **expected calibration error**, ECE, is commonly estimated by dividing predictions into confidence bins, computing each bin's absolute confidence-accuracy gap, and weighting by the bin's fraction of examples. The name “expected” does not make the estimate exact.

## 5. Calculate a binned ECE

Use bins [0,0.5) and [0.5,1] for a tiny example. The final bin includes probability one. Empty bins contribute nothing; do not divide by their count.

```python
confidence=[0.2,0.4,0.8,1.0]
correct=[0,1,1,1]
low_gap=abs((0.2+0.4)/2-(0+1)/2)
high_gap=abs((0.8+1.0)/2-(1+1)/2)
print(round(0.5*low_gap+0.5*high_gap,3))
```

**Output:** `0.15`.

This is fifteen percentage points when expressed as a probability gap times one hundred. Do not confuse a value of 0.15 with 0.15 percentage points.

Different bin boundaries can give different ECE values. Report the binning procedure and sample count when comparing models. A low ECE also does not imply useful discrimination: predicting the overall class frequency for every example can be calibrated while failing to distinguish situations.

## 6. Ranking and ROC curves

**Discrimination** is the ability to rank positive examples above negative ones. A **ROC curve** plots the true-positive rate against the false-positive rate while varying a decision threshold.

A **true positive** is a positive example classified as positive. A **false positive** is a negative example classified as positive. True-positive rate divides true positives by all actual positives. False-positive rate divides false positives by all actual negatives.

Threshold changes can trade one kind of error for another. Accuracy at one threshold does not describe the full ranking. **AUC**, area under the ROC curve, summarises that ranking over thresholds.

For binary labels and real-valued scores, AUC has a convenient interpretation: the fraction of positive-negative pairs where the positive score is higher, awarding half credit to ties.

```python
positive=[0.8,0.6]
negative=[0.2,0.6]
credit=0.0
for p in positive:
    for n in negative:
        credit += 1.0 if p>n else 0.5 if p==n else 0.0
print(credit/(len(positive)*len(negative)))
```

**Output:** `0.875`.

There are four pairs: three strict wins and one tie. The pairwise method is simple and suitable for our tiny exercises, but it costs the product of positive and negative counts. Large datasets need more efficient ranking methods.

If a set contains only one label, AUC is undefined. Return None rather than inventing 0.5. AUC of 0.5 is a meaningful no-ranking baseline when both classes are present.

## 7. Read the direction of the metric

For a win predictor, higher AUC means better ranking of wins above losses. For the project's **C-live discriminator**, a classifier distinguishing bot behaviour from human behaviour, high AUC means the two populations are easy to distinguish.

Therefore a high discriminator AUC can be evidence against the opponent model's human-likeness. It is not an opponent win rate and not a direct measure of our Icebow policy's strength.

Similarly, lower NLL is better under its prediction task, while higher top-1 agreement is better under its agreement task. Neither alone proves strong closed-loop play. **Closed-loop** evaluation means the model's actions affect subsequent states throughout the game.

Keep the measured population attached to the number. Results on human replay data, live calibration data, and simulator matches answer different questions. Compare two models on the same appropriate population before attributing a difference to the model.

## 8. Missing labels and uncertainty

A metric needs valid targets. For outcome classification, include only explicit WIN and LOSS under our decisive convention, and report DRAW and UNKNOWN separately. Never derive a negative label from the absence of a result.

Confidence intervals from Part C still matter. A small ECE computed from a tiny bin is uncertain. An AUC estimate from many rows of a few matches may have less independent evidence than the row count suggests.

A report should include counts, label definition, split identity, metric direction, and a restrained interpretation. A list of decimals without those details cannot tell the reader whether an experiment succeeded.

## Common mistakes

- Scoring the largest probability instead of the true label in NLL.
- Omitting numerical stabilisation in softmax.
- Treating ECE as independent of its bins and sample count.
- Calling discriminator AUC a win rate.
- Calculating AUC when only one class is present.
