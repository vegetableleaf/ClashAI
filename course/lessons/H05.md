## 1. Define success before defining a convenient number

A **sparse reward** appears only occasionally, such as +1 at a win and -1 at a loss. A **dense reward** appears at many intermediate decisions. Sparse outcomes align naturally with winning, but credit can be noisy across a long match.

A **proxy** is a measurable quantity used in place of the real goal. Tower damage, elixir spent and X-Bow locks are possible proxies. Each omits context. Damaging a tower while losing your own king tower is not necessarily progress. Spending elixir is not necessarily using it well.

```python
events = [{"rocket": 1, "win": 0}, {"rocket": 0, "win": 1}]
for event in events:
    print(event["rocket"], event["win"])
```

It prints two lines: `1 0` and `0 1`. The first record looks best under a Rocket-count reward; the second looks best under the actual outcome. These toy records do not prove Rocket is bad. They prove that the two objectives can disagree.

Before training, write an example where the proxy increases while the real goal gets worse. If you can easily construct one, the learner may find it too. A reward should be judged by the objective it defines, not by whether its name sounds strategically reasonable.

## 2. Add a potential difference

A **potential** is a numerical estimate of how promising a state is. Write it Phi(s). **Potential-based shaping** adds F = gamma * Phi(next_state) - Phi(state) to the environment reward. The discount must match the return calculation.

For a toy win predictor, let Phi = P(win) - 0.5. A predicted win probability of 0.7 becomes potential 0.2. The subtraction centres the quantity; it does not turn a probability predictor into a guaranteed measure of strategic value.

```python
gamma = 0.9
phi_now = 0.2
phi_next = 0.3
shaping = gamma * phi_next - phi_now
print(round(shaping, 2))
```

It prints `0.07`. The next potential is discounted before subtracting the current potential. Reversing the subtraction would reward moving toward less promising states.

At a true episode end, our convention sets the continuation potential to zero. This prevents a terminal bonus from being accidentally counted twice. The terminal match reward already communicates the outcome.

```python
reward = 1.0
phi_now = 0.3
phi_terminal = 0.0
print(reward + 0.9 * phi_terminal - phi_now)
```

It prints `0.7`. That last shaped reward is smaller than one, but earlier shaping terms must be included before judging the total return.

## 3. Watch the cancellation across a match

A **telescoping sum** is a sum whose interior terms cancel. Discounted potential differences telescope when they use the same discount as the return. For a completed episode with terminal potential zero, the total shaping contribution is minus the initial potential.

```python
gamma = 0.9
phi = [0.2, 0.3, 0.0]
shaping = [gamma * phi[t+1] - phi[t] for t in range(2)]
total = shaping[0] + gamma * shaping[1]
print(round(total, 2))
```

It prints `-0.2`. The middle potential contributes positively in one term and negatively in the next with exactly matching weights.

For two action sequences from the same initial state, this constant shift does not change their ordering by full discounted return. That is the reason potential shaping can improve intermediate credit without deliberately rewarding a particular habit. The statement depends on consistent discounts, terminal treatment and a well-defined fixed potential.

If you omit the last subtraction or use gamma one for shaping and gamma 0.9 for returns, cancellation fails. If you change the predictor halfway through an episode without accounting for it, you no longer have the same fixed potential sequence function. Such details are algorithmic choices, not formatting details.

The practical benefit is not that a zero-terminal potential creates extra full-match reward. It redistributes the signal over time. Approximate value learning and limited data can respond differently to that distribution, so the effect still needs measurement.

## 4. Recognize reward hacking

**Reward hacking** occurs when an agent improves the specified reward in a way that fails the intended goal. The agent need not understand the loophole. Optimization can repeatedly select the behaviour that the numeric objective rewards.

Suppose a bonus pays 0.2 per deployment and a loss pays -1. Six pointless deployments produce a positive total. If the intended goal is winning, this arithmetic already reveals a problem.

```python
win_reward = -1
deployment_bonus = 0.2
deployments = 6
score = win_reward + deployment_bonus * deployments
print(round(score, 2))
```

It prints `0.2`. A losing match outscored a neutral zero-return match because the proxy dominated the result. Lowering the bonus reduces this particular example but does not establish that the proxy is safe everywhere.

A **farm audit** intentionally searches for cheap repetitive ways to collect a bonus. Test empty Rocket placements, harmless cycling, repeated waiting and actions that trigger counters without helping the board. Include negative controls that should receive no useful credit.

A **simulator exploit** is a policy that benefits from an inaccurate simulator rule. It may score well even under win-only rewards. Better reward arithmetic cannot repair a wrong targeting rule or an opponent that never answers siege. That requires fidelity and opponent investigations.

## 5. Separate reward design from diagnosis

When Rocket alternatives receive negative estimated return in crforge, several explanations remain possible. The action may be poor in that state. The learner may fail to defend after spending six elixir. The opponent model may behave unrealistically. The engine may model damage or timing incorrectly.

A **diagnosis** identifies a cause using evidence that distinguishes it from alternatives. Adding a Rocket bonus before testing these possibilities makes the policy comply with a preference without establishing why the original signal disagreed.

Design an audit table with action, immediate proxy, eventual outcome and the state category. Compare the same starting states and random continuations where possible. H07 develops that paired counterfactual design. For now, calculate whether your proposed term changes trajectory rankings.

```python
base_returns = [1.0, -1.0]
bonus_totals = [0.0, 3.0]
combined = [r + b for r, b in zip(base_returns, bonus_totals)]
print(combined)
```

It prints `[1.0, 2.0]`. The losing trajectory is now preferred. If this objective change is intentional, document and justify it. If it is accidental, do not call it harmless shaping.

A training log can establish that the combined reward rose. It cannot by itself establish that the bot became stronger against live humans. Evaluate wins, losses, draws and unknown outcomes separately. Unknown live records stay outside win-rate denominators and must not be assigned a neutral reward merely to make an array rectangular.

Write a brief explanation of why a mathematically valid potential can still be practically unhelpful. Prediction errors, limited training, observation shift and mismatched time units are reasonable answers. Avoid claiming that the algebra guarantees a live improvement.

## Common mistakes

- Calling any intermediate bonus potential shaping.
- Using different discount factors for shaping and return.
- Keeping a nonzero terminal potential without accounting for it.
- Treating a high proxy score as proof of more wins.
- Repairing an unexplained simulator incentive with a habit bonus.
