## What you will build

A **pipeline** is a series of cooperating stages. A **worker** is a child process assigned one unit of work. **Concurrency** means several tasks can be in progress at once. Your Bash script will run seeds zero through nineteen with two workers at a time, then call a Python collector.

## Milestone 1: Simulate one seeded match

Both towers start at 100 HP, and our elixir starts at five. Run at most twenty ticks. Each tick adds one elixir, capped at ten. If at least six is available, spend six and damage the other tower by a seeded random integer from fifteen through twenty-five. On every third tick, including zero, the opponent deals five through fifteen damage to our tower.

Clamp HP at zero. After both actions, stop if either tower is destroyed. At the end, compare HP: larger own HP means WIN, smaller means LOSS, equal means DRAW. This is a toy tiebreaker, not the real game's rules.

Use random.Random(seed), a separate generator for each match. **Deterministic** means the same inputs produce the same outputs under this implementation.

```python
import random
a=random.Random(7)
b=random.Random(7)
print([a.randint(1,10) for _ in range(4)] ==
      [b.randint(1,10) for _ in range(4)])
```

**Output:** `True`.

Return a dictionary with seed, ours, theirs, and derived. Keep printing outside the simulator so tests can inspect the return value. Tests compare your function with the specified rules, not merely with itself: a constant function would also reproduce the same output.

## Milestone 2: Validate seed coverage

Twenty rows do not necessarily mean twenty distinct matches. A duplicate seed can hide a missing one. Sort the records and compare the complete seed list against the expected list. Raise ValueError if they differ.

```python
rows=[{"seed":2},{"seed":0},{"seed":1}]
ordered=sorted(rows,key=lambda row:row["seed"])
print([row["seed"] for row in ordered])
```

**Output:** `[0, 1, 2]`.

A **collector** combines worker outputs. It should not guess which unfinished seed would have won. Keep each worker's output in its own file, wait for completion, then combine records in numeric seed order. This avoids simultaneous writes to one JSONL file.

JSONL means one JSON object per line, as in B06. A valid file still needs semantic checks: unique seeds, expected fields, and outcomes consistent with the match state.

## Milestone 3: Summarise uncertainty

Count explicit WIN, LOSS, and DRAW values in derived. Anything else is unknown. Decisive win rate is wins divided by wins plus losses. Draws and unknowns are separate counts. If there are no decisive matches, rate and interval are None.

```python
rows=[{"derived":"WIN"},{"derived":"LOSS"},{}]
w=sum(r.get("derived")=="WIN" for r in rows)
l=sum(r.get("derived")=="LOSS" for r in rows)
print(w/(w+l))
```

**Output:** `0.5`.

The live log uses this same cleaning principle: a missing derived result is not a loss. Counts must reconcile to the total number of records.

Use the **Wilson interval** from C05 with z=1.96. Let n=w+l, p=w/n, denominator=1+z²/n, centre=(p+z²/(2n))/denominator, and half-width=z×sqrt(p(1-p)/n+z²/(4n²))/denominator. Return a two-element list of lower and upper bounds, clamped to [0,1] against roundoff.

```python
n,p,z=20,0.5,1.96
den=1+z*z/n
centre=(p+z*z/(2*n))/den
half=z*(p*(1-p)/n+z*z/(4*n*n))**0.5/den
print(round(centre-half,3),round(centre+half,3))
```

**Output:** `0.299 0.701`.

Twenty seeds provide only practice-scale evidence. The interval assumes an appropriate sampling interpretation. It cannot account for the enormous difference between this toy game and live Clash Royale.

## Milestone 4: Wait for both jobs

An ampersand starts a background command; dollar-exclamation-mark contains its PID. Save each PID immediately, then wait for both.

```bash
printf '%s\n' worker &
child=$!
wait "$child"
printf '%s\n' collected
```

**Output:** `worker`, then `collected`.

With two workers, save two IDs. Set status=0 before waiting. Use `wait "$child" || status=1` for each child: the operator || runs its right-hand command if the left command fails. Check status only after both waits. This avoids abandoning the second worker when the first fails.

The exercise prints two worker markers and then collected. The two workers may finish in either order. Collected must be last.

## Milestone 5: Connect the complete pipeline

The supplied harness writes sim.py and collect.py in a temporary directory. You fill the SCRIPT string with Bash code. The script receives Python's path as argument one and the temporary folder as argument two. Assign them to PY and WORK, then quote every expansion used as a path.

Use an arithmetic loop to launch pairs:

```bash
for ((seed=0; seed<4; seed+=2)); do
  printf '%s %s\n' "$seed" "$((seed+1))"
done
```

**Output:** `0 1` and `2 3`.

The three fields initialise, test, and update the loop variable. Your actual script uses twenty as the upper limit. Each pair runs sim.py twice, passing one seed to each child. Redirect stdout to the corresponding seed-numbered .json file. The symbol > writes stdout to a file.

Wait for both PIDs and fail before collection if either worker failed. After all ten pairs finish, run collect.py with WORK as its argument. That program reads each file, creates matches.jsonl in order, and prints a JSON object containing rows and summary.

The Python harness uses subprocess.run to start Bash. Capture_output collects stdout and stderr; timeout limits waiting; sys.executable selects the course's interpreter. These tools were introduced in B11. TemporaryDirectory cleans up the generated files after the exercise.

Keep status chatter off stdout: json.loads must decode the collector's entire output. An extra “starting” line would corrupt that interface even if every worker succeeded.

The checks run the pipeline twice, verify all twenty seeds, compare outcomes with the simulator, decode the JSONL, and recompute the summary. This establishes an end-to-end local pipeline contract.

## Milestone 6: Write up the experiment

Return a report string containing decisive count, draws, unknowns, rate, interval, and a limitation statement. The exercise checks those required pieces; the quality of the explanation also needs your judgment.

Explain why two workers were chosen: enough to practise concurrent execution while keeping a shared laptop workload tiny. More workers would change speed, not automatically strengthen the evidence.

Separate measured statements from assumptions. Completing twenty distinct seeds is measured. Treating those outcomes as representative trials is an assumption. Improved live Icebow play is not established. State that distinction directly.

For no decisive outcomes, write rate=None rather than zero percent. Missing evidence should remain visible. A report with a convenient invented number is less useful than an honest unavailable result.

## Common mistakes

- Counting rows without checking distinct seeds.
- Mixing progress messages into JSON stdout.
- Waiting only for the most recent child.
- Recording missing output as a loss.
- Describing a toy result as a live improvement.
