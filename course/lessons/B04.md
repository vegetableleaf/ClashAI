## Why this matters for ClashBot

A bot must respond to changing state. It cannot always play X-Bow merely because X-Bow is in its hand. Elixir, game phase, and available options affect the decision. Python conditions let code select between alternatives, and loops let it repeat updates as time advances.

The course checker, `course/check_exercises.py`, also makes decisions and repeats work: it checks each exercise and counts problems. The syllabus lists no required source for B04, so we use a short excerpt from that verified file to connect our learning to a real program.

Our miniature elixir simulation prepares you to read RoyaleSim and crforge code later. It is a declared approximation with chosen phase boundaries, not a validation of either engine or of live emulator timing. The same programming structures also appear in training loops for imitation and reinforcement learning.

## 1. Comparisons ask questions

A **comparison** evaluates a relationship and produces a boolean. `==` tests equality; `!=` tests inequality. `<` and `>` mean less than and greater than. `<=` and `>=` include equality. These are different from the single assignment sign `=`.

```python
elixir = 6
print(elixir >= 6)
print(elixir > 6)
```

It prints `True` then `False`. Six elixir is enough for a cost of six, so an affordability check needs `>=`, not `>`. The boundary case often reveals a bug that a larger example would hide.

A **boundary case** is an input at the edge between behaviors, such as exactly enough elixir or exactly the first second of a new phase. Before writing a condition, test one value below the boundary, one at it, and one above it by hand.

## 2. If selects a block

A **conditional statement** runs code depending on a condition. `if` begins it, followed by an expression and a colon. The indented **block**, a group of statements belonging together, runs only when the condition is true.

```python
elixir = 6
if elixir >= 6:
    print("X-Bow is affordable")
```

It prints `X-Bow is affordable`. Change the value to five and this program prints nothing. Four spaces are the usual indentation. The indentation is part of Python syntax, not decoration.

`else` gives an alternative when the condition is false:

```python
elixir = 5
if elixir >= 6:
    print("affordable")
else:
    print("wait")
```

It prints `wait`. Exactly one branch runs. Both branch headers end with a colon, and each body is indented. The `else` aligns with its matching `if`, showing which decision it belongs to.

## 3. Elif introduces another condition

`elif` means "otherwise, if." Python checks the conditions in order and runs only the first matching branch. A final `else` handles all remaining cases.

```python
seconds = 150
if seconds < 120:
    multiplier = 1
elif seconds < 180:
    multiplier = 2
else:
    multiplier = 3
print(multiplier)
```

It prints `2`. These are chosen teaching boundaries: under 120 seconds is 1x, from 120 through below 180 is 2x, and 180 onward is 3x. Do not use this simplified schedule as a claim about a specific live game mode.

Order matters. If you tested `seconds < 180` first, a value of sixty would match that branch too. When conditions overlap, the first matching one wins. Explain each interval in words before translating it into code.

## 4. Combine conditions

**Boolean operators** combine or invert truth values. `and` requires both conditions to be true. `or` requires at least one. `not` reverses a truth value. Use parentheses to make a longer expression's grouping clear.

```python
hand = ["X-Bow", "Tesla", "Knight", "Skeletons"]
elixir = 5
can_play = ("X-Bow" in hand) and (elixir >= 6)
print(can_play)
```

It prints `False`. Membership came from B03. Being in hand is necessary here but not sufficient; affordability also matters. This expression models two requirements, not the entire legality system.

```python
has_target = False
print(not has_target)
print(has_target or True)
```

It prints `True` twice. These are logic demonstrations, not recommendations to always attack. Real decision code must define the meaning and source of each condition rather than hide assumptions inside a complicated expression.

## 5. For repeats over a collection

A **loop** repeats a block. A `for` loop assigns each element from a collection to a loop variable in turn, then runs the block. An **iteration** is one repetition.

```python
for card in ["X-Bow", "Tesla", "Rocket"]:
    print(card)
```

It prints the three names on three lines in order. On the first iteration `card` refers to X-Bow, then Tesla, then Rocket. You do not need three separate print statements with three separate names.

The built-in `range` supplies a sequence of integers. `range(3)` supplies zero, one, and two. `range(2, 5)` supplies two, three, and four. As with slicing, the stop is excluded.

```python
for tick in range(3):
    print(tick)
```

It prints `0`, `1`, and `2`. A **tick** is one discrete update step in a model. In our toy simulation we declare one tick to be one second. Real engines may use different tick durations; never transfer a numeric tick count between them without checking units.

## 6. Accumulate a total

An **accumulator** stores a running total. Initialize it before the loop, update it inside, and inspect it afterward. `+=` is shorthand for adding and assigning back to the same name.

```python
total_cost = 0
for cost in [6, 4, 1]:
    total_cost += cost
print(total_cost)
```

It prints `11`. If you put `total_cost = 0` inside the loop, it would reset on every iteration and lose earlier contributions. Indentation therefore affects both which statements repeat and what information survives.

A **counter** is an accumulator that tracks how many qualifying items you saw. Combine a loop with an `if` to count affordable cards:

```python
affordable = 0
for cost in [6, 4, 1]:
    if cost <= 4:
        affordable += 1
print(affordable)
```

It prints `2`. The inner block is indented twice because it belongs to a condition inside a loop. The final print is outside both blocks, so it runs once.

## 7. While repeats until a condition changes

A `while` loop repeats as long as its condition is true. You must ensure something changes so the loop can finish. Otherwise you create an **infinite loop**, a repetition that never reaches its stopping condition.

```python
elixir = 3.0
steps = 0
while elixir < 6:
    elixir = min(10, elixir + 1)
    steps += 1
print(steps)
```

It prints `3`. This example adds one whole elixir per step to make the trace easy. It is not the 2.8-second regeneration model. After three updates, the condition becomes false and execution continues after the loop.

The course stops programs exceeding thirty seconds. That time limit protects the exercise experience; it should not be used as your loop's intended stopping mechanism. Use a finite range when you already know how many updates are needed.

## 8. Simulate elixir one step at a time

Now combine phase selection with a loop. Let `tick` represent the start of a one-second interval. Choose the multiplier at that start, add one second of regeneration, then cap at ten. We perform no spending in this first example.

```python
elixir = 0.0
for tick in range(3):
    multiplier = 1
    elixir = min(10, elixir + multiplier / 2.8)
print(f"{elixir:.3f}")
```

It prints `1.071`. Three updates add `3 / 2.8` elixir before display rounding. Keep the unrounded state inside the loop.

For phase changes, place the earlier `if`/`elif`/`else` inside the loop and compare `tick` with the declared boundaries. For spending, explicitly choose whether the play happens before or after regeneration. Different update orders can produce different results near a cap or affordability threshold.

A **trace** is a record of intermediate states. B03 taught list `append`, so you can build one:

```python
elixir = 0.0
trace = []
for tick in range(3):
    elixir = min(10, elixir + 1)
    trace.append(elixir)
print(trace)
```

It prints `[1.0, 2.0, 3.0]`. Again, this trace example uses one elixir per step for clarity. A final value alone can hide update mistakes; a trace exposes which step first differs from expectation.

## Common mistakes

- Using `=` when you mean `==`.
- Requiring more elixir than the exact card cost.
- Resetting an accumulator inside its loop.
- Forgetting that range excludes its stop.
- Updating nothing in a while loop's stopping condition.
