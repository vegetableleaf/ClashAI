# F10 - Many heads, sampling and temperature

**Time:** about 4 hours ? **You will be able to:** decode multiple model outputs with temperature, legal-action masks, and reproducible sampling.

## Why this matters for ClashBot

Playing Icebow requires more than choosing a card name. The bot must decide whether to play, which card to use, where to place it, and sometimes how to handle timing or an ability. Those choices must eventually become an action accepted by the simulator or a tap interpreted by the phone emulator.

`pipeline/decision_options.py` records configurable inference choices such as card selection and temperature. **Inference** means using a model to compute predictions rather than updating its parameters. Reading these settings helps explain why the same checkpoint can behave differently under different decoding rules.

F09 introduced attention heads inside an encoder. This lesson uses **output head** to mean a final model component producing scores for a particular prediction task. These are different uses of the word head. Our examples use a teaching three-card menu, not the complete production action format.

## 1. Separate shared information from task-specific scores

A **shared representation** is an intermediate vector reused by several prediction tasks. One head can turn it into card logits, another into placement logits, and another into timing logits. Sharing allows all tasks to use some common board information.

```python
import torch
from torch import nn
board = torch.zeros(2, 8)
card_head = nn.Linear(8, 3)
cell_head = nn.Linear(8, 4)
print(tuple(card_head(board).shape))
print(tuple(cell_head(board).shape))
```

This prints `(2, 3)` and `(2, 4)`. Two observations receive three card scores and four teaching-cell scores. These cell counts are deliberately tiny. The real model's placement grid is much larger.

A **gate** is an output controlling whether an action happens. A **timing head** can describe when an action happens. An **ability head** can describe an additional available action. Their exact meanings depend on the model version and training labels. Do not assume every checkpoint implements every head with the same shape.

Multiple outputs also do not imply independence. Placement may be **conditional**, meaning its distribution depends on the chosen card. A defensive Tesla placement and an attacking X-Bow placement should not be interpreted as interchangeable actions just because they share an arena coordinate system.

## 2. Convert logits into probabilities

A **decoder** turns model outputs into an executable choice. The simplest card decoder takes the largest logit. A probabilistic decoder first applies softmax and then samples a category.

```python
import numpy as np
logits = np.array([2.0, 1.0, 0.0])
weights = np.exp(logits-logits.max())
probabilities = weights/weights.sum()
print(np.round(probabilities, 3).tolist())
print(int(np.argmax(logits)))
```

This prints `[0.665, 0.245, 0.09]` and `0`. The **argmax** is the index of the largest value. A **greedy** decoder always selects an argmax. In NumPy, a tie returns the first maximum; that is an implementation convention, not a strategic preference.

A probability of 0.665 means category zero is chosen about that often over repeated independent samples from this fixed distribution. It does not mean the action wins 66.5% of matches. Card probabilities and win probabilities answer different questions.

## 3. Temperature controls concentration

**Temperature**, written T, divides logits before softmax. T must be finite and positive. Lower values concentrate probability on high-scoring categories; higher values flatten the distribution. T=1 leaves the original softmax unchanged.

```python
import numpy as np

def probabilities(logits, temperature):
    scores = np.asarray(logits, dtype=float)/temperature
    weights = np.exp(scores-scores.max())
    return weights/weights.sum()

print(round(probabilities([2, 0], 1)[0], 3))
print(round(probabilities([2, 0], 0.5)[0], 3))
```

This prints `0.881` and `0.982`. The preferred action becomes more likely when temperature falls. It is still not literally guaranteed at T=0.5.

Greedy selection is a separate branch, not ?divide by zero.? Never implement T=0 by passing zero into the probability function. Also remember that temperature cannot reorder distinct logits: it changes their probability differences, not which one is largest.

A temperature change is an experimental change. If a new model is compared with an old model at a different temperature, you cannot attribute the whole difference to training. Hold decoding settings fixed when asking whether the weights improved.

## 4. Mask impossible actions first

An **action mask** says which choices are currently permitted. For our teaching card menu, a card is available only if it is in hand and affordable. Real action legality can include additional engine conditions, so this is a deliberately limited example.

```python
import numpy as np
costs = np.array([6, 4, 1])
in_hand = np.array([True, True, False])
elixir = 4
allowed = in_hand & (costs <= elixir)
print(allowed.tolist())
```

This prints `[False, True, False]`. The X-Bow-like six-elixir option is unaffordable. The cheap third option is not in hand. The `&` operator combines boolean arrays entry by entry; Python's ordinary `and` is not the array operation we need.

Replace illegal logits with negative infinity before applying softmax. Their probabilities become zero. This prevents a high-scoring but unaffordable card from receiving selection probability.

```python
import numpy as np
logits = np.array([100.0, 1.0, 0.0])
allowed = np.array([False, True, False])
scores = np.where(allowed, logits, -np.inf)
weights = np.exp(scores-scores.max())
print((weights/weights.sum()).tolist())
```

This prints `[0.0, 1.0, 0.0]`. `np.where` chooses the logit where allowed is true and negative infinity otherwise.

If no card is legal, there is no card probability distribution to normalise. Our exercise returns `None` to signal ?no card available.? A caller can then represent waiting explicitly. Do not invent a fallback card or let NaNs pass into the action system.

## 5. Sampling needs a random generator

**Categorical sampling** chooses one category according to its probabilities. NumPy's `default_rng(seed)` creates a local random-number generator. Its `choice` method accepts a probability vector with `p=`.

```python
import numpy as np
a = np.random.default_rng(21)
b = np.random.default_rng(21)
p = [0.7, 0.2, 0.1]
left = a.choice(3, size=6, p=p)
right = b.choice(3, size=6, p=p)
print(np.array_equal(left, right))
```

This prints `True`. Matching seeds reproduce the stream for the same calls in this environment. Different call counts consume random numbers differently. If one decoder makes an extra draw before choosing a card, later choices may diverge even with the same initial seed.

Create the generator once per simulated run, not once per decision. Resetting it at every decision repeatedly uses the first draw and creates an unintended pattern. For paired evaluations, document the random streams and which operations use each one.

Sampling is a behavioural choice. It is not automatically more human-like than greedy decoding. A sampled policy can still have unrealistic timing, placement, or card frequencies. G04 will measure those properties separately.

## 6. Card and cell form a joint choice

A **joint probability** describes several choices together. If card probability is P(card) and the selected card's conditional cell probability is P(cell given card), the pair has probability equal to their product.

```python
card_probability = 0.6
cell_probability_given_card = 0.25
joint_probability = card_probability*cell_probability_given_card
print(joint_probability)
```

This prints `0.15`. It is not correct to multiply by a cell distribution belonging to another card. In a two-stage decoder, choose the card first, then compute or select that card's placement distribution.

Training labels must agree with decoding conventions. A placement head trained on one grid cannot be interpreted using another grid merely because both arrays contain coordinates. Likewise, a timing output trained for fixed slots needs a decoder that understands those slots.

The exercises stop at simple probabilities and seeded samples. They do not recreate the production decoder. This boundary matters: a few correct softmax operations cannot validate hand cycling, emulator tap coordinates, engine acceptance, and timing together.

## 7. Check invariants before looking at wins

An **invariant** is a condition that should always hold. For a probability vector, values should be finite and nonnegative, and their sum should be one. Illegal categories should have probability zero. Output length should equal the number of candidate cards.

Test easy edge cases first: one legal action, equal logits, a very large logit, and no legal actions. These expose errors that a random battle result might hide. A bot could win despite selecting an illegal action once, so wins are not a substitute for decoder checks.

For temperature, compare concentration on a unique maximum rather than expecting one particular random sample. For sampling, check reproducibility and membership in the legal set. Avoid a brittle test requiring exact empirical frequencies from a short random run.

## 8. Read defaults without assuming deployment

The source excerpt below describes defaults and validation. A caller may provide non-default settings. A checkpoint filename alone does not identify the active decoder. A useful experiment record pairs model identity with code version, simulator version, feature contract, seed, and decoding options.

The exercises progress from softmax to legality to sampling. Explain each return value in words before submitting: ?these are card-choice probabilities given a legal set,? or ?this integer is one sampled card index.? Precise descriptions prevent later confusion between model confidence, action frequency, and match outcomes.

When a decoded action reaches the live system, observation latency and tap handling add more layers of behaviour. The mathematical probability function can be correct while the end-to-end system acts differently. That is why the course later evaluates complete trajectories rather than stopping at per-decision scores.

## Common mistakes

- Using T=0 inside softmax instead of a greedy branch.
- Masking probabilities after softmax without renormalising.
- Sampling an unaffordable card because its logit is large.
- Resetting the generator on every decision.
- Calling a card probability a probability of winning.
