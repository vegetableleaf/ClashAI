# H08 · Staying close to a reference: KL pulls and drift

**Time:** about 4 hours · **You will be able to:** distinguish reference penalties from update stops and measure drift through a shared representation.

## Why this matters for ClashBot

A human-like opponent can become stronger through reinforcement learning while losing the timing patterns that made it representative of humans. That is one reason the opponent learner uses an imitation reference. The same design is not automatically appropriate for ClashBot's own policy.

`scratchpad/gauntlet/L74/plan1026/opp/OPP_LEARNER.md` describes a fixed pull toward the opponent's imitation initialization. The project's worker rules separately state that our own model has no KL penalty leash, while retaining a previous-policy KL stop. These are distinct scopes.

The exercises make that distinction concrete with two-action distributions and a tiny shared network. A parameter can remain frozen while the function it helps compute changes. Seeing that happen numerically is more useful than assuming “frozen” means “unchanged behaviour.”

## 1. Name the reference and the policy being constrained

A **reference policy** is a saved distribution used as a comparison target. An **anchor** is a reference intended to resist movement away from a chosen behaviour. An imitation initialization can be an anchor when we want an opponent to remain human-like.

A **KL pull** adds beta times a divergence to the optimization loss. **Beta** is the coefficient controlling the strength of that penalty. Larger beta places more cost on departing from the reference; beta zero removes that particular loss term.

```python
policy_loss = -0.4
kl = 0.03
beta = 2.0
total_loss = policy_loss + beta * kl
print(round(total_loss, 2))
```

It prints `-0.34`. Minimizing total loss trades reward improvement against reference departure. The coefficient has meaning only with the specified divergence, direction, weighting and other loss terms.

A fixed reference remains the initial model. A moving reference can be the previous update's model. A policy that moves slightly at every update can stay close to each moving reference while eventually becoming very different from its original imitation behaviour. State the reference identity every time you report a KL value.

## 2. Penalties, stops and drift reports answer different questions

H04 introduced a KL early stop. It asks whether the next update step would exceed a local movement threshold. A penalty asks the optimizer to prefer smaller divergence. A **drift monitor** measures changes in behaviour or output over time, whether or not it changes optimization.

```python
beta = 0.0
measured_kl = 0.025
stop_limit = 0.02
penalty = beta * measured_kl
stop = measured_kl > stop_limit
print(penalty, stop)
```

It prints `0.0 True`. There is no penalty, yet the early-stop condition is active. Calling this contradictory would confuse two different controls.

The owner's “no leash on our own model” rule concerns the policy penalty for that learner. It does not imply that opponent calibration must discard its imitation anchor, or that identity checks and local update stops disappear. Scope is part of a technical rule.

A good report names the learner seat, reference checkpoint, penalty coefficient, stop threshold and monitored distributions. Without those fields, two logs both labelled “KL” may describe entirely different mechanisms.

## 3. Freeze a head, then change its input

A **head** is an output part of a neural network, such as the timing or card predictor. A **trunk** is the shared representation that feeds several heads. Freezing a head means its parameters are not updated. Its outputs still depend on the trunk.

Consider a one-number trunk and a one-number head. The output is their product with the input. Hold the head fixed at two, then change the trunk from one to three.

```python
x = 1.0
head = 2.0
before = head * (1.0 * x)
after = head * (3.0 * x)
print(before, after)
```

It prints `2.0 6.0`. The head parameter did not move. The output changed because the representation changed.

In PyTorch, `requires_grad_(False)` disables gradient accumulation for a parameter. It does not block gradients through the operation to earlier trainable inputs. That is useful when training a trunk beneath a fixed output mapping, but it invalidates the assumption that frozen heads guarantee stable timing.

```python
import torch
trunk = torch.tensor(1.0, requires_grad=True)
head = torch.tensor(2.0, requires_grad=False)
output = trunk * head
output.backward()
print(trunk.grad.item(), head.grad)
```

It prints `2.0 None`. The trunk can still learn. An output-stability claim therefore needs measurements on fixed inputs, not only a parameter checksum.

## 4. Measure outputs on a fixed probe set

A **probe set** is a fixed collection of inputs used to inspect a model. Compare the original and updated model on exactly these inputs. Changing the probe set while comparing outputs introduces a second source of change.

A simple statistic is **mean absolute difference**, abbreviated MAD: average the absolute before/after difference. For probability outputs it measures average movement in probability units.

```python
before = [0.2, 0.4, 0.8]
after = [0.3, 0.35, 0.75]
mad = sum(abs(a-b) for a,b in zip(before, after)) / len(before)
print(round(mad, 4))
```

It prints `0.0667`. This is about 6.67 probability points of average absolute movement. It does not reveal whether the movement improves decisions, so pair it with accuracy, calibration or behavioural evaluation.

A timing **hazard** is a conditional probability that an event occurs now given it has not occurred earlier in the relevant interval. The opponent model's timing output includes such quantities. A frozen timing head can have changed hazards if its trunk representation changes.

A probe set should cover meaningful states. If it contains only opening hands, it cannot establish overtime stability. Report the number and source of probe rows, and keep the set fixed for a declared comparison. A separate fresh set can assess whether the observed pattern generalizes.

## 5. Interpret a reference pull as a design tradeoff

An anchor can preserve useful human structure and can also resist beneficial adaptation. Reducing beta is therefore a hypothesis about a tradeoff, not a guaranteed route to stronger opponents. Test one coefficient change at a time with a fixed evaluation.

The opponent document describes `beta0 = beta_min = beta_max` as a way to hold the coefficient fixed. **Clamping** restricts an updated number to a range. If both ends of the range are the same number, an adaptive update cannot move the coefficient.

```python
proposal = 0.12
lower = upper = 0.03
beta = min(upper, max(lower, proposal))
print(beta)
```

It prints `0.03`. The adaptation formula may run, but the clamp determines the result.

The document also discusses `th_anchor`, a separate timing-output pull. Do not assume it is interchangeable with the card/cell KL coefficient. Different heads can have different losses, scales and references. The later timing-policy-gradient work changes the timing objective again.

Choose evaluation statements carefully. “Timing parameters are byte-identical” is a claim about stored numbers. “Hazards changed by this much on these rows” is a claim about outputs. “The opponent remains human-like” requires a broader behavioural comparison. These claims form a progression of evidence, and none should silently stand in for the next.

For our own bot, diagnosing drift can include checking decoding identity, simulator exploits and changes in the opponent pool. A reference penalty is only one possible tool and is not authorized merely because it is easy to implement.

## Common mistakes

- Treating zero beta as disabling every KL-related check.
- Applying the opponent anchor rule to our own learner without checking scope.
- Assuming frozen parameters imply frozen outputs.
- Changing probe rows between the before and after measurements.
- Reporting a small MAD as proof of human-like whole-game behaviour.
