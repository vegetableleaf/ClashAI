## 1. Observe, decide, act, confirm

A **reader** converts captured game information into a structured observation. A **decision loop** repeatedly reads an observation, chooses an action, and requests execution. An **actuator** applies that request; here it can be a tap on the emulator. **ADB**, Android Debug Bridge, is a tool for communicating with an Android device or emulator. We discuss its role without executing device commands. A tap request is not confirmation: a menu overlay, illegal placement, stale hand, or timing race may prevent the intended card from appearing. Keep requested and confirmed actions as separate events.

```python
events=['observation','decision','tap_requested','play_confirmed']
print(' -> '.join(events))
request={'card':'X-Bow','confirmed':False}
print(request['confirmed'])
```

**Output:** `observation -> decision -> tap_requested -> play_confirmed` and `False`.

This toy request is not sent anywhere. Confirmation may come from a subsequent hand transition, elixir change, or observed unit. Each signal has ambiguity, so the real system needs a defined confirmation rule. A lack of confirmation should remain visible rather than being converted into a successful play count.

## 2. Latency and stale observations

**Latency** is elapsed time between an event and its effect or observation. **End-to-end latency** includes capture, reading, decision, queueing, and action delivery. An observation's **age** at tap time is tap_time minus capture_time. A model may take only a few milliseconds while the overall loop uses a much older frame. A **budget** is a declared maximum acceptable duration for a stage or whole loop. These exercises use invented milliseconds and an explicit toy threshold; they do not assert a production safety limit. Negative durations usually indicate inconsistent clocks or event ordering.

```python
capture,read_done,decide_done,tap_done=1000,1040,1060,1090
print(tap_done-capture)
print(decide_done-read_done)
print((read_done-capture)+(decide_done-read_done)+(tap_done-decide_done))
```

**Output:** `90`, `20`, and `90`.

The model stage is twenty milliseconds, while the observation is ninety milliseconds old when the tap completes. Adding nonoverlapping stage durations recovers the total. Use the same clock basis for all times; mixing timestamps from different machines without synchronization can create meaningless negative ages.

## 3. Navigation and supervision

A **navigator** handles screens between battles, such as menus and result screens. A **supervisor** watches a child process and may restart it after certain failures. A **watchdog** detects stalled progress or specific incident events. These roles are different from the policy choosing a card. An **intentional stop** should be distinguishable from a crash. The start script documents a between-match stop workflow, and the watcher explicitly excludes normal stop-file messages from alerts. We model the decisions with strings; no exercise starts, stops, or inspects a live process.

```python
def toy_event(line):
    if line.startswith('[live] stop file'): return 'intentional_stop'
    if 'NOT restarting' in line: return 'gave_up'
    if line.startswith('[nav] run stopped'): return 'incident'
    return 'ordinary'
print(toy_event('unknown: wait'))
print(toy_event('[live] stop file requested'))
```

**Output:** `ordinary` and `intentional_stop`.

The order gives intentional stopping a clear meaning. A production parser should follow the actual log grammar rather than broad substring guesses. The watcher proposal documents how counting ordinary unknown and tap-through lines produced false alarms during normal transitions.

## 4. Progress, heartbeats, and results

A **heartbeat** is a periodic sign that a component is still running. It is not necessarily evidence of useful progress. A **progress event** indicates the workflow advanced, such as a confirmed play or result. An **API**, application programming interface, provides structured access to another service; a **poller** periodically asks for updates. The battle-log poller supplies eventual results, while the decision loop may have already finished. This explains why a local match row can exist without derived outcome. C02's unknown category is therefore an operationally meaningful state, not merely untidy data.

```python
last_progress,now=100,850
age=now-last_progress
threshold=720
print(age)
print(age>=threshold)
result=None
print('unknown' if result is None else result)
```

**Output:** `750`, `True`, and `unknown`.

The threshold is a toy twelve-minute rule corresponding to the watcher proposal's documented no-progress interval. Whether to alert also depends on a live process being present and whether an intentional stop is active. A heartbeat alone should not reset a progress timer if no match activity has occurred.

## 5. Safe lifecycle reasoning

A **lifecycle** is the progression from startup through operation to shutdown. Reading a startup script is not authorization to execute it. The source documents an offline check path and a between-match stop, but this course task only simulates those decisions. In a real operating workflow, establish process ownership, avoid duplicate supervisors, and honor intentional stopping before considering a restart. The course's teaching boundary is explicit: return a recommended status from supplied facts, with no side effects. Later E01 and E02 cover shell and process syntax; here we use ordinary Python conditionals.

```python
def next_status(stop_requested,process_running):
    if stop_requested: return 'remain stopped'
    if process_running: return 'observe existing process'
    return 'needs operator review'
print(next_status(True,False))
print(next_status(False,True))
```

**Output:** `remain stopped` and `observe existing process`.

A function returning text cannot itself start a process, which makes the exercise safe and easy to test. Its result is an educational recommendation, not a production supervisor. The real system includes more conditions, such as account activity, known screens, model checks, and retry limits.

## Guided practice and review

### Practice 1: Measure observation age

Write ages(capture,read_done,decide_done,tap_done), returning (model_ms,total_ms). Require nondecreasing times with an assertion. Example: 1000,1040,1060,1090 gives (20,90).

This check catches a clock-order problem before an apparently excellent negative latency enters a chart.

### Practice 2: Count confirmed requests

Write confirmation(events) returning (requested,confirmed) for event strings 'tap_requested' and 'play_confirmed'; ignore other events. Example: two requests and one confirmation gives (2,1).

Aggregate counts do not pair individual requests and confirmations. A fuller system needs action identifiers and timing, but the distinction already prevents a misleading success count.

### Practice 3: Classify synthetic log lines

Write classify(line): starts '[live] stop file' -> intentional_stop; contains 'NOT restarting' -> gave_up; starts '[nav] run stopped' -> incident; else ordinary. Example: 'unknown: wait' is ordinary.

The rules are deliberately narrow and fully taught. They illustrate the source's false-alarm problem without claiming to duplicate its full parser.

### Practice 4: No-progress decision

Write stalled(now,last_progress,running,stop_requested), True only if running, not intentionally stopped, and elapsed >=720 seconds. Example: now=850,last=100,running=True,stop=False gives True.

A missing process belongs to a different incident category. Separating categories makes a report actionable without conflating normal shutdown and stalled play.

### Practice 5: Choose a read-only lifecycle status

Write status(stop_requested,running), returning 'remain stopped', 'observe existing process', or 'needs operator review' in the order taught. Example: stop=True wins even if running=True.

## Common mistakes

- Equating a requested tap with a confirmed card play.
- Using an old observation without measuring its age.
- Treating ordinary unknown-screen transitions as a stuck incident.
- Restarting a process when an intentional stop was requested.
- Assuming a source file's existence proves that version is running.
