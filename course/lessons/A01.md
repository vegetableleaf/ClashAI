## Why this matters for ClashBot

ClashBot is not one file called "the bot." It is a collection of programs, settings, records, and explanations. The Icebow X-Bow deck is one game strategy within that collection. Before understanding its decisions, you need to find the evidence describing them.

`HANDOFF.md` records project findings. `pipeline/` contains shared Python code. `icebow/` contains the deck-specific project area. `scratchpad/gauntlet/L74/` holds experiments and supporting records. These names will recur throughout the course. Knowing where you are prevents a correct command from being applied to the wrong place.

The live bot interacts with a phone emulator, a program that behaves like a phone on a computer. Simulators such as RoyaleSim and crforge model games in software. **Imitation learning** means learning to copy examples; **reinforcement learning** means learning from rewards. Later lessons explain both. Today you only need to distinguish their code and records from the running game itself.

## 1. Files hold content; folders hold names

A **file** is a named collection of stored information. A **folder**, also called a **directory**, contains named files and other folders. A folder is an addressable container, not a paragraph of text. Opening a folder shows its contents; opening a text file shows its words.

A **repository**, often shortened to **repo**, is a project folder whose history can be tracked with Git. Git arrives in A04. For now, the repository root is the top folder of this project: `C:\Users\benpe\ClashBot`. **Root** here means the starting folder for project paths, not the root of the whole computer.

A filename such as `HANDOFF.md` has a main name and an **extension**, the ending after the final dot. The extension suggests a format. `.md` usually means Markdown text, `.py` Python source, and `.json` structured text. An extension is a convention, not proof that the content is valid.

Do not rename an unfamiliar file to make it open in an editor. Changing `.json` to `.txt` changes the name, not its meaning. Other code may depend on the original name. In this course, locating and reading project evidence is separate from editing project implementation.

## 2. A path is a route to a named item

A **path** gives the route through folders. A **separator** marks the boundary between its components. Windows commonly displays backslashes. Git Bash commonly uses forward slashes. These are two spellings of routes on the same machine, rather than two copies of the project.

The Windows absolute path `C:\Users\benpe\ClashBot\HANDOFF.md` begins with a drive and includes the complete route. An **absolute path** identifies an item without relying on your current folder. In Git Bash the corresponding route is `/c/Users/benpe/ClashBot/HANDOFF.md`.

A **relative path** starts from the **working directory**, the folder a command currently uses. From the repo root, `HANDOFF.md` and `pipeline/__init__.py` are relative paths. From inside `pipeline/`, the relative route to the handoff is `../HANDOFF.md`. The special component `..` means the parent folder; `.` means the current folder.

Think of the route `scratchpad/gauntlet/L74/` one component at a time: enter scratchpad, then gauntlet, then L74. The final slash conventionally signals a folder. A slash does not create the folder, and omitting it from an existing directory path does not turn that directory into a file.

## 3. Your first tiny terminal vocabulary

A **terminal** is a window in which you type instructions and read responses. A **shell** interprets those instructions. For these exercises the shell is Git Bash. A02 will cover commands properly; we need just three small commands now.

A **command** names an action. `pwd` prints the working directory. **Output** is the text a command produces. Type this in the exercise editor:

```bash
pwd
```

It prints the repository root in Bash notation, normally `/c/Users/benpe/ClashBot`. The exercise runner starts here even if another terminal window is elsewhere. A drive's displayed letter casing can differ; the important fact is that this is the ClashBot root.

`printf` prints text. The quoted text stays together; `\n` asks for a new line. We use one simple form throughout these first exercises:

```bash
printf 'ClashBot\n'
```

It prints `ClashBot` on one line. The single quotes belong to the shell instruction and are not printed. The final newline moves the next output to a new line. A **comment** begins with `#` and describes the code without being executed.

```bash
# This is a route, not a request to open the file.
printf 'pipeline/__init__.py\n'
```

It prints `pipeline/__init__.py`. Printing a path does not read the file, run it, or establish that it exists. That distinction will matter when we assess evidence.

`ls -d` displays the named item itself. Here `-d` is an option that keeps a directory from being expanded into a listing of its children. Give an exact name after a space:

```bash
ls -d pipeline/
```

It prints `pipeline/` when that folder exists. Unlike the previous `printf`, this command checks a real named item. A mistyped path produces an error instead. A02 explains options and errors in more detail.

## 4. Text is not the same as a program

A **text file** stores readable characters. A **binary file** stores bytes intended for a particular program, such as an image viewer or a model loader. A **byte** is a small unit of stored information. Both kinds occupy disk space, but an ordinary editor cannot meaningfully display every format.

Python source is text that an interpreter can execute. A log is text recording events. A Markdown document is text intended for a reader. They can all contain words like "play," but opening a document does not play a card. Running a script may perform actions; reading its source is a different operation.

A trained model can be stored as a binary artifact. An **artifact** is a file produced or preserved by work, such as an experiment result. You cannot establish how well a model plays merely because an artifact exists. You need evidence from evaluation, and later lessons explain how to assess it.

The same caution applies to logs. A **log** is a record of events, often with times. A log can be old. A folder name may describe an experiment that did not succeed. A handoff can contain both earlier claims and later corrections. Location tells you where evidence lives, not whether a claim is currently true.

## 5. Build a small mental map

Start with the question you are trying to answer. "Where is shared observation code?" suggests `pipeline/`. "What was recorded about recent work?" suggests `HANDOFF.md`. "Where are L74 experiments?" suggests the named scratchpad folder. Do not search every file merely because you have not yet learned a narrower route.

An **observation** is information the bot receives about a game. An **action** is a choice it makes, such as playing a card. Live observations originate from the emulator workflow; simulator observations originate from a software game model. Shared code may translate both into a representation a learning program can use.

You do not need to understand that representation today. The useful habit is separating an area's purpose from the details inside it. Sketch four boxes on paper labeled handoff, shared code, deck area, and experiments. Put the four verified paths beside them. That map is more useful than memorizing a long directory listing.

## Before the exercises: trace each route

For each path you write, say its starting folder aloud. A relative route without a starting folder is incomplete information. Next, identify the final component and decide whether it names a file or folder. Finally, distinguish "I printed this spelling" from "I checked this item exists." These are different claims.

The first exercise asks for a root-relative document path. The second asks for a real directory check. The third asks you to translate an absolute Windows route into Git Bash notation. The fourth asks you to reason about a parent directory. None requires starting the emulator, opening a model, or running a training program.

If an answer fails, change one thing and try again. For a path exercise, inspect spelling, capitalization, separators, and the requested starting point. Do not add extra status text when the task requests one exact line. Later you will learn more flexible output checks; today a narrow response makes mistakes easy to locate.

## Common mistakes

- Confusing the repository root with the root of the C drive.
- Treating a printed filename as evidence that the file exists.
- Using a relative route without checking its starting directory.
- Assuming every text file is executable code.
- Reading a historical heading as a statement of current runtime state.
