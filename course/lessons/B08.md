## 1. A module supplies names

A **module** is a unit of Python code that can be imported. Many modules correspond to a `.py` file. Some supplied modules are implemented differently, but you use their exported names through the same import mechanism. A **name** is an identifier such as `json`, `loads`, or `counts`.

```python
import json

row = json.loads('{"derived":"WIN"}')
print(row["derived"])
```

It prints `WIN`. The import binds the name `json` to the module. The dot in `json.loads` accesses a name provided by that module. You can read it aloud as “the loads function in json”. It is not a path separator and it does not mean that the function lives in your current script.

A **namespace** is a collection of names and the values they refer to. Keeping functions under the `json` namespace makes their origin visible. This matters when a large project uses several helpers with similar names, such as different loading functions for observations and model files.

## 2. Import a particular function

The alternative form `from module import name` binds a selected name directly in your script. Here `math` is a supplied mathematics module, and **ceil** means round upward to the nearest integer.

```python
from math import ceil

print(ceil(2.2))
print(ceil(2.0))
```

It prints `3` and `2`. This is useful when converting a duration into a minimum whole number of ticks. A **tick** is one update step in a simplified simulation. If a step lasts half a second, covering 1.1 seconds requires three steps, not two.

```python
from math import ceil

def ticks_needed(seconds, tick_seconds):
    return ceil(seconds / tick_seconds)

print(ticks_needed(1.1, 0.5))
```

It prints `3`. The calculation is a teaching example; it does not establish either engine's actual tick duration. `from math import ceil` gives you the name `ceil`, not necessarily the name `math`. Keep the import style consistent with the way you call the function.

Avoid `from module import *` while learning. The star asks for many names at once and makes it harder to see their source. When an unfamiliar function appears deep in a ClashBot file, an explicit import helps you trace it back to its definition.

## 3. Use an alias deliberately

An **alias** is another local name for the same imported object. The keyword `as` introduces it. An alias can shorten a long module name, but should still make the source understandable.

```python
import json as data_json

print(data_json.loads('{"card":"Xbow"}')["card"])
print(data_json.__name__)
```

It prints `Xbow` and `json`. The special attribute `__name__` records the module's name. Assigning the alias did not create a new decoder or change the format. It only changed how this script refers to the imported module.

You will eventually see conventional aliases such as `np` for NumPy. Those conventions are not magic Python syntax; they are ordinary aliases. We will not use arrays here because the course introduces them in Part C. Knowing that an alias points to a module is enough to follow the import lines for now.

## 4. Separate a definition from a call

Importing a module executes its top-level statements. **Top level** means statements outside a function or class body. Defining a function creates it but does not execute its body. Calling it executes the body.

Imagine this small teaching module named `report_math.py`:

```python
print("loading report helpers")

def decided_rate(wins, losses):
    if wins + losses == 0:
        return None
    return wins / (wins + losses)
```

Executing or first importing this hypothetical module prints `loading report helpers`. It does not print a win rate because the function has not been called. These are illustrative files, not instructions to add files to the project.

In a caller, the following would use that hypothetical module:

```python
import report_math

print(report_math.decided_rate(3, 1))
```

On its first import in a fresh process, this prints `loading report helpers` followed by `0.75`. The helper's input is counts, so it does not need to know where the matches were stored. This separation lets tests check the calculation without reading a live log.

Python normally remembers an imported module within one process. Repeating the same import usually reuses that module instead of rerunning all its top-level code. A new exercise run starts a new process, so do not rely on state left behind by a previous run.

## 5. Keep script behaviour behind an entry guard

An **entry point** is the place execution begins for a particular use of a program. Python assigns `__name__` the value `"__main__"` when a file is run as the main script. When it is imported normally, its name identifies the module instead.

```python
def main():
    print("report requested")

if __name__ == "__main__":
    main()
```

When run as a script, this prints `report requested`. When placed in an imported module, this guarded call prints nothing. The function is still defined and can be called deliberately. The conditional is called an **entry guard** because it limits when the script action runs.

The guard does not prevent other top-level statements from executing. A file can still read data, construct objects, or launch work above the guard. Therefore “it has a main guard” is not enough to prove that importing an operational file has no side effects. A **side effect** is a change outside the returned value, such as writing a file or starting a process.

## 6. A package organises modules

A **package** groups modules under a shared name. A regular package directory contains an `__init__.py` file. Python also supports packages without that marker in some arrangements, but the concrete `pipeline/` package here has one.

The dotted name `pipeline.decision_options` refers to a module inside `pipeline`. A line such as `from pipeline.decision_options import DecisionOptions` selects a name from that module. B09 explains the class that name refers to. You do not need to use the class to understand the route through the package.

Keep three ideas separate: a filesystem directory, a Python package name, and an imported value. They often line up, but they are not identical. A directory can contain notes and outputs that are not Python modules. A module can export many values. Importing one exported name does not copy the whole source into your script.

The package's `__init__.py` executes when the regular package is first imported. Some projects use it to collect convenient names. In ClashBot's inspected `pipeline/__init__.py`, the contents are a descriptive string rather than a collection of eager imports. That makes the package boundary easier to inspect.

## 7. Understand the search path

The **module search path** is the list of locations Python searches when locating imports. Python exposes it as `sys.path`. The `sys` module supplies information about the running interpreter.

```python
import sys

print(isinstance(sys.path, list))
print(isinstance(sys.executable, str))
```

It prints `True` and `True`. The built-in `isinstance(value, type)` asks whether a value has a particular type. `sys.executable` names the interpreter executable. We print type checks rather than a machine-specific path so the result is predictable across installations.

When a Python script is launched by filename, the script's directory is normally an important search location. That is not always the repository root. The course runner writes your answer to a temporary file but sets its working directory to the root. Consequently, a relative file read may succeed while a local package import needs additional setup. File lookup and module lookup are related but distinct mechanisms.

**PYTHONPATH** is an environment setting that adds locations to Python's module search path. A launch command for a remote training machine may include the repository root there so workers can import `pipeline`. This does not install dependencies, select a checkpoint, or start training by itself. It changes where Python searches.

An **environment variable** is a named setting passed to a process by its parent. You do not need to change one for this lesson. If an import fails, first identify the interpreter, the module name, and the existing search arrangement. Guessing a global path change can make one command work while hiding why another was wrong.

## 8. Read a module without importing it

Reading Python source with `open` gives you text. It does not execute the statements in that text. This is the right first step when inspecting operational scripts whose side effects you do not yet understand.

```python
with open("pipeline/__init__.py", encoding="utf-8") as source:
    description = source.read()
print("Deck-agnostic" in description)
```

For the inspected file, it prints `True`. **Deck-agnostic** means the shared code is intended not to depend on one particular deck. That description is a design statement in the file, not a guarantee that every helper has been tested with every deck.

Do not name a practice script `json.py` or `math.py` in a directory Python searches first. Such a file can **shadow** the supplied module, meaning Python finds your file instead of the intended one. A surprising import failure may therefore come from a filename collision rather than a missing installation.

## In the real project

The syllabus points to `pipeline/`. Its `pipeline/__init__.py` contains this complete short excerpt:

```python
"""Deck-agnostic observation pipeline shared by icebow and hogeq (S0 step 2, L63).

Nothing here imports either deck's ``clashrl`` copy at module load; ``obs_contract.from_live`` pulls
``BoardWarp`` from ``icebow/src/clashrl/actions.py`` lazily (the deck yaml names the src dir).
"""
```

It prints nothing. Line 1 opens a **docstring**, a descriptive string attached to the module. Line 2 separates paragraphs. Line 3 says deck-specific code is not imported here immediately. Line 4 describes a **lazy import**, an import postponed until the relevant functionality needs it. Line 5 closes the docstring.

For contrast, `pipeline/decision_options.py` contains this exact import line:

```python
from dataclasses import dataclass, replace
```

It prints nothing. The line imports two specific names from one supplied module. B09 will use `dataclass`; `replace` creates a modified copy of a data record. Recognising the source of these names is enough today. Do not import the whole decision module merely to inspect this one statement, because its other imports bring in more dependencies.

## Common mistakes

- Calling `json.loads` after importing only `loads` without binding `json`.
- Assuming the working directory and module search path are identical.
- Treating an entry guard as protection against every top-level side effect.
- Naming a practice file after a standard-library module.
- Changing the search path before checking which interpreter is running.
