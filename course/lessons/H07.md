# H07 · Counterfactual credit: forking the simulator

**Time:** about 5 hours · **You will be able to:** compare paired simulator continuations, calculate fork advantages, and audit a misleading training signal.

## Why this matters for ClashBot

A match loss does not identify which decision caused it. ClashBot might fire Rocket, defend poorly afterwards and lose, even though the Rocket itself was reasonable. A controlled what-if comparison can ask what would have happened after waiting from the same state.

`pipeline/cf_credit.py` constructs these comparisons by forking simulator state. The report `scratchpad/gauntlet/L74/plan1026/cf/P4_AUDIT.md` then examines the resulting incentive. It found that several Rocket alternatives were priced negatively in that particular simulator and continuation policy.

This is a lesson in both algorithms and interpretation. We will calculate the signal and then ask what it actually establishes. The exercises use copied Python state and tiny return arrays, so they need neither the Java engine nor any live match interaction.

## 1. Define the question at a decision point

A **counterfactual** asks what would happen under an alternative action while holding the relevant starting conditions fixed. A **fork** is an independent copy of the state from which that alternative can be simulated. The decision point is the **root** of the comparison.

For a Rocket decision, candidates might include the actual action, waiting and a different affordable card. Each candidate should begin with the same towers, units, elixir, hand, clock and opponent information. Otherwise the difference could be caused by different starting conditions.

```python
import copy
root = {"elixir": 9, "units": [{"hp": 100}]}
branch = copy.deepcopy(root)
branch["elixir"] -= 6
branch["units"][0]["hp"] = 80
print(root["elixir"], root["units"][0]["hp"])
```

It prints `9 100`. A **deep copy** duplicates nested mutable objects. A shallow dictionary copy would still share the inner unit dictionary. The unchanged root is essential: later candidates must not inherit damage caused by the first candidate.

In a real simulator, copying the visible board is insufficient. Hidden queues, random-generator states and policy memory can influence future decisions. The source's fork contract includes these states because replay identity depends on them.

## 2. Pair the randomness, not just the starting board

**Common random numbers**, abbreviated CRN, means giving compared candidates corresponding random continuations. If one continuation happens to be easy, it should be easy for both candidates under the defined coupling. This can reduce noise in their difference.

Suppose the actual action gets returns [0.2, 0.8, 0.4] and waiting gets [0.1, 0.7, 0.3] under three paired continuations. Compare each pair before averaging.

```python
actual = [0.2, 0.8, 0.4]
wait = [0.1, 0.7, 0.3]
differences = [w - a for w, a in zip(wait, actual)]
print([round(x, 2) for x in differences])
```

It prints `[-0.1, -0.1, -0.1]`. The absolute returns vary widely, but the paired difference is stable. With independent random draws, variation in scenario difficulty could obscure the action effect.

CRN does not force trajectories to remain identical after different actions. The actions are meant to change the future. It aligns random sources under a declared scheme. A candidate that consumes random draws differently can complicate that coupling, so an implementation should test unchanged-action replay explicitly.

Pairing can reduce variance when outcomes are positively correlated. It is not a universal guarantee. Measure the variance of differences rather than claiming a benefit solely because the seeds match.

## 3. Estimate continuation value and candidate advantage

A **rollout** is a simulated continuation. A **horizon** is how far the rollout runs before it stops. If the match ends, use the discounted terminal outcome. If the horizon ends first, a value estimate supplies the remaining return.

Write Q[i,k] for candidate i's estimated return under continuation k. Average across k to get a candidate score. Then subtract the mean candidate score to form an advantage relative to the candidate set.

```python
scores = [0.4, 0.1, -0.2]
baseline = sum(scores) / len(scores)
advantages = [score - baseline for score in scores]
print([round(a, 2) for a in advantages])
```

It prints `[0.3, -0.0, -0.3]`. The displayed negative zero is a tiny floating-point rounding residue. Mathematically these advantages sum to zero. The middle candidate is average within this set; that does not mean it is globally optimal.

The audit report often uses a different presentation: alternative minus the actual policy action. That pairwise contrast is easy to read but is not identical to the candidate-mean training advantage. Label which quantity you are plotting.

The candidate set matters. Adding an extremely bad alternative changes the mean baseline and therefore each advantage. It should not be confused with discovering a better actual action. Preserve the candidate-generation rule across comparisons and report coverage.

## 4. Audit the horizon and the continuation policy

A **horizon audit** compares truncated estimates with continuations run to the true match end. A short horizon might miss Rocket's later defensive cost. A biased value model might overestimate a tower-damage advantage. Both can change the sign of a training signal.

```python
horizon_delta = -0.24
terminal_delta = -0.22
print(horizon_delta < 0 and terminal_delta < 0)
```

It prints `True`. In this numerical example both estimates agree in sign. That weakens a simple explanation that the negative sign is caused only by truncation. It does not prove the simulator or opponent is faithful to humans.

A **continuation policy** is the policy used after the forced candidate action. If the learner cannot defend after spending six elixir, the fork measures that weakness too. The question is not “Could a perfect player make Rocket work?” It is “How does this candidate work with these continuation policies?”

This distinction makes counterfactual credit actionable but limited. It estimates the consequences of changing an action within a particular system. Improving later defence, opponent realism or engine fidelity can change the estimate.

Samples from one match share conditions. For uncertainty, the audit clusters by match rather than pretending every fork is independent. A **cluster** is a group of related observations treated together when resampling. Part C's uncertainty lessons apply here with the match as the resampling unit.

## 5. Interpret the Rocket finding in its own units

The audit's return scale uses approximately +1 for a win and -1 for a loss. Under a no-draw, undiscounted interpretation, a return difference of -0.24 corresponds to a win-probability difference of -0.12, or minus twelve percentage points. It is not minus twenty-four points.

```python
delta_return = -0.24
delta_probability = delta_return / 2
print(round(100 * delta_probability, 1))
```

It prints `-12.0`. The conversion requires the reward convention. Do not apply it blindly to shaped, discounted or mixed rewards.

The report's negative Rocket-family results do not establish that human Rocket cycling is bad. They describe the tested simulator, candidates, policies, states and sampling scheme. An audit is valuable precisely because it can reveal that a training signal points away from a desired capability.

Increasing the weight of a negative signal makes that disagreement stronger. A responsible next step is to investigate the cause: state selection, own defence, opponent behaviour, mechanics or estimator quality. Flipping the sign by hand would conceal the disagreement.

Also inspect which decisions are selected for forks. A **trigger** is a condition that requests a fork, such as a Rocket being available. If only easy or unusual states trigger, the average says little about all Rocket opportunities. Include counts, clock phases and candidate availability in the report.

## Practice plan

The first exercise makes independent nested-state branches. Change one branch and verify that the root and another branch remain unchanged. Next compute paired deltas and reject unequal lengths instead of silently truncating with zip.

The third exercise builds candidate-mean advantages from a rectangular return table. The fourth reports both horizon and terminal signs, using a deliberately narrow label: agreement or disagreement. It does not decide which strategic behaviour is correct.

After finishing, explain why matching the actual-action fork to the original rollout is a useful positive control. If the supposedly unchanged fork cannot reproduce the continuation, differences between alternatives cannot yet be trusted.

## Common mistakes

- Copying only the visible board while sharing hidden mutable state.
- Comparing unpaired means and calling the design paired.
- Confusing candidate-mean advantage with alternative-minus-actual audit output.
- Converting a -0.24 return difference into -24 percentage points.
- Treating a negative simulator estimate as a universal fact about human strategy.
