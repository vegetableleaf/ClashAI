## Why this matters for ClashBot

A Clash Royale board contains different kinds of information: cards, moving units, positions, towers, and remembered plays. The model in `pipeline/model_v3.py` uses learned lookup tables and a transformer encoder to combine information. Understanding this design helps you read how an Icebow decision can depend on several parts of the board at once.

F08 taught tensors and modules. We now use them to build representations and weighted lookups. All examples remain small CPU calculations. A tensor with the correct shape does not establish that an observation from the phone emulator means the same thing as an observation from RoyaleSim or crforge.

This lesson explains model components, not reinforcement-learning updates. The same kinds of components can support imitation learning or reinforcement learning. How a model is trained and what its structure is are separate questions.

## 1. Categories need representations

A **category ID** is an integer naming an item. ID 2 does not mean a card is twice as strong as ID 1. Feeding arbitrary IDs as ordinary measurements would create relationships that the numbering scheme never promised.

An **embedding** is a learned vector representing a category. An **embedding table** stores one vector per ID. Looking up a card means selecting its row. Training adjusts the selected entries through gradients, just as it adjusts linear-layer weights.

```python
import torch
table = torch.tensor([[1.0, 0.0], [0.0, 1.0], [0.5, 0.5]])
ids = torch.tensor([2, 0, 2])
print(table[ids].tolist())
```

This prints `[[0.5, 0.5], [1.0, 0.0], [0.5, 0.5]]`. Repeated IDs retrieve the same row. The two coordinates are learned features; neither is automatically an elixir cost or damage value.

A teaching vocabulary might map Knight to zero, Tesla to one, and X-Bow to two. This mapping is local to the example. It is not a claim about the project's catalogue IDs. Model weights and their vocabulary mapping must remain compatible.

## 2. Register a learned lookup

PyTorch's `nn.Embedding(count, width)` creates a trainable table. The count is the number of possible IDs. Width is the number of numerical coordinates in each vector.

```python
import torch
from torch import nn
embedding = nn.Embedding(3, 4)
ids = torch.tensor([[0, 1], [2, 0]], dtype=torch.long)
vectors = embedding(ids)
print(tuple(vectors.shape))
print(embedding.weight.numel())
```

This prints `(2, 2, 4)` and `12`. The first two dimensions come from the ID array. The new final dimension contains the vector. IDs must be integers within the table's range. Negative IDs are not a convenient missing-card convention.

A **padding** entry represents unused space when examples have different lengths. Padding requires an explicit agreement between the data and model. Even if the embedding row is zero, a later attention operation may still attend to it unless it is masked. Never assume a zero input automatically means ?ignore this.?

## 3. Weighted lookup is the core of attention

**Attention** combines information using weights that depend on the current input. A **query** is a vector describing what information is being sought. **Keys** are vectors compared with the query. **Values** are vectors whose information will be combined.

These are mathematical names, not files. A simple picture is an X-Bow-related query comparing itself with representations of enemy units and buildings. The learned similarities determine how much each value contributes. This picture helps intuition but does not prove any individual trained attention head has that exact tactical role.

```python
import numpy as np
query = np.array([1.0, 0.0])
keys = np.array([[1.0, 0.0], [0.0, 1.0]])
scores = keys @ query
print(scores.tolist())
```

This prints `[1.0, 0.0]`. The dot product gives a larger score to the first key. Scores are not yet weights: they may be negative and need not sum to one.

## 4. Softmax turns scores into weights

Recall **softmax** from F05: exponentiate scores and divide by their sum. Subtracting the largest score before exponentiating improves numerical stability without changing the probabilities.

```python
import numpy as np
scores = np.array([1.0, 0.0])
exp_scores = np.exp(scores-scores.max())
weights = exp_scores/exp_scores.sum()
values = np.array([[10.0, 0.0], [0.0, 20.0]])
answer = weights @ values
print(np.round(weights, 3).tolist())
print(np.round(answer, 3).tolist())
```

This prints `[0.731, 0.269]` and `[7.311, 5.379]`. The answer is a mixture, not necessarily one original value. If both scores were equal, both weights would be one half.

**Scaled dot-product attention** divides similarity scores by the square root of vector width before softmax. Dot products tend to grow in magnitude with width; scaling helps keep the resulting probabilities from becoming excessively concentrated for that reason alone.

```python
import numpy as np
scores = np.array([2.0, 0.0])
width = 4
print((scores/np.sqrt(width)).tolist())
```

This prints `[1.0, 0.0]`. In an actual layer, the width is the size of each comparison vector. It is not the number of cards in a deck or the number of examples in a batch.

## 5. Self-attention lets items exchange information

**Self-attention** creates queries, keys, and values from the same collection of input representations. Every item can gather information from other items. A board representation of an enemy troop can therefore be updated using nearby structures or global information, provided those inputs are encoded and allowed by the mask.

The query, key, and value vectors normally come from separate learned linear transformations. A **multi-head attention** layer performs several such comparisons in parallel, using smaller vector spaces, then combines their outputs. An attention head is not the same as an output head for card or cell selection in F10.

Multiple heads provide capacity to learn different relationships. They do not guarantee a neat assignment such as ?head one watches the left lane.? Inspecting one attention weight is not a complete explanation of the eventual action: other layers and values also matter.

## 6. A mask excludes unavailable entries

A **mask** specifies entries that must not contribute. For attention, unwanted scores can be replaced by negative infinity before softmax. Their exponentials become zero. At least one score must remain available.

```python
import torch
scores = torch.tensor([2.0, 100.0, 1.0])
allowed = torch.tensor([True, False, True])
weights = torch.softmax(scores.masked_fill(~allowed, float("-inf")), dim=0)
print(round(weights[1].item(), 3))
print(round(weights.sum().item(), 3))
```

This prints `0.0` and `1.0`. The `~` operator reverses a boolean tensor, so it identifies disallowed entries here. Masking after softmax without renormalising would leave weights summing to less than one.

For a sequence model predicting the next card, a **causal mask** hides future positions. Causal means a prediction can depend only on information already available at that time. For a board encoder using one present snapshot, a blanket triangular sequence mask may be inappropriate: many current board items are simultaneously visible. Choose the mask from the task's information boundary.

## 7. Position must be supplied

Attention alone does not know that one item is near the bridge and another is behind the king tower. A **positional representation** supplies location or ordering information. For play history this might mean sequence position. For board units it can mean coordinates.

A **patch** is a region of the board treated as one representation. The project's model defines 9 by 16 patches and 36 by 64 half-tile placement cells. A patch is therefore not a single action cell. Confusing these resolutions would misread the model's placement logic.

Remembered past actions also need consistent ordering and time information. A summary of earlier public plays is useful; a feature accidentally extracted from after the action is **future leakage**, information unavailable when making the decision. Excellent held-out accuracy cannot rescue a leaked task.

## 8. Assemble an encoder layer

A **transformer encoder layer** combines self-attention with a small feed-forward network, residual connections, and normalisation. A **residual connection** adds a component's input to its transformed output. **Layer normalisation** rescales intermediate coordinates using their mean and variance, with learned adjustments.

These operations help the network train and preserve useful information through several layers. For this lesson, focus on the input/output contract rather than deriving every normalisation derivative.

```python
import torch
from torch import nn
torch.manual_seed(3)
layer = nn.TransformerEncoderLayer(
    d_model=8, nhead=2, dim_feedforward=16,
    dropout=0.0, batch_first=True)
x = torch.zeros(2, 3, 8)
layer.eval()
with torch.no_grad():
    y = layer(x)
print(tuple(y.shape))
print(torch.isfinite(y).all().item())
```

This prints `(2, 3, 8)` and `True`. `batch_first=True` means dimensions are examples, items, features. `d_model` is representation width. `nhead` is the number of attention heads, and width must be divisible by that count. `dim_feedforward` is the hidden width of the internal MLP.

An encoder stack repeats encoder layers. Repetition preserves the outer shape while allowing more transformations. The shape check tells you the contract holds, not that the random model understands a battle.

## 9. Connect each exercise to a reading skill

First, implement table lookup. Check repeated IDs and several positions, not only a single row. Next, compute scaled attention from a query, keys, and values. Equal scores should produce the mean of the values, a strong sanity check that needs no trained model.

Then add masking and explicitly reject an all-false mask. This is an exercise in handling an undefined case honestly. Finally, run a tiny encoder layer and verify that a batch's item and feature dimensions survive.

When reading the real excerpt, identify what is a learned parameter, what is a configuration choice, and what is a tensor shape. These categories answer different questions. A larger embedding width changes parameter count. More board items change computation and memory. A different mask changes which information is available. None of them alone establishes that the model will defend an X-Bow more effectively in a closed-loop match.

## Common mistakes

- Treating catalogue IDs as numerical measures of strength.
- Mixing an attention head with an action-output head.
- Forgetting that padding needs a compatible mask.
- Letting a next-card example include its own future label as an input.
- Confusing patch resolution with placement-cell resolution.
