## 1. Random variables

A **random variable** is a numerical description of an uncertain outcome. Let W be one for a decisive Icebow win and zero for a loss. A **probability** is a number between zero and one expressing how likely an event is under a stated model. A **Bernoulli variable** takes one with probability p and zero with probability 1-p. Our model uses only decisive games; missing outcomes never become zeros. A known draw is a separate outcome and must be handled before applying this two-outcome model.

```python
p = 0.6
print(p)
print(1-p)
print(round(p + (1-p), 3))
```

**Output:** `0.6`, `0.4`, and `1.0`.

These probabilities sum to one because win and loss exhaust the modeled outcomes. This is a toy probability, not an estimate from the real log. An estimated probability comes from data and has uncertainty, which C05 covers. Do not confuse the value chosen to simulate a bot with evidence that the live bot has that value.

## 2. Count several trials

A **trial** is one modeled observation. **Independent** trials do not influence one another's outcomes under the model. A **binomial distribution** describes the number of successes in n independent Bernoulli trials with the same p. It is a useful first approximation, not a universal description of live matchmaking. Consecutive matches may share an opponent population, software version, fatigue pattern, or time period. Those relationships can make the independence or constant-probability assumption doubtful. We first calculate the probability of one particular sequence, then distinguish it from any sequence with the same number of wins.

```python
p = 0.6
specific = p*p*(1-p)
print(round(specific, 3))
print(round(3*specific, 3))
```

**Output:** `0.144` and `0.432`.

The specific sequence WIN, WIN, LOSS has probability .144. Three sequences contain exactly two wins: WWL, WLW, and LWW. Their probabilities add to .432. Multiplying probabilities assumes independence. Counting the alternative orders is essential; otherwise you calculate one arrangement instead of a total count.

## 3. The binomial formula

A **combination** counts ways to choose k positions from n without considering selection order. Python's math.comb(n,k) calculates this count using integers. The binomial probability for exactly k wins is comb(n,k) times p raised to k times (1-p) raised to n-k. The **exponent** operator ** repeats multiplication. A **probability mass function** assigns a probability to each possible discrete count. It should sum to one across every possible count. That sum is a useful independent test of an implementation.

```python
from math import comb
n = 3
p = 0.6
prob = comb(n,2)*p**2*(1-p)**(n-2)
print(round(prob, 3))
print(round(sum(comb(n,k)*p**k*(1-p)**(n-k) for k in range(n+1)), 6))
```

**Output:** `0.432` and `1.0`.

At p=0 all mass is at zero wins; at p=1 it is at n wins. These boundaries are useful tests. For very large n, direct powers can lose numerical precision; our small exercises do not require a specialist numerical routine. We will use only tiny values for exact tail calculations later.

## 4. Expected value and spread

The **expected value** is a probability-weighted average over possible outcomes. It is a long-run average under the model, not a promised result for one run. For n Bernoulli trials, expected wins are n*p. **Variance** measures average squared distance from the expected value; binomial variance is n*p*(1-p). **Standard deviation** is its square root, bringing the spread back into units of wins. A reward can have its own expected value: if a toy win pays two points and a loss costs one, expectation is 2*p - (1-p). Real reinforcement-learning rewards are introduced properly in Part H.

```python
from math import sqrt
n, p = 20, 0.6
print(n*p)
print(round(sqrt(n*p*(1-p)), 3))
print(round(2*p - (1-p), 3))
```

**Output:** `12.0`, `2.191`, and `0.8`.

The expected count is twelve but an actual sample contains an integer count that varies. A reward expectation of .8 points does not mean the probability of winning is .8. Keep units attached to calculations: wins, probability, and reward points answer different questions.

## 5. Simulate reproducibly

A **pseudorandom generator** is a deterministic algorithm that produces a sequence resembling random draws. A **seed** selects its initial state. Python's random.Random creates a local generator, avoiding accidental changes to shared global state. Its random method returns a number from zero up to but excluding one; comparing that number with p creates a Bernoulli sample. NumPy's default_rng creates its own generator and binomial draws counts directly. A seed alone is insufficient for an experiment record: generator implementation, draw order, code, and data versions also matter.

```python
import random
import numpy as np
def sample(seed):
    rng = random.Random(seed)
    return [int(rng.random() < .6) for _ in range(5)]
print(sample(7) == sample(7))
rng = np.random.default_rng(7)
counts = rng.binomial(10, .6, size=4)
print(counts.shape)
print(bool(((counts >= 0) & (counts <= 10)).all()))
```

**Output:** `True`, `(4,)`, and `True`.

The underscore is an ordinary loop variable used when its value is not needed. The NumPy ampersand combines Boolean masks element by element; parentheses keep the comparisons grouped. Do not demand identical sequences from Python and NumPy: they are different generator interfaces. Reproducibility means rerunning the same specified procedure.

## Common mistakes

- Treating an expected value as a guaranteed outcome.
- Assuming all live games share one fixed win probability.
- Resetting the random seed inside every iteration.
- Using a seed as a substitute for recording code and table versions.
- Calling repeated dependent observations independent games.
