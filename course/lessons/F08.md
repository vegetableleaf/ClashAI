## 1. A tensor has values, shape, type, and device

A **tensor** is an array managed by PyTorch. Like a NumPy array, it has a shape and a numerical type, called its **dtype**. It also has a **device**, the processor on which its values live. The **CPU** is the computer's general-purpose processor. A **GPU** handles many numerical operations in parallel. **CUDA** is the interface PyTorch uses for supported NVIDIA GPU operations.

```python
import torch
x = torch.tensor([[0.6, 0.8], [0.3, 0.4]], dtype=torch.float32)
print(tuple(x.shape))
print(x.dtype)
print(x.device)
```

This prints `(2, 2)`, `torch.float32`, and `cpu`. Each row represents one observation; the columns are our teaching elixir and tower-health features. **Float32** stores each number in four bytes. It can represent fractions, but arithmetic still rounds.

For a classifier, features normally use floating-point tensors and class labels use integer tensors. `torch.long` is PyTorch's usual 64-bit integer dtype. A class label such as 2 names a category; it is not a measurement twice as large as category 1.

Use `tensor.to(device)` to move a tensor, and `model.to(device)` to move a model. Both must agree. Our exercises explicitly use CPU, so they work in the installed course environment. Do not assume a CUDA device exists.

## 2. Autograd records a computation

**Autograd**, short for automatic differentiation, records operations needed to compute gradients. Setting `requires_grad=True` asks PyTorch to track how a tensor contributes to later results.

```python
import torch
w = torch.tensor(0.0, requires_grad=True)
loss = 0.5 * (2*w - 1)**2
loss.backward()
print(w.grad.item())
```

This prints `-2.0`, matching F07. `backward()` traverses the recorded calculation backwards. The `.grad` attribute holds the derivative. `.item()` converts a one-element tensor to an ordinary Python number for reporting.

Gradients accumulate by default. Calling backward on another newly computed loss adds its gradient to the existing one. This is useful for micro-batching in F12, but usually wrong if you meant to start a new update. Clear old gradients before each ordinary training step.

Do not turn a loss into a Python number before backpropagation. `loss.item()` is useful for a log, but the resulting number no longer carries the computation. Similarly, rebuilding a tensor from detached numbers will not reconnect it to earlier operations.

## 3. A module owns trainable layers

An **nn.Module** is PyTorch's base class for a model component. It stores child layers and exposes their trainable parameters. The `forward` method describes the computation; calling the object runs that method through PyTorch's machinery.

```python
import torch
from torch import nn

class TinyCardModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.output = nn.Linear(2, 3)

    def forward(self, x):
        return self.output(x)

model = TinyCardModel()
print(tuple(model(torch.zeros(4, 2)).shape))
print(sum(p.numel() for p in model.parameters()))
```

This prints `(4, 3)` and `9`. `super().__init__()` initialises the module's registration machinery. `nn.Linear(2, 3)` owns six weights and three biases. `numel()` returns the number of stored elements. Four input rows become four sets of three class scores.

These scores are **logits**, unconstrained numbers before softmax. A model can output negative logits. They become probabilities only after normalisation. The three classes in this example are teaching categories, not a complete Icebow hand.

## 4. Choose a loss and an optimiser

For classification, `nn.CrossEntropyLoss()` combines a stable log-softmax with the negative log-likelihood from F05. Pass raw logits and integer labels. Do not apply softmax first: the loss already performs the needed transformation.

An **optimiser** updates parameters using gradients. **Adam** keeps moving estimates of gradient direction and scale to adjust its updates. You do not need Adam's full derivation to use it correctly, but you must still choose a learning rate and assess held-out results.

```python
import torch
from torch import nn
logits = torch.tensor([[0.0, 0.0]])
labels = torch.tensor([1], dtype=torch.long)
loss = nn.CrossEntropyLoss()(logits, labels)
print(round(loss.item(), 4))
```

This prints `0.6931`. Equal scores give probability one half to the correct class, so the negative natural logarithm is about 0.6931. For batches, the default loss is the mean across rows.

The standard update order is: clear gradients, compute logits, compute loss, call backward, then step the optimiser. A **training loop** repeats that sequence. An **epoch** is one pass through the training dataset; an update may use only a smaller batch.

```python
import torch
from torch import nn
torch.manual_seed(7)
model = nn.Linear(1, 1)
optimiser = torch.optim.Adam(model.parameters(), lr=0.01)
x = torch.tensor([[1.0]])
target = torch.tensor([[2.0]])
optimiser.zero_grad()
loss = ((model(x)-target)**2).mean()
loss.backward()
optimiser.step()
print(all(p.grad is not None for p in model.parameters()))
```

This prints `True`. The exact loss depends on initialisation, so this example checks that both parameters receive gradients. A small loss after one update would not prove the model learned a general relationship.

## 5. Load data in batches

A **TensorDataset** groups tensors whose first dimension refers to the same examples. A **DataLoader** supplies batches from that dataset. Training often shuffles row order; evaluation normally keeps a stable order.

```python
import torch
from torch.utils.data import TensorDataset, DataLoader
x = torch.arange(6, dtype=torch.float32).reshape(6, 1)
y = torch.tensor([0, 1, 0, 1, 0, 1])
loader = DataLoader(TensorDataset(x, y), batch_size=4, shuffle=False)
print([len(labels) for features, labels in loader])
```

This prints `[4, 2]`. The final batch is smaller. When reporting an epoch's mean loss, weight each batch mean by its row count. Averaging 4-row and 2-row batch means equally would give the last two examples too much influence.

For these exercises, use the default single-process loader. Additional loading workers are not needed for a six-row in-memory table. In real training, loading, simulation, and transfer can all become bottlenecks; F12 considers those separately.

## 6. Training mode and evaluation mode differ

`model.train()` selects training behaviour. `model.eval()` selects evaluation behaviour for layers that behave differently, such as **dropout**, which randomly suppresses some intermediate values during training. Calling eval does not disable gradient recording.

Use `with torch.no_grad():` during evaluation when derivatives are unnecessary. It saves work and makes the intention clear. You still need eval mode for deterministic dropout behaviour. Our simple linear examples have no dropout, but learning both operations now avoids subtle bugs later.

```python
import torch
from torch import nn
model = nn.Linear(2, 3)
model.eval()
with torch.no_grad():
    logits = model(torch.zeros(5, 2))
print(logits.requires_grad)
print(tuple(logits.argmax(dim=1).shape))
```

This prints `False` and `(5,)`. `argmax(dim=1)` chooses the largest class score in each row. That is a predicted class, not a probability. Compare predictions with labels for accuracy, and retain logits for cross-entropy.

## 7. Save values and verify a round trip

A **state dictionary** maps parameter names to tensors. Save it using `torch.save(model.state_dict(), path)`. Loading requires rebuilding the same architecture and then calling `load_state_dict`. A state dictionary does not automatically document feature meanings, class ordering, or dataset splits.

A **checkpoint** is a saved training state. A full resumable checkpoint can also include optimiser state and progress. Here we save model values only. We use a temporary directory, which Python removes when the context ends.

```python
import hashlib
import tempfile
from pathlib import Path
import torch
from torch import nn

with tempfile.TemporaryDirectory() as folder:
    path = Path(folder) / "tiny.pt"
    source = nn.Linear(2, 3)
    torch.save(source.state_dict(), path)
    digest = hashlib.sha256(path.read_bytes()).hexdigest()
    restored = nn.Linear(2, 3)
    restored.load_state_dict(torch.load(path, map_location="cpu", weights_only=True))
    same = all(torch.equal(a, b) for a, b in
               zip(source.parameters(), restored.parameters()))
    print(same, len(digest))
```

This prints `True 64`. **SHA-256** is a hash function producing a fingerprint of file bytes. The digest is useful for identifying exactly which file was evaluated. It does not prove that a model is accurate or that its training data were suitable.

Only load the teaching file you just created. The `weights_only=True` option requests restricted weight loading; `map_location="cpu"` keeps the example portable. Comparing restored predictions adds a useful behavioural check alongside parameter equality.

## 8. Debug one boundary at a time

Start with input shape and dtype. Next check output shape. Then inspect whether loss is finite and gradients exist. Finally check whether repeated training reduces loss on a deliberately easy teaching dataset. This order separates data-contract mistakes from optimisation mistakes.

The exercises follow those boundaries. One computes a gradient with autograd. One builds a module. One trains a tiny line-fitting model. One saves and restores weights in temporary storage. Each task runs independently because the course runner starts a fresh process for every answer.

A correct loop is only one part of ClashBot's evidence chain. The model still needs compatible board features, action decoding, and evaluation against appropriate opponents. Keep the small program's conclusion narrow: you have shown that the mechanics work. You have not shown that the live bot should use these weights.

## Common mistakes

- Passing probabilities instead of logits to CrossEntropyLoss.
- Forgetting zero_grad and unintentionally accumulating updates.
- Assuming eval mode also turns autograd off.
- Loading values into a differently shaped model.
- Treating a hash match as evidence of playing strength.
