## Project contract

Predict one of eight teaching card IDs from the previous two IDs. Keep match boundaries intact. Train two embedding widths, select with validation NLL, then score the selected model on test. Report accuracy and NLL together.

A **sequence window** is a short consecutive segment used as input. Its target is the following card. For history [0,1] and label 2, the input must not include 2. A fixed-width history is simpler than a transformer but preserves ordering.

## Milestone 1: create past-only windows

For each target index from two onward, take exactly the two preceding cards. Never join the end of one match to the beginning of another.

```python
cards = [0, 1, 2, 3]
rows = [(cards[i-2:i], cards[i]) for i in range(2, len(cards))]
print(rows)
```

This prints `[([0, 1], 2), ([1, 2], 3)]`. The first history stops before its target. The two windows overlap, so they are related observations. This is why the next milestone splits matches rather than randomly separating windows.

Your function also accepts a width. Reject zero or negative widths. If the sequence has too few cards for a history plus target, return an empty list. Do not fill the missing past with later cards.

Acceptance: the hand-written sequence gives the expected rows, a short sequence gives none, and changing width changes history length without leaking the label.

## Milestone 2: generate and split whole matches

Create twelve matches, each containing twenty-four IDs. Match m begins at m modulo eight and cycles through all eight IDs. **Modulo**, the remainder operation %, wraps numbers back into zero through seven.

```python
matches = [
    {"match": m, "cards": [(m+t)%8 for t in range(24)]}
    for m in range(12)
]
print(len(matches))
print(matches[1]["cards"][:5])
```

This prints `12` and `[1, 2, 3, 4, 5]`. The generator is deliberately easy. It does not model elixir, uncertain hands, positioning, or human choices among available cards.

Use IDs 0?7 for train, 8?9 for validation, and 10?11 for test. This rule is declared before any comparison. The validation set chooses a setting; the test set reports performance after that choice is frozen.

Patterns repeat across synthetic matches. Separating matches prevents direct reuse of the same match but does not make this generated task realistic. Real histories might require additional separation by player, time, or replay source.

Acceptance: every match appears exactly once, in the specified group, with its full card sequence unchanged. Only after that grouping should you create windows.

## Milestone 3: register a small neural model

Use an eight-row embedding table with width d. Each of two input IDs retrieves a vector. Flatten the history and vector dimensions together, then apply a linear layer producing eight logits.

```python
import torch
from torch import nn
embedding = nn.Embedding(8, 4)
history = torch.tensor([[0, 1], [3, 4]])
vectors = embedding(history)
flat = vectors.flatten(start_dim=1)
print(tuple(vectors.shape))
print(tuple(flat.shape))
```

This prints `(2, 2, 4)` and `(2, 8)`. **Flattening** joins dimensions. Starting at dimension one preserves the batch dimension. The first four columns represent the earlier card, and the next four represent the later card.

Averaging those vectors would discard their order. The model might then be unable to distinguish two histories containing the same cards in reverse order. Flattening retains that distinction without introducing recurrent networks or additional architecture.

Derive NextCard from nn.Module and register layers named embedding and output. Forward returns logits, not probabilities, because cross-entropy applies its own normalisation.

Count parameters as 8*d embedding values plus 2*d*8 output weights plus eight biases. The total is 24*d+8: 104 at width four and 200 at width eight. These teaching models are tiny compared with F11's measured curve.

Acceptance: input shape (3,2) becomes output shape (3,8), both layers receive gradients, and parameter counts agree with the formula.

## Milestone 4: train one model

The provided tensors helper converts windows into integer tensors. Histories have shape examples by two; labels have one integer per example.

```python
import torch
x = torch.tensor([[0, 1], [1, 2]], dtype=torch.long)
y = torch.tensor([2, 3], dtype=torch.long)
print(tuple(x.shape), tuple(y.shape))
```

This prints `(2, 2) (2,)`. Embedding inputs and classification targets use integer IDs. The output logits use floating-point numbers.

Use one CPU thread and set seed 11 before constructing each model. Train with Adam at 0.05 for 100 full-batch updates. This fixed schedule avoids adding a second model-selection problem. The tiny dataset fits comfortably within the exercise time limit.

Use only train_matches inside train_model. Each update clears gradients, computes logits, computes cross-entropy, calls backward, then steps Adam. The function's steps argument controls how often this happens.

Acceptance: training NLL falls below the stated threshold on this easy pattern. The returned model keeps the requested architecture. A zero-step call leaves the seeded initial values unchanged, proving that the update count is respected.

A successful fit verifies mechanics and learnability of the generated relationship. It does not establish generalisation to real people. Keep that conclusion separate even if every synthetic training prediction is correct.

## Milestone 5: compare sizes, then freeze a choice

Train widths four and eight independently with identical schedules. Evaluate both on validation using eval mode and no_grad. Accuracy is the fraction of matching argmax labels. NLL is mean cross-entropy.

```python
import torch
logits = torch.tensor([[3.0, 0.0], [0.0, 3.0]])
labels = torch.tensor([0, 1])
accuracy = (logits.argmax(dim=1)==labels).float().mean().item()
nll = torch.nn.functional.cross_entropy(logits, labels).item()
print(accuracy, round(nll, 3))
```

This prints `1.0 0.049`. Perfect accuracy need not give zero NLL. The correct classes still receive probabilities less than one. NLL can distinguish two models with equal top-one accuracy.

Record width, parameter count, accuracy, and NLL for each validation run. Choose minimum (nll,params): lower NLL wins, and an exact tie favours fewer parameters.

```python
rows = [{"width":4, "params":104, "nll":0.2},
        {"width":8, "params":200, "nll":0.2}]
chosen = min(rows, key=lambda row: (row["nll"], row["params"]))
print(chosen["width"])
```

This prints `4`. The tie rule is fixed in advance. Do not use the test results to change it. After choosing, evaluate only the selected model on test and record the number of scored rows.

Acceptance: both model sizes appear in validation results, the counts are correct, the chosen width follows the rule, and the reported test metrics agree with an independent evaluation of the selected model.

A single seed is adequate for this mechanics project but inadequate for a strong scaling conclusion. A future comparison should repeat training seeds while keeping the split and selection rule fixed. Do not call a small one-seed NLL difference a demonstrated architecture advantage.

## Common mistakes

- Including the label in the history.
- Splitting overlapping rows instead of complete matches.
- Using a deck list as if it were a chronological sequence.
- Choosing the model using test scores.
- Presenting synthetic accuracy as evidence of live strength.
