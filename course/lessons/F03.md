# F03 · Calculus you actually need: slopes and gradients

**Time:** about 6 hours · **You will be able to:** estimate slopes, calculate simple gradients, and use small descent steps to reduce a toy loss.

## Why this matters for ClashBot

F01 trained a model by trying a few multipliers. ClashBot's models have far too many adjustable values to try every combination. Calculus provides local information about how a small parameter change affects loss. That information guides a training update.

The syllabus lists no source file here. We use the update sequence in `pipeline/train_gen.py` to connect the mathematics to actual training. You will implement the calculations in ordinary Python and NumPy. Automatic differentiation and PyTorch are taught properly in F08.

## 1. Change in output divided by change in input

A **slope** describes how much an output changes relative to an input. For a straight line, the slope is constant. Suppose a toy damage predictor multiplies a feature by three.

```python
def prediction(x):
    return 3*x + 2
change = (prediction(5)-prediction(4))/(5-4)
print(change)
```

**Output:** `3.0`.

Moving the input by one changes the output by three. Moving by one tenth would change it by three tenths. The ratio stays three.

For a curved function, the ratio depends on where and how far you move. A **derivative** is the local slope as the change becomes very small. It describes a function at a particular input value, not its average behaviour across every possible input.

The derivative does not predict the result of an arbitrarily large move. This limitation becomes important when choosing training step sizes.

## 2. A loss curve with a visible minimum

Consider L(w)=(w-3)², where w is a model parameter. A **minimum** is a point where the function is no larger than nearby values; here the global minimum occurs at three and has loss zero.

```python
def loss(w):
    return (w-3)**2
print([loss(w) for w in [1,2,3,4,5]])
```

**Output:** `[4, 1, 0, 1, 4]`.

The slope is negative to the left of three and positive to the right. A negative slope means increasing w locally decreases loss. A positive slope means decreasing w locally decreases loss.

For this function, the derivative is 2(w-3). You can verify its sign against the list above before worrying about algebraic notation.

```python
def derivative(w):
    return 2*(w-3)
print(derivative(1), derivative(3), derivative(5))
```

**Output:** `-4 0 4`.

A zero derivative is a **stationary point**. It need not always be a minimum: other functions have flat maxima or saddle points. Our quadratic is deliberately simple so the minimum is easy to see.

## 3. Numerical derivatives

A **finite difference** estimates a derivative using function values at nearby points. A **central difference** uses one point on each side: [f(w+h)-f(w-h)]/(2h).

```python
def loss(w):
    return (w-3)**2
w,h=1.0,0.001
estimate=(loss(w+h)-loss(w-h))/(2*h)
print(round(estimate,6))
```

**Output:** `-4.0`.

This estimate agrees with the analytical derivative. **Analytical** means calculated from a mathematical expression rather than by nearby numerical samples.

The choice of h matters. A large h measures behaviour over too wide a region. An extremely tiny h can subtract nearly equal floating-point values and lose precision. Use a moderate small value, such as 1e-5, for these smooth toy functions.

A **gradient check** compares a formula-based derivative with a finite-difference estimate. It is particularly useful after deriving a new loss. Agreement on several nontrivial points gives more evidence than checking only at a zero-gradient optimum.

## 4. Descend opposite the slope

**Gradient descent** adjusts parameters opposite the direction of increasing loss. In one dimension, the update is w_new = w - learning_rate × derivative(w). The **learning rate** controls step size.

```python
w=1.0
learning_rate=0.1
gradient=2*(w-3)
new_w=w-learning_rate*gradient
print(new_w)
print(round((new_w-3)**2,3))
```

**Output:** `1.4` and `2.56`.

The old loss was four, so this step improved it. Subtracting a negative gradient increased w, moving it toward three. The word “descent” refers to the loss value, not always to decreasing the parameter.

```python
w=1.0
for _ in range(20):
    w -= 0.1 * 2*(w-3)
print(round(w,3))
```

**Output:** `2.977`.

The updates approach the minimum. A finite number of steps need not land on it exactly. Use a tolerance when checking approximate convergence.

## 5. Too-large steps can increase loss

A local slope suggests a direction, but not a universally safe distance. Try the same quadratic with learning rate 1.5.

```python
w=1.0
new_w=w-1.5*2*(w-3)
print(new_w,(new_w-3)**2)
```

**Output:** `7.0 16.0`.

The step crossed the minimum and landed farther away. The loss rose from four to sixteen. A correct gradient does not guarantee a successful update for every learning rate.

When a training run becomes unstable, check numerical values, feature scales, and update size before assuming more steps will help. In our exercises the functions are tiny, so you can calculate the expected direction by hand.

A learning rate of zero leaves parameters unchanged. A negative rate follows the slope uphill for this example. Tests should check both the update formula and the resulting loss where a decrease is expected.

## 6. Several parameters: partial derivatives

A **partial derivative** measures change with respect to one parameter while holding the others fixed. The **gradient** collects all partial derivatives in parameter order.

Let L(a,b)=(a-2)² + 2(b+1)². Its gradient is [2(a-2), 4(b+1)]. The extra factor two in the second squared term makes that direction steeper.

```python
import numpy as np
point=np.array([0.0,0.0])
gradient=np.array([2*(point[0]-2),4*(point[1]+1)])
updated=point-0.1*gradient
print(updated.tolist())
```

**Output:** `[0.4, -0.4]`.

Both gradient components must be computed from the same original point for the simultaneous update described here. Accidentally changing one parameter and then calculating the other derivative can implement a different method.

The parameter order is as important as feature order in F02. A two-element gradient with swapped components has the correct shape but updates the wrong quantities. Test an asymmetric point rather than a case where both derivatives happen to match.

## 7. The chain rule follows a calculation

The **chain rule** calculates how changes pass through composed operations. If a parameter changes a prediction, and the prediction changes loss, multiply the local sensitivities.

For prediction p=w×x and loss L=(p-y)², changing p changes loss at rate 2(p-y). Changing w changes p at rate x. Therefore dL/dw = 2(p-y)x.

```python
x,y,w=2.0,5.0,1.0
prediction=w*x
gradient=2*(prediction-y)*x
print(prediction,gradient)
```

**Output:** `2.0 -12.0`.

Increasing w slightly moves the prediction toward five, so the negative derivative makes sense. If x were zero, changing w would not affect this example's prediction, and its gradient contribution would be zero.

For a mean loss across examples, average their gradient contributions. Do not sum them while claiming to optimise a mean unless you also account for the changed update scale.

```python
xs,ys,w=[1.0,2.0],[2.0,4.0],0.0
g=sum(2*(w*x-y)*x for x,y in zip(xs,ys))/len(xs)
print(g)
```

**Output:** `-10.0`.

F04 adds a bias parameter and uses these derivatives to fit a numerical predictor. F07 extends the chain-rule idea to layers of a neural network.

## 8. Gradients are about the chosen objective

A loss gradient answers “which small parameter changes reduce this loss on these examples?” It does not directly answer “which action wins the next live match?” That connection depends on the task, data, model, and evaluation.

A poorly chosen target can be optimised very successfully. A training set with missing outcomes mislabelled as losses can teach the wrong relationship. Clean labels before computing derivatives. Exclude unknown results from outcome training targets rather than converting absence into zero.

Record loss on separate data as training proceeds. A falling training curve can coexist with worsening generalisation. F06 will turn this observation into a checkpoint-selection procedure.

Line one clears previously stored gradients. Line two asks the library to calculate derivatives through the loss computation. The real optimizer need not be plain gradient descent. The conceptual connection is that derivatives inform updates. PyTorch syntax, optimizer state, and schedules receive fuller treatment in F08 and F12. We read these four lines now to recognise their roles, not to reproduce the whole trainer.

## Common mistakes

- Adding the gradient instead of subtracting it.
- Forgetting the input factor in the chain rule.
- Checking derivatives only at a point where every gradient is zero.
- Assuming any positive learning rate reduces loss.
- Treating lower training loss as proof of better live play.
