**Time:** about 8 hours · **You will be able to:** assemble and test a command-line report of recorded match outcomes overall, by source date, and by observed opponent card.

## Why this matters for ClashBot

Watching Icebow on the phone emulator gives you individual moments: an X-Bow placement, a defensive response, or a lost tower. The file `scratchpad/gauntlet/L74/loss_review/matches.jsonl` lets you inspect a broader collection of recorded runs. Your project turns that file into a clearly defined report.

The report is a foundation for later analysis, not a claim that the current bot improved. The source contains derived labels, rehearsal records, and missing observations. Your program must preserve those distinctions. It must not make an incomplete record look like a completed loss.

Later course projects will compare RoyaleSim and crforge experiments and assess imitation-learning and reinforcement-learning results. This project supplies an earlier skill: produce a reproducible descriptive summary with a denominator another reader can understand.

## The project contract

A **contract** states the inputs a program accepts and the outputs it promises. Your input is a UTF-8 JSONL file with one match dictionary per nonblank line. The project expects `ts`, when present, to be text and `opp_cards`, when present, to be a list of card-name strings. These are the shapes observed in the supplied source. Malformed JSON and non-dictionary rows fail visibly rather than disappearing from the report.

The outcome field is `derived`. Recognised values are `WIN`, `LOSS`, and `DRAW`. Any other value, including an absent field, is UNKNOWN. Include a row in outcome categories only when `dry_run is False`. A row marked True, or missing that explicit False value, is EXCLUDED. This conservative rule prevents ambiguous inclusion from becoming an unnoticed change in the denominator.

Define win rate as `WIN / (WIN + LOSS)`. This is a **decided-match rate**, a fraction restricted to recognised wins and losses. Draws, unknowns, and excluded rows remain visible as counts. A denominator of zero produces `None` internally and `N/A` in the printed report.

Date groups use the first eight characters of `ts` when they are digits. Call these source-date groups because the timestamp text has no timezone offset. Missing or unsuitable prefixes go into UNKNOWN_DAY. This is a bucket rule, not a full calendar-date validator.

Opponent-card groups use each distinct observed name in `opp_cards` once per match. They overlap: one match can enter several card groups. Missing card observations contribute no named groups. These are observed-card summaries, not complete-deck classifications or causal estimates of a card's strength.

The seven milestones below correspond exactly to the seven interactive exercises. Later exercises supply completed earlier helpers so every exercise can run in a fresh process. Your work is cumulative in design, but the runner does not preserve variables between exercise submissions.

## Milestone 1: Load and validate the records

Build `load_rows(path)`. It opens the selected file for reading, ignores blank lines, decodes JSON, and requires a dictionary. Use B06's file loop and B07's explicit errors.

The `continue` statement skips the rest of the current loop iteration and moves to the next item. It is useful for blank lines:

```python
lines = ["", "match"]
accepted = []
for line in lines:
    if not line.strip():
        continue
    accepted.append(line)
print(accepted)
```

It prints `['match']`. In the actual loader, the accepted item will be a decoded dictionary. Use `enumerate(source, start=1)` to know the line number. If a decoded value is a list, raise `ValueError` with that number and an explanation.

The exercise checks the real file against a fresh independent read. It also creates small temporary inputs to test blank lines and malformed records. A **temporary directory** is a short-lived location managed for a bounded task and removed afterwards. These checks do not alter the source log.

Completion means both valid data and invalid data behave as specified. Merely loading today's first line is insufficient. Your loader must iterate through all nonblank records and return them in source order.

## Milestone 2: Count exclusive categories

Build `summarize(rows)`. Initialise five counters: WIN, LOSS, DRAW, UNKNOWN, and EXCLUDED. Every input row must enter exactly one category. Check exclusion first, then classify the remaining label.

```python
rows = [{"dry_run":False}, {"dry_run":True}, {}]
included = 0
for row in rows:
    if row.get("dry_run") is False:
        included += 1
print(included)
```

It prints `1`. Using `not row.get("dry_run")` would also accept a missing value because `None` is false in a boolean context. That is not this project's contract. Be precise about absence.

After counting, calculate the denominator. A **conditional expression** chooses one value using the form `value_if_true if condition else value_if_false`:

```python
wins = 1
losses = 1
decided = wins + losses
rate = wins / decided if decided else None
print(rate)
```

It prints `0.5`. With both counts zero, the expression would produce None without attempting division. Store that result under `win_rate` alongside the five counts.

The tests use a fixed six-row example containing a win, loss, draw, unknown, dry run, and missing dry-run flag. This small input exposes category mistakes directly. Remember B12: a correct total alone cannot detect swapped win and loss counts.

## Milestone 3: Group by source date

Build `by_day(rows)`, returning a dictionary from date bucket to summary. First collect rows for each bucket, then call the same `summarize` helper on each group. Reusing one definition keeps overall and grouped reports consistent.

The dictionary method `setdefault(name, default)` returns an existing value or inserts and returns the default if the name is absent. It simplifies grouping:

```python
groups = {}
groups.setdefault("20261029", []).append({"derived":"WIN"})
groups.setdefault("20261029", []).append({"derived":"LOSS"})
print(len(groups["20261029"]))
```

It prints `2`. The second call finds the already stored list and appends to it. The default empty list is not substituted for existing contents.

Use `stamp[:8].isdigit()` together with a length check for the stated bucket rule. **isdigit** is a string method that asks whether all characters are digits. Do not describe the resulting date as UTC or convert it into a local timezone without source evidence.

Completion means every input row appears in one date group, including rows that will later be counted as excluded. Filtering inside `summarize` keeps the exclusion count visible per date. If you filtered those rows out before grouping, their date-level coverage would disappear.

## Milestone 4: Group by observed opponent card

Build `by_card(rows)` with the same collect-then-summarize structure. The difference is that one row can enter several groups. Deduplicate names within each row using a set before appending the row to groups.

```python
observed = ["Xbow", "Xbow", "Knight"]
print(sorted(set(observed)))
```

It prints `['Knight', 'Xbow']`. Set iteration order is not the reporting order, so sort group names when displaying them. The grouping dictionary itself need not be sorted for counting to be correct.

If the opponent reveals both Knight and Xbow, that match belongs to both summaries. Therefore adding all card-group totals can exceed the overall match count. That is expected under this definition. The overall categories are mutually exclusive; the card groups are not.

The exercise verifies that repeated sightings do not double-count a match. It also checks a card that appears in both a win and a loss, so the per-card denominator must be calculated from that group rather than copied from the overall report.

## Milestone 5: Render an honest line

Build `render_summary(name, counts)`, returning one string rather than printing immediately. A **renderer** converts structured values into presentation text. Keeping it separate lets tests compare the exact string without capturing process output.

```python
rate = 0.5
print(f"win_rate={100 * rate:.1f}%")
rate = None
print("N/A" if rate is None else f"{100 * rate:.1f}%")
```

It prints `win_rate=50.0%` and `N/A`. The format `:.1f` shows one digit after the decimal point. Multiplying by one hundred converts a fraction into a percentage.

Your line must include all five counts, not just the rate. For the fixed sample, the expected line is `overall: WIN=1 LOSS=1 DRAW=1 UNKNOWN=1 EXCLUDED=2 win_rate=50.0%`. A reader can then see how much evidence was left out of the rate calculation.

Do not add debug messages inside the renderer. The caller controls where the returned text goes. A clean separation between calculation and presentation will also help when later projects produce tables or figures instead of plain text.

## Milestone 6: Assemble the command-line interface

A **command-line interface**, or CLI, lets a caller provide inputs through arguments. Build `main(argv)` using B11's argparse pattern. Require `--input`, load that file, and print the three report sections.

```python
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("--input", required=True)
args = parser.parse_args(["--input", "sample.jsonl"])
print(args.input)
```

It prints `sample.jsonl`. This example only parses text; it does not open that illustrative filename. In the full report, `args.input` flows into `load_rows`.

Print the overall line first. Then print `By source date (timezone unspecified):` and date groups in sorted order. Finally print `By observed opponent card (groups overlap):` and sorted card groups. Return zero to indicate success.

Inside the interactive exercise, the checker calls `main(["--input", path])` itself. Do not add an unconditional call that tries to parse the course runner's arguments. The finished function is the command-line core. In a standalone script, the usual adapter would be:

```python
import sys

# This adapter belongs after the completed helper and main definitions.
if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))
```

The adapter prints nothing itself. With the completed definitions and a valid input argument, `main` prints the report. `sys.argv[1:]` takes the process arguments after the script name. This is an explanation of packaging the finished code, not a requirement to create another repository file for this course task.

Completion means the integrated report works with the synthetic example and its helpers read the current real source. The tests capture output in memory, verify section order, and check the category-total invariant. No network, emulator, or training process is involved.

## In the real project

The required source is `scratchpad/gauntlet/L74/loss_review/matches.jsonl`. Its first record contains this exact fragment:

```text
"ts": "20260925_015246", "ckpt": "gen_s0.pt", "sha8": "", "dry_run": true
```

This data prints nothing. On this line, `ts` supplies the source timestamp, `ckpt` names a recorded checkpoint, `sha8` is an empty recorded fingerprint field, and `dry_run` is true. The report therefore excludes this row from its outcome categories even if some other fields look complete. An empty fingerprint does not identify exact model bytes.

Another exact fragment in that record is:

```text
"has_end": true, "stop_why": "max_seconds", "wall_s": 30.1
```

Again, this is data rather than code output. The line records an ending marker, a time-limit reason, and elapsed seconds. None supplies a WIN label. Your report uses the source's `derived` field when present instead of inventing a result from unrelated metadata.

## Common mistakes

- Counting unknown outcomes as losses or silently dropping them.
- Including a missing dry-run flag as if it explicitly meant False.
- Calling a source-date bucket UTC without an offset.
- Counting the same observed card twice in one match.
- Adding overlapping card-group totals and expecting the overall total.
- Printing zero percent when there are no decided matches.
