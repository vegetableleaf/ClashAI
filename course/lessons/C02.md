## 1. Make a table

**pandas** is a Python package for working with tables. A **DataFrame** is its table object. A **Series** is a single labeled column. The row **index** identifies positions or labels; it is not necessarily a match identifier. Construct a DataFrame from dictionaries: dictionary names become columns. Access one column with square brackets and its name. We use small invented records before reading the full log so every cleaning decision is visible. Calling len on a DataFrame counts rows, whereas len on a selected column counts its values.

```python
import pandas as pd
df = pd.DataFrame([{'derived':'WIN'}, {'derived':'LOSS'}, {}])
print(len(df))
print(df['derived'].notna().tolist())
```

**Output:** `3` and `[True, True, False]`.

**Missing data** is information not present in a record. pandas commonly displays it as NaN or NA. notna identifies present values, but presence alone does not prove a recognized outcome: an unexpected string must also be excluded. The missing record remains a real observation about logging coverage.

## 2. Normalize before counting

**Data cleaning** means transforming records into a consistent representation while preserving their meaning. Normalize outcomes by checking membership in a declared set. Series.isin returns a Boolean mask, just as NumPy comparisons did in C01. Series.where keeps values where the mask is true and replaces the others. Our category unknown includes absent, null, and unrecognized outcomes. That last case deserves investigation in a real analysis, but it must not quietly alter the win rate. Keep a copy when you want to preserve the original table for inspection.

```python
import pandas as pd
s = pd.Series(['WIN', 'DRAW', None, 'unexpected'])
clean = s.where(s.isin(['WIN','LOSS','DRAW']), 'unknown')
print(clean.tolist())
```

**Output:** `['WIN', 'DRAW', 'unknown', 'unknown']`.

WIN and LOSS form the decisive subset. DRAW is separate. For one win, one loss, one draw, and one unknown, decisive rate is 1/2, not 1/4. Different questions can use different draw conventions, but a report must state its denominator before comparisons. Do not change the convention after seeing which version looks better.

## 3. Read JSON lines and dates

**JSON lines** stores one JSON object per nonblank line. B06 introduced json.loads; pandas also offers read_json(path, lines=True). We retain the standard-library reader in exercises so we can select exactly the fields we need. **Date parsing** converts timestamp text into date-time values. pd.to_datetime accepts an explicit format; errors='coerce' converts invalid dates into missing dates rather than guessing. The .dt accessor exposes date operations on a Series. strftime formats dates for display. None of these operations determines the source time zone automatically.

```python
import pandas as pd
s = pd.Series(['20260925_183254', 'bad'])
dates = pd.to_datetime(s, format='%Y%m%d_%H%M%S', errors='coerce')
print(dates.dt.strftime('%Y-%m-%d').fillna('unknown').tolist())
```

**Output:** `['2026-09-25', 'unknown']`.

The percent codes mean four-digit year, month, day, hour, minute, and second. fillna replaces missing values for presentation. Keep unknown dates visible rather than dropping those rows accidentally. Treat the log's ts as recorded time unless you have verified its time-zone convention; do not label it UTC merely because other project logs use UTC.

## 4. Groups and weighted rates

**Grouping** divides rows by a column's value, then computes a summary for each group. groupby creates the grouping operation; sum adds values inside each group. Boolean True acts like one when summed, which makes counting wins convenient. A daily report needs both wins and decisive games. An overall rate is total wins divided by total decisive games. It is usually not the arithmetic mean of daily percentages, because days may contain different numbers of matches. This difference can reverse an apparent conclusion when one period contains many more games.

```python
import pandas as pd
df = pd.DataFrame({'day':['A','A','B'], 'win':[1,0,1], 'known':[1,1,1]})
totals = df.groupby('day')[['win','known']].sum()
print(totals['win'].tolist())
print((totals['win']/totals['known']).tolist())
```

**Output:** `[1, 1]` and `[0.5, 1.0]`.

Group A has one win in two games, while B has one in one. The overall rate is 2/3, not 0.75. In pandas, a list of column names selects several columns. Missing group labels need an explicit policy; our cleaned day label unknown preserves them for an audit.

## 5. Joining and chronological summaries

A **merge** joins tables using shared labels. For example, attach a display description to each experiment arm. A **left join** keeps every row from the left table. validate='many_to_one' requires each label in the right table to appear at most once. Without that check, duplicate descriptions could duplicate match rows and inflate counts. For a **time series**, a sequence ordered by time, sort dates before rolling calculations. A **rolling window** summarizes a fixed number of consecutive observations, not automatically a fixed number of days. We use it for plotting in C03.

```python
import pandas as pd
a = pd.DataFrame({'arm':['base','new'], 'wins':[2,3]})
b = pd.DataFrame({'arm':['base','new'], 'label':['control','candidate']})
out = a.merge(b, on='arm', how='left', validate='many_to_one')
print(out['label'].tolist())
print(pd.Series([1,0,1]).rolling(2).mean().tolist()[1:])
```

**Output:** `['control', 'candidate']` and `[0.5, 0.5]`.

on names the matching column. The first rolling mean is missing because there are not yet two observations. Excluding that first value in this display is deliberate, not a reason to fill it with zero. A two-match window has very little evidence and is only a teaching example.

## Common mistakes

- Dividing wins by every logged row.
- Using a missing result as False and therefore a loss.
- Averaging daily percentages without their denominators.
- Joining duplicate labels and accidentally multiplying rows.
- Assuming timestamp parsing establishes a time zone.
