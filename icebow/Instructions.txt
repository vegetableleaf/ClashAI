===============================================================================
 CLASHAI - THE S1 BOT: FULL SET-UP, TRAINING AND LIVE PLAY (FROM SCRATCH)
===============================================================================

This guide takes a brand-new person on a Windows PC from "I just forked the repo"
to "a model I trained myself is playing Clash Royale on my screen". Everything
runs on YOUR OWN PC. No cloud, no rented GPUs.

You do NOT need to be a programmer. Do the stages IN ORDER and copy-paste the
commands exactly. Anything shown in an indented block like this:

    some command here

is a command you type into a terminal and press Enter.

HOW THE BOT WORKS (the short version)
  1. Download recordings of real matches played by strong players (pro replays).
  2. Re-play every one of those matches inside a copy of the real game engine
     running on your PC. This turns each replay into "what the board looked like"
     + "what the pro did" at every moment.
  3. Train a neural network (called "S1") to copy the pros' decisions:
     which card to play, where to put it, or whether to wait.
  4. Teach a second network (an object detector) to recognise the units on your
     screen, so the bot can see the board the same way the training data did.
  5. Point the bot at Clash Royale in Google Play Games and let S1 play.


===============================================================================
 READ THIS FIRST - WHAT THIS PROJECT CANNOT GIVE YOU
===============================================================================

  * THE GAME ENGINE'S FILES. The engine sandbox code is public, but the game files
    it runs (APKs, libg.so, assets) are NOT redistributable. You must obtain the
    EXACT game build 15.535.29 yourself (for example from an Android emulator you
    own). Any other game version will not run - the sandbox checks file hashes.
  * TRAINED MODELS. No trained S1 model and no trained detector are included. You
    train both yourself in this guide.
  * PERMISSION TO AUTOMATE THE GAME. Automating Clash Royale breaks Supercell's
    Terms of Service. Use a THROWAWAY account. This is a learning project.

Expect the whole guide to take a few days of on-and-off work. Most of the time is
the computer running on its own (driving replays, training) and hand-labelling
pictures for the detector.


===============================================================================
 WHAT YOU NEED (checklist)
===============================================================================

[ ] Windows 10 or 11, 64-bit, with hardware VIRTUALIZATION turned on
    (Task Manager -> Performance -> CPU -> "Virtualization: Enabled").
[ ] An NVIDIA GPU. This guide was tested on an 8 GB laptop GPU (RTX 5050).
[ ] RAM: 32 GB recommended. The engine's virtual phone alone uses ~4.2 GB.
[ ] Free disk: ~40 GB (Android tools ~15-20 GB, engine files ~1 GB,
    replay downloads ~0.8 GB, your replay corpus and datasets ~1 GB, plus room).
[ ] Python 3.13 (tested with 3.13.14) from python.org - TICK "Add Python to PATH".
[ ] Git for Windows (git-scm.com). It also installs "Git Bash" and curl, which
    Stage 4 uses.
[ ] JDK 17 and the Android SDK command-line tools (needed by the engine sandbox;
    Stage 3 tells you where).
[ ] Google Play Games for PC with Clash Royale installed, on a throwaway account.
[ ] The deck this bot is built for ("Icebow X-Bow Control"):
    Tornado, Evolved Tesla, Ice Wizard, X-Bow, Rocket, Evolved Knight, The Log,
    Skeletons.


===============================================================================
 THE RULES FOR EVERY COMMAND
===============================================================================

1. Every stage starts with a line saying WHICH FOLDER to be in:

     FOLDER: repo root    = the top folder you cloned (it contains "pipeline",
                            "icebow", "research", ...)
     FOLDER: icebow       = the "icebow" folder inside it
     FOLDER: sandbox      = research\ext\cr-native-sandbox inside it

2. Use PowerShell unless a stage says "Git Bash".
   (Start menu -> type "PowerShell" -> Enter.)

3. Never run the engine, training and the live bot at the same time. Each one
   needs a lot of memory; together they crash.


===============================================================================
 STAGE 0 - COMPUTER SET-UP (one time)
===============================================================================

1. Install Python 3.13 (tick "Add Python to PATH").
2. Install Git for Windows.
3. Install Google Play Games for PC, then install Clash Royale and log in with your
   throwaway account.
4. Check Python works. In PowerShell:

       python --version

   You should see "Python 3.13.x". If it says "not recognized", re-install Python
   and tick "Add Python to PATH".


===============================================================================
 STAGE 1 - GET THE CODE
===============================================================================

1. On GitHub, click "Fork" to make your own copy of the project.
2. On your fork's page, click the green "Code" button and copy the HTTPS URL.
3. In PowerShell:

       cd $HOME\Documents
       git clone <PASTE-YOUR-FORK-URL-HERE>
       cd .\<the-cloned-folder-name>

   You are now in the REPO ROOT. Remember where it is.


===============================================================================
 STAGE 2 - INSTALL THE BOT'S PYTHON ENVIRONMENT
===============================================================================
FOLDER: icebow

1. Create the bot's private Python environment and install its packages:

       cd .\icebow
       python -m venv .venv
       .\.venv\Scripts\python.exe -m pip install --upgrade pip
       .\.venv\Scripts\python.exe -m pip install -r requirements.txt
       .\.venv\Scripts\python.exe -m pip install ultralytics polars

   (ultralytics = the object detector; polars = reads the downloaded replays.
   They are not in requirements.txt yet, so install them by hand.)

2. Install PyTorch with CUDA for your NVIDIA card. Newer cards (RTX 40/50 series):

       .\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cu128

   Older cards: pick the matching command at https://pytorch.org/get-started/locally/

3. Check the install. This prints your deck and the card list:

       .\.venv\Scripts\python.exe run.py cards

4. Check the training code works. Go back to the repo root and run its tests:

       cd ..
       icebow\.venv\Scripts\python.exe -m unittest pipeline.tests.test_obs_contract

   It should end with "OK".


===============================================================================
 STAGE 3 - INSTALL THE GAME ENGINE SANDBOX (one time)
===============================================================================
FOLDER: repo root, then sandbox

The engine sandbox runs the real game's logic headless inside an Android emulator,
so replays can be re-played exactly. Its own README is the full reference; these
are the steps in order.

1. Clone it into EXACTLY this folder (the replay tools look for it there):

       git clone https://github.com/IMAX9D/cr-native-sandbox.git research\ext\cr-native-sandbox
       cd research\ext\cr-native-sandbox

2. Create its own Python environment and install it:

       python -m venv .venv
       .\.venv\Scripts\python.exe -m pip install -e .

3. Install JDK 17 and the Android SDK command-line tools as the sandbox README
   describes (section 1.1).

4. Put the game files for build 15.535.29 (that you obtained yourself) into the
   sandbox's "runtime" folder, as the README describes (sections 1.3-1.4):
   runtime\apks, runtime\x86_64-libs, runtime\extracted-assets.

5. Create your settings file and fill in YOUR paths (SDK, JDK, APKs, ...):

       Copy-Item runtime.env.example.ps1 runtime.env.ps1
       notepad runtime.env.ps1

   IMPORTANT: every NEW PowerShell window that uses the engine must load it first:

       . .\runtime.env.ps1

6. Let the sandbox install the Android pieces it needs, create its virtual phone,
   and check everything:

       . .\runtime.env.ps1
       .\scripts\bootstrap.ps1
       .\scripts\doctor.ps1
       .\scripts\smoke.ps1

   The smoke test must print "PASS". If it does not, fix that before going on
   (see TROUBLESHOOTING). Then go back to the repo root:

       cd ..\..\..


===============================================================================
 STAGE 4 - DOWNLOAD PRO REPLAYS (one time)
===============================================================================
FOLDER: repo root  (step 2 in Git Bash)

The replays come from a public dataset on HuggingFace (VanguardX101/IL_Replay,
about 252,000 matches, 825 MB). Check the dataset page for its licence before you
use it. About 766 of those matches use the Icebow deck.

1. Make the download folder and fix the download script's path.

       New-Item -ItemType Directory -Force scratchpad\gauntlet\L67\hf\replays
       notepad scratchpad\gauntlet\L67\_hf_dl.sh

   Line 3 says   cd /c/Users/benpe/ClashBot/scratchpad/gauntlet/L67/hf
   Change the start to YOUR repo root, written the Git Bash way. Example: if your
   repo root is C:\Users\alex\Documents\ClashBot the line becomes
       cd /c/Users/alex/Documents/ClashBot/scratchpad/gauntlet/L67/hf
   Save and close Notepad.

2. Open Git Bash (Start menu -> "Git Bash"), go to your repo root, and download.
   It is safe to re-run if it stops; finished files are skipped:

       cd /c/Users/alex/Documents/ClashBot
       bash scratchpad/gauntlet/L67/_hf_dl.sh

   It ends with "DONE ok 52 bad 0". Close Git Bash and go back to PowerShell.

3. The converter compares against the project owner's own replay files, which you
   do not have. Create two EMPTY stand-in files so it runs (PowerShell, repo root):

       New-Item -ItemType Directory -Force icebow\data\royaleapi\crawl2
       New-Item -ItemType File -Force icebow\data\royaleapi\crawl2\battles.csv
       New-Item -ItemType File -Force icebow\data\royaleapi\crawl2\plays_ext.csv

4. Pick out the Icebow matches and convert them to the format the engine reads:

       icebow\.venv\Scripts\python.exe scratchpad\gauntlet\L67\hf_to_crawl.py --hf scratchpad\gauntlet\L67\hf\replays --out scratchpad\gauntlet\ext\crawl_hf_icebow

   You get scratchpad\gauntlet\ext\crawl_hf_icebow\ with battles.csv,
   plays_ext.csv and tags.json (the list of matches to re-play).


===============================================================================
 STAGE 5 - START THE ENGINE
===============================================================================
FOLDER: sandbox  (a NEW PowerShell window, left open)

1. Start the virtual phone and the engine service (one "slot"):

       cd <your repo root>\research\ext\cr-native-sandbox
       . .\runtime.env.ps1
       .\.venv\Scripts\python.exe -m native_core.worker start --workers 1 --base-port 37031 --transport adb --avd-name royale_worker_api31

   It takes several minutes. About 1 start in 10 fails with a crash inside the
   engine - that is a known engine bug, not your mistake. Just run the same start
   command again.

2. Check it answers:

       .\.venv\Scripts\python.exe -m native_core.client --port 37031 ping

Leave this window open. The engine stays running in the background until you stop
it in Stage 7.


===============================================================================
 STAGE 6 - RE-PLAY THE PRO MATCHES IN THE ENGINE (builds your corpus)
===============================================================================
FOLDER: repo root  (a different PowerShell window)

This re-plays every downloaded match inside the engine and saves one file per
match with the board recorded along the way.

    research\ext\cr-native-sandbox\.venv\Scripts\python.exe research\sandbox_tools\replay_batch.py --crawl scratchpad\gauntlet\ext\crawl_hf_icebow --tags scratchpad\gauntlet\ext\crawl_hf_icebow\tags.json --out scratchpad\gauntlet\ext\corpus_v6\icebow --record-every 20 --record-plays --port 37031 --determinism-every 0

  * DO NOT leave out --record-every 20 or --record-plays. Without them the files
    look fine but the dataset in Stage 8 silently gets no "wait" examples.
  * It takes about 25 seconds per match: roughly 5-6 hours for ~766 matches.
    If it stops, run the SAME command again - finished matches are skipped.
  * About 1 in 5 matches fails with "card has no native evolution form". That is a
    known gap in the engine. Expect roughly 600 good matches out of 766.

Check the first finished file really recorded the board: open any
scratchpad\gauntlet\ext\corpus_v6\icebow\replay_*.json in Notepad and search for
"frames". It must be there and not empty.


===============================================================================
 STAGE 7 - STOP THE ENGINE
===============================================================================
FOLDER: sandbox  (the Stage 5 window)

When Stage 6 is finished, stop the engine AND its virtual phone (without
--stop-vm the phone keeps ~4 GB of memory):

    .\.venv\Scripts\python.exe -m native_core.worker stop --workers 1 --base-port 37031 --stop-vm


===============================================================================
 STAGE 8 - BUILD THE TRAINING DATASET
===============================================================================
FOLDER: repo root

Turn the corpus into rows the network learns from. Always give BOTH --corpus and
--out (the defaults point at the project owner's files):

    New-Item -ItemType Directory -Force icebow\data\pipeline
    icebow\.venv\Scripts\python.exe -m pipeline.dataset icebow --corpus scratchpad\gauntlet\ext\corpus_v6\icebow --out icebow\data\pipeline\s1_dataset_v6.npz

It takes a minute or two and prints how many rows it built. 15% of the matches
are kept aside automatically to test the model on (the "val" split).

OPTIONAL - a noisy copy that matches what the live detector sees. On the screen
the detector misses some units and misplaces others; a model that also trained on
noisy boards may handle that better. This is still being measured, so start with
the normal dataset. To build it:

    icebow\.venv\Scripts\python.exe scratchpad\gauntlet\L67\build_degraded.py icebow --corpus scratchpad\gauntlet\ext\corpus_v6\icebow --out scratchpad\gauntlet\L67\s1_dataset_v6_degraded_s0.npz --seed 0
    icebow\.venv\Scripts\python.exe scratchpad\gauntlet\L67\merge_aug.py --clean icebow\data\pipeline\s1_dataset_v6.npz --degraded scratchpad\gauntlet\L67\s1_dataset_v6_degraded_s0.npz --out icebow\data\pipeline\s1_dataset_v6aug.npz


===============================================================================
 STAGE 9 - TRAIN THE S1 MODEL
===============================================================================
FOLDER: repo root

    icebow\.venv\Scripts\python.exe -m pipeline.train_s1 icebow --seed 0 --epochs 20 --data icebow\data\pipeline\s1_dataset_v6.npz --tag v6lat --grid lattice --out-dir scratchpad\s1_runs

  * It uses your GPU automatically. On an 8 GB laptop GPU, a dataset of ~340,000
    rows took about 5 minutes per epoch (20 epochs = under 2 hours). A dataset
    built from ~600 matches is smaller, so it is quicker.
  * It saves the best epoch to:  icebow\data\pipeline\s1_icebow_v6lat_s0.pt
  * Close the game and the live bot while it trains.
  * For the optional noisy dataset, use  --data icebow\data\pipeline\s1_dataset_v6aug.npz --tag v6aug
    (about 3 times slower per epoch).


===============================================================================
 STAGE 10 - CHECK THE MODEL
===============================================================================
FOLDER: repo root

Score the model on the matches it never trained on:

    icebow\.venv\Scripts\python.exe -m pipeline.eval_s1 icebow icebow\data\pipeline\s1_icebow_v6lat_s0.pt --data icebow\data\pipeline\s1_dataset_v6.npz

It prints one line of numbers. The ones to look at:
  * card_top1       - how often it picks the same card as the pro
  * cell_half_top1  - how often it picks the exact same spot
  * gate_bal_acc    - how well it decides "play now" vs "wait"
For reference, the project owner's model (trained on ~2,200 matches) scored about
65% card and 21% exact spot on its own test set. With fewer matches expect lower.


===============================================================================
 STAGE 11 - POINT THE BOT AT YOUR GAME + RECORD A FEW MATCHES
===============================================================================
FOLDER: icebow

The bot sees the game by screenshotting your game window and taps at positions on
it, so it must know where the window is.

1. Open Clash Royale in Google Play Games on the HOME screen. Make the window a
   normal upright (portrait) shape, keep it fully visible, and DON'T move or
   resize it afterwards.

2. Open config\config.yaml in Notepad. Near the top find:

       window:
         title_contains: "Clash Royale"
         region: [739, 38, 669, 1182]

   Change the region line to auto-detect the window (the word null, NO brackets):

       region: null

3. Check the bot can see the game (with the game on HOME):

       .\.venv\Scripts\python.exe run.py diag

   It prints a "match score" for each menu screen and saves a picture of what it
   captured in the data folder. If there is no frame or the picture is wrong, go
   back to steps 1-2.

4. Record yourself playing 5-10 matches with the Icebow deck. These recordings are
   used for the card pictures (Stage 12), the detector (Stage 13) and a small
   required file (Stage 14):

       .\.venv\Scripts\python.exe run.py record

   Play normally with your mouse. When done, click the PowerShell window and press
   Ctrl+C. Each recording is saved in data\sessions\<date-time>\.

5. Re-cut the in-match screen picture from YOUR recording, so the bot recognises
   "in a match" on your screen size:

       .\.venv\Scripts\python.exe run.py calibrate


===============================================================================
 STAGE 12 - CARD PICTURES + CHECK RECOGNITION
===============================================================================
FOLDER: icebow

The bot recognises the 4 cards in your hand by matching small pictures of your
deck's cards. The project already includes pictures in templates\cards. Check
whether they work on your screen first:

    .\.venv\Scripts\python.exe run.py verify --hand

It writes pictures (in the session's "annotated_hand" folder) labelled with the
card it thinks is in each slot. If they are right, skip to step 3.

1. If cards are wrong or missing, cut new pictures from your recording:

       .\.venv\Scripts\python.exe run.py hand-templates

   This drops "_cand_0.png", "_cand_1.png", ... into templates\cards.

2. Rename each crop to the card it shows, using these exact names:

       tornado.png   tesla.png   tesla_evo.png   ice_wizard.png   x_bow.png
       rocket.png    knight.png  knight_evo.png  the_log.png      skeletons.png

   Extra good crops of the same card: <name>_2.png, <name>_3.png. Delete junk.
   Run  run.py verify --hand  again until every slot is right.

3. Check the towers are read correctly (green = alive, red = destroyed):

       .\.venv\Scripts\python.exe run.py verify --towers


===============================================================================
 STAGE 13 - TRAIN THE DETECTOR (so the bot can see units on the board)
===============================================================================
FOLDER: icebow

S1 decides from a list of units on the board, and on the live screen that list
comes from an object detector (YOLO). You need to train one. This is the biggest
manual job in the guide: you draw boxes around units on screenshots.

1. Pull frames to label out of your recordings, then run autolabel. Autolabel
   pre-boxes your OWN troops for you AND writes the Label Studio setup file that
   step 2 needs (data\detect\label_studio_config.xml), so do not skip it:

       .\.venv\Scripts\python.exe run.py detect-frames --count 200
       .\.venv\Scripts\python.exe run.py autolabel --all --preview

2. Install and start Label Studio (a free labelling app) in its own PowerShell
   window. Replace <your repo root> with your real path:

       python -m pip install label-studio
       $env:LABEL_STUDIO_LOCAL_FILES_SERVING_ENABLED = "true"
       $env:LABEL_STUDIO_LOCAL_FILES_DOCUMENT_ROOT  = "<your repo root>\icebow\data\detect\images"
       label-studio start

   It opens in your browser. Create an account (local only), then a project.
   Paste the contents of icebow\data\detect\label_studio_config.xml as the
   labelling setup. Add "Local files" storage pointing at the folder with your
   frames (inside data\detect\images).

3. Label EVERY unit on EVERY frame, on both sides (troops, buildings, spells).
   A unit you leave unboxed teaches the detector "this is background".
   The class names come from config\detect_classes.yaml.

4. Export from Label Studio as JSON (not the YOLO export - it breaks on Windows),
   then import it:

       .\.venv\Scripts\python.exe run.py detect-import --export <your-export.json>

   LATER ROUNDS: detect-import REBUILDS the whole train/val set from the files you
   give it. Back up data\detect first, and pass ALL your exports together
   (comma-separated), not just the newest one.

5. Train the detector. ALWAYS pass --model (the default is a much bigger model):

       .\.venv\Scripts\python.exe tools\detect\train.py --model yolo11s.pt

   It saves to runs\detect\<run name>\weights\best.pt. If it stops, continue with
       .\.venv\Scripts\python.exe tools\detect\train.py --resume <run name>

6. Tell the bot to use it: in config\config.yaml find the "detect:" section and set

       weights: runs/detect/<run name>/weights/best.pt

7. Check it on random frames:

       .\.venv\Scripts\python.exe run.py detect-preview

   LATER ROUNDS: once you have a detector, `run.py pre-annotate` puts its boxes into
   Label Studio for you, so labelling becomes fixing boxes instead of drawing them.


===============================================================================
 STAGE 14 - THE REQUIRED PLACEHOLDER FILE (temporary)
===============================================================================
FOLDER: icebow

The live-play command still refuses to start unless an OLD-style model file
(data\policy.pt) exists. When you play with S1 (Stage 15), S1 makes every play and
every wait, so this file's quality does not matter - it just has to exist and match
your deck. Make it from your Stage 11 recordings:

    .\.venv\Scripts\python.exe run.py label --all
    .\.venv\Scripts\python.exe run.py train-bc

When it finishes, data\policy.pt exists. (This stage will disappear once the live
code no longer needs the old file.)


===============================================================================
 STAGE 15 - LET YOUR S1 MODEL PLAY
===============================================================================
FOLDER: icebow

1. Make sure the engine is stopped (Stage 7) and no training is running.
2. Open Clash Royale on the HOME screen (same window position as Stage 11).
3. Start the bot with your model:

       .\.venv\Scripts\python.exe run.py play --student data\pipeline\s1_icebow_v6lat_s0.pt --student-gate-tau 0.27

   * --student-gate-tau is how eager it is to play: lower = plays more often.
     0.27 is what the project owner uses. A model trained on the noisy dataset
     (v6aug) needs a much lower value (around 0.08-0.16).
   * The bot queues matches, plays cards, and moves from match to match by itself.
   * It prints every play and wait. Press Ctrl+C to stop.
   * To keep a copy of what it printed, add  | Tee-Object -FilePath play_log.txt
     to the end of the command.

 STAGE 16 - OPTIONAL EXTRAS
===============================================================================

* MEASURE YOUR MODEL IN THE ENGINE (advanced). Instead of watching live matches,
  play your model against recorded opponents it never trained on, inside the
  engine, and get a win rate with a confidence interval. Commands:
  pipeline.e1_pool, pipeline.e1_eval, pipeline.e1_score. Step-by-step runbook:

* WATCH REMOTELY (Discord): put your channel's webhook URL in the "monitor:"

      .\.venv\Scripts\python.exe run.py cards-import

* SAVE YOUR WORK: code changes can be pushed with git. Everything in the "data"
  folders (recordings, datasets, models) stays on your PC on purpose.


===============================================================================
 TROUBLESHOOTING
===============================================================================

The engine smoke test (Stage 3) does not print PASS:
  Run  .\scripts\doctor.ps1  in the sandbox folder (after  . .\runtime.env.ps1 )
  and fix what it lists. The most common causes are a wrong path in
  runtime.env.ps1, virtualization turned off, or game files that are not exactly
  build 15.535.29.

The engine start (Stage 5) fails:
  About 1 start in 10 crashes inside the engine. Run the start command again.
  If it keeps failing, run the stop command with --stop-vm, then start again.

Replays in Stage 6 never advance / time out:
  Make sure only ONE program talks to the engine at a time (close any second
  replay_batch window). If every replay stalls at the very start, the public
  sandbox may be missing a fix the project owner uses locally - check the
  project's issue tracker.

hf_to_crawl.py says a file is missing (Stage 4):
  You skipped Stage 4 step 3 (the two empty stand-in files).

The dataset in Stage 8 has 0 "wait" rows:
  Stage 6 ran without --record-every 20. Delete the corpus folder and re-run
  Stage 6 with the exact command shown.

"CUDA not available" / training is very slow:
  PyTorch is the CPU build or your NVIDIA driver is old. Redo Stage 2 step 2 and
  update the driver.

Training or the bot crashes with "CUDA error" or "out of memory":
  Something else is using the GPU or memory (the detector, another training run,
  the engine). Run one thing at a time.

"no policy at data\policy.pt" when starting play:
  Do Stage 14.

diag says "no frame" / the captured picture is wrong:
  The game window moved, is minimized, or is covered. Redo Stage 11 steps 1-3.

The bot doesn't press Battle / gets stuck on a menu:
  Run  run.py diag  on that screen. If its score is below the threshold, your
  screen looks different from the saved pictures in templates\ - take your own
  screenshot of that screen, crop it like the existing picture, and replace it.

Cards are recognized wrong:
  Redo Stage 12 with clearer crops, named exactly after the cards.

The bot plays but ignores enemy units:
  The detector is missing or not loading. Check the "weights:" path from Stage 13
  step 6, and run  run.py models  to see which models it found.
